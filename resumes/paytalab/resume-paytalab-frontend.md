## 소개

사용자의 예약·결제와 병원·운영팀의 관리 업무를 함께 개발해 온 프론트엔드 엔지니어입니다. React·TypeScript·Next.js로 의료복지 서비스와 채용 SaaS를 개발했습니다. 직접 써 보며 발견한 불편을 PO에게 제안하고, 요구사항에서 빠진 동작을 디자이너·백엔드 개발자와 확인해 제품에 반영합니다.

- **모바일 사용성:** 리뷰 작성의 키패드 가림·반복 선택 문제를 발견해 PO에게 공유하고, 담당자가 정한 복수 선택 UI를 구현했습니다.
- **운영 안정성:** Sentry를 도입하고 라이브러리 내부까지 원인을 추적해, 75건·57명 이상에게 발생한 크래시를 수정했습니다. 배포 뒤 18일간 같은 오류는 0건이었습니다.
- **변경에 대응하는 구조:** 관리자 검색 화면 27개를 조합 가능한 필터로 전환하고, 폼 필드·값을 TypeScript로 검사하며 테스트·skills·lint rule로 구현 기준을 관리합니다.

#### 조회 구조·성능·운영 오류 대응 | 2025.05 – 현재

- 서버 조회 결과를 props로 읽어 캐시 무효화가 화면에 반영되지 않던 구조를 TanStack Query prefetch·hydration으로 전환했습니다. 서버 초기 조회와 클라이언트 갱신을 같은 캐시에서 처리합니다.
- 관리자 검색 오류는 `dev`에서 나타나지 않아 `build` 후 `start`로 재현했습니다. 라우터 캐시 문제까지 추적하고, 서버가 검색 조건을 읽지 않는 같은 경로 변경을 History API로 처리했습니다.
- 글로벌 서비스의 클라이언트에서 목 백엔드 의존을 분리해 앱 번들을 **2,564KB→1,880KB**로 줄였습니다. 복지몰 검색의 canonical·제목·사이트맵도 구성했습니다.
- Sentry를 도입해 오류 수집·민감 정보 제거 기준을 정하고 Bottom Sheet 크래시를 수정했습니다. 회원 조회 실패는 401일 때만 로그아웃하도록 바꿨습니다.

티켓·plan 검토 → 테스트 작성 → 에이전트 구현·에이전트 코드 리뷰 → 변경분 테스트·lint·typecheck → 직접 diff 리뷰·화면을 띄워 동작 확인 → 전체 CI(테스트·knip·lint) → QA 더블 체크 요청
