## 소개

사용자가 예약하고 병원과 운영팀이 처리하는 과정을 함께 개발해 온 프론트엔드 엔지니어입니다. React·TypeScript로 복지몰과 병원 관리자·백오피스의 예약·리뷰·쿠폰·결제·정산을 다뤘습니다. 직접 써 보며 발견한 불편과 요구사항에서 빠진 동작을 담당자와 논의하고 구현에 반영합니다.

기능을 늘리면서 상태 관리·폼·공통 UI·데이터 조회 기준을 정하고 저장소 전반을 리팩터링했습니다. AI 개발 workflow로 구현하며 제출된 코드와 테스트를 읽고 화면을 띄워 동작을 확인합니다. 출시 뒤에도 Sentry 오류와 VOC를 추적하고, 반복되는 판단은 skills와 lint rule에 남깁니다.

#### 데이터 조회·네트워크 요청·SEO 개선 | 2025.05 – 현재

입사 당시에는 서버 컴포넌트의 `ensureQuery` 결과를 render props로 전달했습니다. 화면이 Query 캐시를 구독하지 않아 무효화해도 갱신되지 않았고, 조회 조건만 바꿀 때도 서버 렌더링 결과를 다시 받아야 했습니다. 2025년 5월부터 화면별로 prefetch·hydration으로 옮겨 서버 초기 조회와 클라이언트 갱신을 같은 캐시에서 처리하도록 했습니다.

- 로그인 상태의 링크 prefetch가 proxy의 권한 검증과 `member/info` 요청까지 유발하는 것을 Sentry에서 확인했습니다. 불필요한 prefetch를 끄고 해당 요청이 사라지는 것을 확인했습니다.
- 글로벌 서비스의 클라이언트 번들에 목 백엔드 코드가 포함되는 의존을 분리해 앱 번들을 **2,564KB에서 1,880KB**로 줄였습니다.
- 관리자 검색 오류는 localhost의 `dev`에서 나타나지 않아 `build` 후 `start`로 재현했습니다. 목록 7개 중 6개에서 확인하고 라우터 캐시 이슈까지 추적했습니다. 서버가 검색 조건을 읽지 않는 화면의 같은 경로 변경은 History API로 처리해 불필요한 RSC 요청을 없앴습니다.
- 지역·진료과 검색의 canonical·제목·사이트맵을 구성하고, 제휴 병원이 3곳 이상인 조합만 사이트맵에 넣었습니다. 병원·시술 상세의 메타데이터와 검진 검사 항목의 JSON-LD도 정리했습니다.

#### 테스트 도입 | 2026.07 – 현재

7월부터 테스트 코드를 도입하고 기능 개발·운영 오류 대응을 거치며 기준을 보완했습니다. 함수·스키마는 Vitest, UI·폼은 React Testing Library, 브라우저 흐름은 Playwright로 확인합니다.
