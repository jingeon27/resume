#### 복지몰 검색 노출 개선 | 2026.06 – 현재

검색엔진이 받는 HTML로 복지몰을 다시 읽어 보며 고쳤습니다. 브라우저 화면에서는 드러나지 않는 문제들이었습니다.

- 루트 layout의 canonical이 하위 페이지로 상속돼, 사이트맵에 올린 검색 결과 수백 개가 홈을 원본으로 선언하고 있었습니다. 페이지마다 자기 canonical을 두고, 검색 결과는 시술과 탭만 남겨 canonical을 만들었습니다.
- 상세 페이지에서 다른 상세로 나가는 링크가 0개라, 상세 5,011개가 사이트맵으로만 닿았습니다. div와 router.push로 이동하던 카드를 링크로 바꾸고, 버튼이 든 카드는 이름만 링크로 만들어 이동이 두 번 일어나지 않게 했습니다.
- 병원과 시술 상세의 제목과 설명을 같은 분야 서비스의 검색 결과와 비교해 다시 쓰고, MedicalClinic과 Product 구조화 데이터를 붙였습니다. 10점 만점 별점을 5점 척도로 선언해 후기가 있는 병원 전부가 무효이던 마크업은 검토에서 찾아 고쳤습니다.
- 진료과 검색은 병원 목록을 클라이언트에서만 받아 서버 HTML에 목록이 없었습니다. 서버에서 받아 첫 응답에 싣고, 봇 UA로 서버 HTML의 목록과 canonical을 확인하는 E2E를 붙였습니다. AI 검색 봇에게는 htmlLimitedBots로 메타데이터를 head에 넣어 보냅니다.
- 지역과 진료과 조합 주소를 색인하고, 사이트맵에는 제휴 병원이 3곳 이상인 조합만 담았습니다. 사이트맵의 공개 조회는 인증 쿠키와 분리해 하루 단위로 재검증합니다.

#### 테스트 도입과 AI 개발 workflow | 2026.04 – 현재

4월부터 에이전트로 구현하고, 7월부터 Vitest, React Testing Library, MSW, Playwright로 테스트를 도입했습니다. 구현이 의도와 어긋나면 파일 배치, 상태 소유권, 공통 코드 사용 기준을 skills에 남기고, 의존 방향과 Public API, queryKey는 lint rule로 검사합니다. 지금 기능 개발과 리팩터링에서는 에이전트가 제출한 제품 코드와 테스트를 직접 읽고, 부족하면 반려한 뒤 수정본을 다시 확인합니다.

티켓, plan 검토 → 테스트 작성 → 에이전트 구현과 에이전트 코드 리뷰 → 변경분 테스트, lint, typecheck → 직접 diff 리뷰, 화면을 띄워 동작 확인 → 전체 CI(테스트, knip, lint) → QA 더블 체크 요청

- 새 기능의 기대 동작은 BDD 형식의 `*.spec`에, 운영과 QA에서 나온 오류는 `*.test`에 씁니다. 새 패턴의 테스트는 제품 코드를 일부러 깨뜨려 실제로 실패하는지 확인합니다.
- 기대 payload는 제품의 변환 함수를 가져다 쓰지 않고 직접 적습니다. React Hook Form과 Ant Design 폼을 실제로 제출해 검증하고, 만들기 어려운 조건은 MSW로 재현합니다.
- 성공만 돌려주는 목이 서버 제약을 가려서, 실제 인증으로 dev API 서버에 붙는 계약 테스트와 병원 관리자, 백오피스의 Playwright E2E를 추가했습니다.
- 자체 lint rule은 RuleTester와 `__fixture__`, mock으로 검증하고, 위반을 정리한 규칙만 error로 올립니다. 쓰지 않는 코드는 Knip으로 찾습니다.
