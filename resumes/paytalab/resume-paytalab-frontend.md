## 소개

사용자가 예약하고 결제하는 화면부터 병원 관리자, 백오피스까지 함께 개발해 온 프론트엔드 엔지니어입니다. 직접 써 보며 발견한 불편은 담당자에게 제안하고, 빠진 동작과 예외는 디자이너, 백엔드 개발자와 맞춰 제품에 반영합니다.

제품을 늘리면서 상태 관리와 폼, 공통 UI, 데이터 조회 기준을 정하고 기존 코드를 리팩터링했습니다. AI로 빠르게 구현하되 코드와 테스트를 직접 읽고, 실제 화면의 동작까지 확인합니다. 출시 뒤에는 Sentry 오류와 VOC를 따라 문제를 해결합니다.

## 지원동기

패스오더의 사용자 웹과 앱 연계 기능, 백오피스를 함께 개발하는 역할에 관심이 갔습니다. 예약과 결제, 병원과 운영팀의 업무를 연결해 온 경험을 살릴 수 있다고 생각합니다. 사용자에게 필요한 정보와 동작을 빠짐없이 제공하고, 운영팀이 처리하기 편한 관리 화면도 함께 만들고 싶습니다.

- 병원 관리자의 프로그램 등록과 검수 요청, 백오피스의 반려와 승인 화면을 개발했습니다. 기존 프로그램의 반려가 새 폼 검증에 막힌 운영 오류는 승인에만 전체 검증을 남겨 당일 수정했습니다. 2026년 9월 두 앱의 등록부터 검수, 반려, 승인까지 E2E를 추가했습니다.
- 수기 정산을 내부 예약 데이터와 연결하는 프로젝트에서 초기 구현을 인수했습니다. 1,170줄이던 페이지를 조회, 표, 편집, 정산 처리로 나누고 파일과 타입을 정리했습니다. ref로 열던 모달도 대상 데이터와 열림 상태를 props로 받게 바꿨습니다.
- 기업과 대학의 컨택상태, 활동 이력, 다음 일정과 담당자별 목록, 포인트 일괄 지급, 임시 휴무일과 진료일 관리 기능을 개발했습니다.

#### 데이터 조회와 검색 노출 개선 | 2025.05 – 현재

서버의 `ensureQuery` 결과를 render props로 받던 화면은 Query 캐시를 구독하지 않아 무효화해도 갱신되지 않았습니다. 예약 화면부터 prefetch와 hydration으로 바꾸고, 서버가 준비한 초기 데이터를 클라이언트가 같은 캐시로 읽고 갱신하게 했습니다.

- 서버가 검색 조건을 읽지 않는 관리자 화면은 같은 경로의 URL 조건 변경에 History API를 사용했습니다. 개발 서버에서는 재현되지 않던 검색 오류를 build 후 start로 목록 7개 중 6개에서 확인하고, 업스트림의 라우터 캐시 문제까지 추적했습니다.
- 검색엔진이 읽는 HTML을 확인해 페이지별 canonical, 상세 페이지 사이의 링크, 병원과 시술의 JSON-LD를 고쳤습니다. 검색 목록은 서버 HTML에 포함하고, 공개 조회는 인증 쿠키와 분리해 사이트맵을 하루 단위로 재검증합니다.
- 관리자 검색 필터는 화면별 조합으로 바꾸고 URL, 폼, API 필드를 같은 Zod 스키마로 맞춰 27개 화면을 옮겼습니다. Ant Design Form의 중첩 필드 경로와 값은 `createTypedForm<T>`로 타입 검사를 받게 했습니다.
