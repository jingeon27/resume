## 소개

사용자가 예약하는 화면과 병원, 운영팀이 이를 처리하는 관리자 서비스를 함께 개발해 온 프론트엔드 엔지니어입니다. SEO와 이벤트 랜딩, 결제, WebView 연동을 맡았습니다. 모바일 리뷰를 직접 쓰며 발견한 불편을 공유하고, 기획에 빠진 예외는 담당자와 논의해 반영했습니다.

기능을 늘리는 동안 상태 관리와 공통 코드도 정리했습니다. 화면별 예외가 쌓인 검색 필터를 다시 설계하고, 결제 실패와 저장 재시도처럼 정상 흐름 밖의 동작도 확인합니다. 구현은 AI에 맡기며 코드와 테스트를 직접 검토하고, 반복되는 판단은 skills와 lint rule에 남깁니다.

#### 테스트 도입과 AI 개발 workflow | 2026.04 – 현재

4월부터 에이전트로 구현하며 상태의 책임과 공통 코드 사용 기준을 정리했고, 7월부터 테스트를 도입했습니다. 완성된 코드와 테스트의 요구사항을 직접 검토하며 같은 수정이 반복되면 skills를 보완합니다. 의존 방향과 공개 API처럼 자동으로 확인할 수 있는 항목은 lint rule로 검사합니다.

티켓과 plan 검토 → 테스트 작성 → 에이전트 구현과 에이전트 코드 리뷰 → 변경분 테스트, lint, typecheck → 직접 diff 리뷰와 화면 동작 확인 → 전체 CI(테스트, knip, lint) → QA 더블 체크 요청

에이전트 리뷰의 critical 항목은 자동 수정하게 합니다. 완성된 코드와 테스트는 직접 읽고, 요구사항이 빠지거나 컨벤션이 어긋나면 수정을 요청합니다. 화면을 띄워 동작도 확인합니다.

새 기능의 기대 동작은 BDD 형식의 `*.spec`에 적고 컴포넌트별로 빠진 조건이 없는지 검토합니다. 운영이나 QA에서 발견한 오류는 `*.test`에 재현합니다. 새 테스트 패턴은 제품 코드를 일부러 깨뜨려 실패하는지도 확인합니다. 기대 payload는 제품의 변환 함수를 재사용하지 않고 따로 적습니다. API 연동은 dev API 서버를 우선하고 재현하기 어려운 조건에 MSW를 씁니다. lint rule은 RuleTester와 fixture로 테스트합니다.
