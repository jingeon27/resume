  • 모바일 사용성: 리뷰 작성의 키패드 가림·반복 선택 문제를 발견해 PO에게 공유하고, 담당자가 정한 복수 선택 UI를 구현했습니다.
  • 운영 안정성: Sentry를 도입하고 라이브러리 내부까지 원인을 추적해, 75건·57명 이상에게 발생한 크래시를 수정했습니다. 배포 뒤 18일간 같은 오류는 0건이었습니다.
  • 변경에 대응하는 구조: 관리자 검색 화면 27개를 조합 가능한 필터로 전환하고, 폼 필드·값을 TypeScript로 검사하며 테스트·skills·lint rule로 구현 기준을 관리합니다.

조회 구조·성능·운영 오류 대응2025.05 – 현재

  • 서버 조회 결과를 props로 읽어 캐시 무효화가 화면에 반영되지 않던 구조를 TanStack Query prefetch·hydration으로 전환했습니다. 서버 초기 조회와 클라이언트 갱신을 같은 캐시에서 처리합니다.
  • 관리자 검색 오류는 dev에서 나타나지 않아 build 후 start로 재현했습니다. 라우터 캐시 문제까지 추적하고, 서버가 검색 조건을 읽지 않는 같은 경로 변경을 History API로 처리했습니다.
  • 글로벌 서비스에서 목 백엔드 코드가 클라이언트에 포함되던 의존을 분리해 앱 번들을 2,564KB→1,880KB로 줄였습니다. 복지몰에는 지역·진료과 검색의 canonical·제목·동적 사이트맵을 구성했습니다.
  • Sentry를 직접 도입해 오류 수집·중복 처리·민감 정보 제거 기준을 정했습니다. Bottom Sheet 크래시를 라이브러리 버전업으로 해결했고, 회원 조회의 타임아웃·서버 오류가 로그아웃으로 이어지던 정책을 401일 때만 끊도록 바꿨습니다.

  • 관리자 검색 필터 27개를 화면에서 조합하는 구조로 전환하고, 재귀 조건부 타입으로 중첩 필드명·값을 검사하는 createTypedForm<T>를 만들었습니다. 화면 간 직접 참조 62건도 정리했습니다.

  • 에이전트의 구현이 의도와 어긋나면 그 판단 기준을 skills·lint rule에 남깁니다. 현재 작업은 아래 순서로 진행하며, 기능 개발·리팩터링의 제품 코드와 테스트를 직접 읽고 검토합니다.

티켓·plan 검토 → 테스트 작성 → 에이전트 구현·에이전트 코드 리뷰 → 변경분 테스트·lint·typecheck → 직접 diff 리뷰·화면을 띄워 동작 확인 → 전체 CI(테스트·knip·lint) → QA 더블 체크 요청
