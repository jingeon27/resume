테스트 도입과 AI 개발 workflow2026.04 – 현재

2026년 4월부터 에이전트로 구현하고 7월부터 테스트를 도입했습니다. 완성된 제품 코드와 테스트를 읽고 화면 동작을 확인합니다. 반복해서 어긋나는 판단은 skills에 남기고, 의존 방향과 공개 API처럼 자동 검사할 수 있는 항목은 lint rule로 만듭니다.

티켓과 plan 검토 → 테스트 작성 → 에이전트 구현과 에이전트 코드 리뷰 → 변경분 테스트, lint, typecheck → 직접 diff 리뷰와 화면 동작 확인 → 전체 CI(테스트, knip, lint) → QA 더블 체크 요청

새 기능은 BDD 형식의 *.spec에 컴포넌트별 기대 동작을 적고 누락을 검토합니다. 운영이나 QA 오류는 *.test에 재현하며, 새 테스트 패턴은 제품 코드를 일부러 깨뜨려 실패하는지 확인합니다. 기대 payload는 제품의 변환 함수를 재사용하지 않고 따로 적습니다. API 연동은 dev API 서버를 우선하고 어려운 조건은 MSW로 재현합니다. 자체 lint rule은 RuleTester와 fixture, mock으로 검증합니다.

테스트용 QueryClient를 앱과 맞추고 첫 조회 실패와 기존 데이터의 재조회 실패를 나눠 검증했습니다. diff에서 놓친 Bottom Sheet의 헤더 스크롤은 수정 후 브라우저 레이아웃 회귀 테스트로 남겼습니다. 에이전트 리뷰의 critical 항목은 자동 수정하게 하되 결과를 다시 확인합니다. 병렬 worktree에서는 변경분과 영향 범위를 먼저 검사하고 타입 검사는 앱과 패키지 단위로 실행합니다.
