소개

사용자가 예약하고 병원과 운영팀이 처리하는 흐름을 세 제품에 걸쳐 만들어 온 프론트엔드 엔지니어입니다. 가입 회원 약 15만 명, 주간 활성 사용자 약 1만 명의 복지몰과 병원 관리자·백오피스를 개발하며, 2026년 1월부터 사내 유일한 프론트엔드 개발자로, 4월부터는 전사 프론트엔드를 단독으로 담당합니다. 직접 써 보며 찾은 불편과 요구사항에서 빠진 동작을 담당자와 논의하고 구현에 반영합니다.

주요 경험

  • 병원·운영팀·사용자 흐름: 병원 관리자의 등록·검수 요청과 백오피스의 반려·승인 화면을 처음 만들었고, 운영팀이 제보한 반려 불가 오류는 반려에까지 걸린 폼 전체 검증을 찾아 당일 고쳤습니다.
  • 결제: 건강검진 예약금 결제에 토스페이먼츠 결제창을 붙이며, 모바일 리다이렉트를 다녀와도 신청 내용이 남게 하고 연속 클릭으로 주문이 두 번 생기지 않게 했습니다.
  • 모바일·WebView: 모바일로 리뷰를 써 보며 찾은 선택 불편을 PO에게 공유해 복수 선택 UI로 바꿨고, 앱에서 열리지 않던 tel: 상담 버튼은 앱 재배포 없이 기존 브릿지로 고쳤습니다.
  • 운영 오류: Sentry를 직접 도입해 57명 이상에게 75건 발생한 Bottom Sheet 크래시를 고쳤고, 배포 뒤 18일간 0건이었습니다. 회원 조회가 실패할 때마다 로그아웃되던 정책은 401일 때만 끊도록 바꿨습니다.
  • 조회·성능: 무효화해도 갱신되지 않던 서버 조회 구조를 prefetch·hydration으로 옮기고, 글로벌 서비스의 앱 번들을 2,564KB에서 1,880KB로 줄였습니다.
  • 개발 방식: 다섯 제품을 혼자 맡으며 테스트와 skills·lint rule을 도입해, AI로 구현한 코드도 같은 기준으로 검토하고 검증합니다.

세이프닥 | Frontend Engineer | 2025.05 – 현재

기업 제휴와 마케팅으로 들어온 사용자가 제휴 병원의 비급여 프로그램을 예약하는 B2B2C 서비스입니다. 복지몰 MVP 출시 초기에 합류해 복지몰·병원 관리자·백오피스를 개발했고, 2026년 7월부터 글로벌 서비스·CMS도 맡았습니다.

병원 관리자·백오피스와 정산2025.06 – 현재

병원 관리자의 프로그램 등록·검수 요청과 백오피스의 반려·승인 화면은 2025년 12월 말부터 제가 처음 만들었습니다. 2026년 9월 1일 운영팀에서 반려 버튼을 눌러도 반응이 없다는 제보가 왔습니다. 프로그램 내용과 상관없는 반려에도 폼 전체 검증이 걸려 있었고, 검증에 실패하면 요청도 안내도 없이 끝났습니다. 오래전에 등록된 프로그램은 새 할인율·카테고리 규칙을 통과하지 못해 반려조차 막혔습니다. 반려와 검수중 전환은 현재 값으로 보내고 내용을 확정하는 승인에만 검증을 남겨 당일 고쳤고, 병원 관리자 등록부터 백오피스의 반려·승인까지 dev API 서버 E2E로 묶었습니다.

같은 달 병원이 쉬는 요일의 특정 날짜를 진료일로 여는 임시 진료일이 새로 생겼습니다. 서버는 임시 휴무와 같은 배열에 type으로 두 항목을 구분해 보내게 됐지만 기존 예약 판정은 그 배열을 모두 휴무로 읽는 구조라, 그대로 두면 새로 연 날이 막힐 수 있었습니다. 두 관리 화면에 임시 진료일 입력을 따로 두고, 복지몰의 예약 가능일 판정은 type으로 나누되 type이 없는 옛 데이터는 휴무로 읽게 맞춰 세 제품을 함께 배포했습니다.

수기로 관리하던 정산을 내부 예약 데이터와 연결하는 기능은 2026년 4월 초기 구현을 인수해 리팩터링하고 배포 전 운영 요구를 반영했습니다. 1,170줄의 정산 페이지에서 조회·표·선택·편집·정산 처리를 나눴습니다. 가격 이력을 추가하자는 요청에는 정산 기준이 프로그램 가격인지 견적 금액인지 먼저 확인했고, 견적 금액이 기준이라 이력 구조는 만들지 않았습니다.

백오피스 기업·대학 관리에는 컨택상태·활동 이력·다음 예정을 관리하는 영업관리 기능을 더해 10월 운영에 배포했습니다. 쿠폰이 남은 제휴를 해지할 때 일괄 회수를 안내하는 판정은 조회가 끝나기 전에도 저장을 통과시킬 수 있는 구조여서, 해당 기업·대학의 조회 결과를 받은 뒤에만 판정하게 바꿨습니다.

건강검진 예약·결제 내재화2026.09 – 현재

건강검진은 아임웹에서 정보를 보고 전화로 문의하던 흐름이었고, 기존 서비스에서는 검진 프로그램과 예약을 관리하기 어려웠습니다. 제휴 병원의 요청으로 세 제품의 프론트엔드를 맡아 개발팀장·부팀장과 빠진 동작과 예외를 확인하며 9월 9일부터 개발했고, 30일 정식 오픈했습니다. 백오피스에는 검사 구성·기업지원 코드·결제취소·환불 승인을, 병원 관리자에는 검진 예약 관리와 결제취소 요청 접수를, 복지몰에는 검사 선택·기업 검진 코드·예약금 결제를 만들었습니다.

토스페이먼츠 결제창은 모바일에서 결과를 리다이렉트로만 돌려줘, 결제창을 다녀오면 페이지가 새로 열리고 입력이 사라졌습니다. 입력값을 결제 시도의 orderId와 함께 sessionStorage에 저장하고, 같은 주문이며 현재 Zod 스키마를 통과한 값만 한 번 복원하게 했습니다. 주문 생성부터 결제창이 열릴 때까지는 신청 버튼을 잠가 중복 주문을 막았고, 입력 복원과 승인 요청 실패 시 예약 목록 이동은 dev API 서버 E2E로 확인했습니다.

데이터 조회·네트워크 요청·SEO2025.05 – 현재

입사 당시에는 서버 컴포넌트의 ensureQuery 결과를 render props로 전달했습니다. 화면이 Query 캐시를 구독하지 않아 무효화해도 갱신되지 않았고, 조회 조건만 바꿀 때도 서버 렌더링 결과를 다시 받아야 했습니다. 2025년 5월부터 화면별로 prefetch·hydration으로 옮겨 서버 초기 조회와 클라이언트 갱신을 같은 캐시에서 처리하게 했습니다.

  • 관리자 검색 오류는 localhost의 dev에서 나타나지 않아 build 후 start로 재현했습니다. 목록 7개 중 6개에서 확인하고 라우터 캐시 이슈까지 추적해, 서버가 검색 조건을 읽지 않는 화면의 같은 경로 변경은 History API로 처리했습니다.
  • 지역·진료과 검색의 canonical·제목·사이트맵을 구성하고 제휴 병원이 3곳 이상인 조합만 사이트맵에 넣었습니다. 글로벌 서비스는 목 백엔드 코드가 클라이언트 번들에 들어가던 의존을 분리해 앱 번들을 2,564KB에서 1,880KB로 줄였습니다.
