테스트 도입과 AI 개발 workflow2026.04 – 현재

4월부터 에이전트로 구현하고, 7월부터 Vitest·React Testing Library·MSW·Playwright 테스트를 도입했습니다. 구현이 의도와 어긋나면 파일 배치·상태 소유권·공통 코드 사용 기준을 skills에 남기고, 의존 방향·Public API·queryKey는 lint rule로 검사합니다. 현재 기능 개발·리팩터링은 에이전트가 제출한 제품 코드와 테스트를 직접 읽고, 부족한 결과를 반려해 수정본을 다시 확인합니다.

티켓·plan 검토 → 테스트 작성 → 에이전트 구현·에이전트 코드 리뷰 → 변경분 테스트·lint·typecheck → 직접 diff 리뷰·화면을 띄워 동작 확인 → 전체 CI(테스트·knip·lint) → QA 더블 체크 요청

  • 새 기능의 기대 동작은 BDD 형식의 *.spec, 운영·QA 오류는 *.test로 작성합니다. 새 테스트 패턴은 제품 코드를 일부러 깨뜨려 실제로 실패하는지 확인합니다.
  • 기대 payload는 제품 변환 함수를 재사용하지 않고 작성합니다. 실제 RHF·Ant Design 폼 제출로 검증하고 만들기 어려운 조건은 MSW로 재현합니다.
  • 성공만 돌려주는 목이 서버 제약을 가려, 실제 인증으로 dev API 서버에 연결하는 계약 테스트와 병원 관리자·백오피스의 Playwright E2E를 추가했습니다.
  • 자체 lint rule은 RuleTester·__fixture__·mock으로 검증하고 위반을 정리한 규칙만 error로 올립니다. 미사용 코드는 Knip으로 확인합니다.
