# 페이타랩 Web Frontend 지원 서류

2026-10-14 확인한 [공식 Web Frontend 공고](https://recruit.passorder.co.kr/c/SKo7m1X2Wm?back=true)를 기준으로 준비했습니다. 현역 산업기능요원 전직 지원이 가능한 포지션이며, 이력서 상단에 현재 병역유형과 복무 시작 시점을 표기했습니다.

## 제출 파일

- [이력서 PDF](김진건_페이타랩_이력서.pdf): 3쪽. 소개·담당 제품·역할, 경력 상세와 기술적 판단·협업·검증 결과, 기술·지원동기·학력을 한 문서에 담았습니다.

원문은 [이력서](resume-paytalab-frontend.md)이며, [HTML 미리보기](resume-paytalab-preview.html)에서도 확인할 수 있습니다. 경력기술서로 분리했던 상세 내용을 이력서 본문에 통합했습니다.

## 수치와 역할의 근거

기존 공통 이력서 `resumev6.md`·`resumev7.md`와 `AGENTS.md`의 사용자 확인·정정 사항을 기준으로 정리했습니다.

- 가입 회원 약 15만 명과 주간 활성 사용자 약 1만 명을 구분했습니다.
- Bottom Sheet 크래시는 배포 전 75건·57명 이상, 2026-09-10 배포 후 09-28까지 18일간 0건입니다.
- 로그인 해제 정책 변경 후의 확인 기간은 2026-09-23~09-28입니다.
- 글로벌 서비스 3주 배포는 PoC이며, 앱 번들은 2,564KB→1,880KB입니다.
- 테스트 도입은 2026년 7월부터, 두 앱 E2E 추가는 9월입니다.
- 정산은 초기 구현 인수 후 리팩터링·운영 요구 반영, Amplitude는 환경 구축·화면 구현·사용자 행동 측정 역할로 적었습니다.

## 다시 생성하기

저장소 루트에서 실행합니다.

```sh
node scripts/build-paytalab-preview.mjs
node scripts/build-paytalab-preview.mjs --pdf
```

PDF 생성은 기본적으로 macOS Google Chrome을 사용하며, 다른 환경은 `CHROME_BIN`으로 경로를 지정합니다. PDF는 기존 저장소 정책에 따라 Git에서 제외되므로 원문·HTML·생성 스크립트를 관리합니다.

A4·10pt로 이력서 3쪽을 확인했습니다. Markdown의 본문 블록 54개와 외부 링크 16개·이메일 링크가 PDF에 모두 존재하는지 대조했고, 본문·쪽 번호가 겹치지 않는지와 모바일 HTML의 가로 폭을 점검했습니다.
