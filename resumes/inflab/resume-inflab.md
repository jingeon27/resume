## Work Experience

### 세이프닥 | Frontend Engineer | 2025.05 – 현재

회원 약 15만 명, 제휴 기업·대학 1,800곳, 제휴 병원 400여 곳, 등록 프로그램 5,000개 규모의 병원 복지 할인 플랫폼에서 국내 B2C 웹(모바일 브라우저·앱 내 WebView)과 운영 백오피스, 병원 어드민을 개발하고 운영합니다. 2026년 1월부터는 **사내 유일 프론트엔드 엔지니어**로 세 제품의 아키텍처와 공통 기반을 맡고 있으며, 2026년 7월에는 글로벌 서비스와 글로벌 CMS를 구축해 런칭했습니다.

구현 전에는 Jira·API 스펙·Figma·운영 맥락을 확인하고 PO·디자이너·백엔드·마케팅이 판단할 수 있도록 선택지와 영향 범위를 공유합니다. 구현 후에는 결정 이유와 남은 한계를 문서로 남깁니다.

**서비스를 만들고, 데이터로 확인하기**

- 예약까지만 있던 MVP를 리뷰·상담·쿠폰·정산·검수까지 넓혔습니다. 쿠폰 발급·보유·최대 혜택 선택부터 검색·상세·예약 예상 결제금액 반영까지 고객 흐름을 구현하고, 운영자 쪽의 발급·회수·정산까지 이어붙였습니다.
- 퍼널·행동 이벤트 250개 규모 중 140개 이상을 직접 구현·고도화해 검색·시술상세·예약의 이탈 지점과 쿠폰 적용 전후를 계측했습니다. 시술상세 개편 후 리뷰 조회 사용자의 예약 전환율이 미조회 사용자보다 15%p 높게 나온 결과를 **인과가 아닌 상관관계로 해석해** 다음 실험의 근거로 남겼습니다.
- 관심 진료과 선택 → 룰렛 → 맞춤 탐색으로 이어지는 기간 한정 랜딩을 기획·디자인과 함께 만들고, 이벤트와 모바일 E2E로 참여·재진입·종료·공유·CTA 흐름을 검증했습니다.

**다국어와 접근성**

- 영어·한국어·아랍어 라우팅과 아랍어 RTL을 지원하고, 영어·한국어 필수 키가 빠지면 컴파일 단계에서 걸리는 UI 사전을 만들었습니다. API의 `translations[]`와 언어 탭 폼 사이 변환은 별도 계층이 맡아 언어가 늘어나도 화면은 바뀌지 않게 했습니다. `Accept-Language`, hreflang, sitemap도 같은 언어 계약에 맞췄습니다.
- 검증 오류가 나도 포커스가 옮겨가지 않던 커스텀 Select와 옵션 칩을 RHF `Controller`에 연결하고, 오류 순서에 따른 포커스 이동과 정확한 accessible name, `role="alert"`를 회귀 테스트로 고정했습니다. Dialog와 라이트박스의 키보드 조작도 같은 방식으로 검증합니다.

**재사용 컴포넌트와 디자인 시스템**

- Radix UI와 `tailwind-variants`를 기반으로 BottomSheet·Dialog·폼 컨트롤 등 **primitive 20개**를 설계해 주요 사용자 흐름에 적용했습니다.
- BottomSheet는 Compound API로 구성해 브라우저 뒤로가기(`popstate`), route change, backdrop tap, snap point, mount 해제를 공통 라이프사이클에서 처리했습니다. 모바일 웹에서 화면마다 반복해서 새던 지점이라 한곳으로 모았습니다.
- 모든 것을 미리 공통화하지 않고 반복되는 행동만 추출하되 화면별 정책은 주입받게 했습니다.

**같은 문제가 다시 나지 않게**

- 정산은 메인과 도메인이 달라 쿠키를 공유할 수 없었습니다. 처음 구현했던 URL 토큰 전달이 서버 access log와 Referer에 토큰을 남긴다는 것을 확인하고, **form POST BFF**로 바꾸면서 CSP `form-action`·`X-Frame-Options`·open redirect 방어와 회귀 테스트를 적용했습니다. ([기술 글](https://blog.bambyul.com/ko/blog/정산-서비스를-별도-호스트로-분리하며-도메인-간-토큰-전달을-설계한-과정))
- Next.js soft navigation 때문에 직전 예약자의 이름·연락처·병력이 다음 예약 화면에 남는 것을 발견해, 재진입과 성공 시에는 초기화하되 제출 실패 시에는 입력을 보존하도록 상태 생명주기를 나누고 브라우저 회귀 테스트를 추가했습니다.
- 성공만 반환하던 Mock이 실서버의 필수값·enum 계약 위반을 가린다는 것을 발견해, Mock을 끄고 실제 인증과 API로 확인하는 계약 테스트 환경을 따로 만들었습니다. 400만 보고는 어느 필드가 문제인지 알 수 없어 서버가 준 거절 코드와 필드 단위 위반 목록을 그대로 드러내게 했고, 찾은 차이는 폼과 타입에 되돌려 반영했습니다.
- 테스트는 순수 함수·스키마 → API 계약·저장 왕복 → UI 통합 → 브라우저 E2E로 나눴습니다. 폼은 화면을 사용자처럼 조작해 상태를 가진 MSW에 저장한 뒤 다시 조회하고, 번역·기존 ID·조건부 그룹·이미지 순서와 실패 뒤 재시도까지 검증합니다. soft navigation·SSR HTML·IntersectionObserver·가상화처럼 브라우저에서만 증명할 수 있는 결합만 Playwright에 둡니다. E2E를 처음 붙였을 때 10개 시나리오의 콜드 실행이 3.5분씩 걸리고 간헐 실패해서, 원인을 잘못된 내비게이션 대기 조건(`waitForURL`의 기본 `waitUntil: 'load'`)과 반복 삽입되는 프로모션 오버레이로 분리해 20초·3회 연속 flaky 0으로 안정화한 뒤 CI에 올렸습니다.

**모노레포·빌드 환경과 팀 생산성**

- 합류 시점의 B2C 웹은 6-layer FSD 골격은 있었지만 `@legacy`에 250개 파일이 남아 있었고(앞선 담당자들이 석 달간 442개에서 줄여온 상태), 남은 250개를 **26일 만에 0개로** 옮겼습니다. 이후 레이어별 책임과 재사용 카탈로그를 가이드 문서 6개로 정의하고, 역방향 의존은 외부 의존성 없이 직접 만든 ESLint 플러그인으로 lint 단계에서 막았습니다. 규칙을 문서로만 두면 지켜지지 않는다고 봤고, 그 위에서 코드베이스가 세 배 가까이 늘었습니다.
- pnpm·Turborepo 환경에서 서버 상태는 TanStack Query, 입력 중인 값은 타입이 지정된 Form, DTO 차이는 변환 계층, 목록 필터와 페이지는 URL이 소유하도록 3개 앱과 9개 패키지의 경계를 정했습니다. 여러 앱에서 계약이 안정된 도메인만 공통 패키지로 올렸습니다.
- 운영 중인 B2C 웹을 Next.js 14→16, Node 24, Turbopack으로 단계적으로 옮기며 호환 문제와 미사용 webpack 설정을 정리했습니다. TypeScript 네이티브 체커를 병행해 로컬 타입 검사를 **12.5초에서 1.9초로** 줄였습니다.
- 200건을 한 번에 내려받던 목록은 20건 단위 무한스크롤과 TanStack Virtual로 바꾸되, 화면 폭을 재기 전에는 첫 페이지를 그대로 그려 SSR HTML을 유지했습니다. 카드가 쌓인 뒤에도 DOM에는 보이는 행만 남는 것을 E2E로 확인합니다.
- Jira 조회부터 배포 PR 생성까지 반복 작업을 자동화하고, 생성된 코드는 금지된 훅·상수 처리·순수 함수의 의존을 우선 점검합니다. **제가 다시 설명할 수 없는 코드는 반영하지 않습니다.**
