#### 상담 채팅과 실시간 상태 | 2026.06 – 현재

관리자 서비스의 상담 채팅을 맡아 사용자 상담의 입력과 실시간 연결을 고치고, 병원 관리자와 상담사가 대화하는 채팅을 새로 만들었습니다. 두 앱이 대화 화면과 입력칸, 실시간 연결을 함께 쓰도록 공유 패키지로 옮겼습니다. 앱마다 다른 API 함수는 외부에서 주입합니다.

- 방의 SSE 연결은 React 밖 스토어에서 관리하고 `useSyncExternalStore`로 구독합니다. 토큰이 만료되면 갱신하고 연결이 끊기면 `last-event-id`로 이어 받습니다. 메시지와 읽음은 Query 캐시에 바로 반영하며, 메시지 순번이 빠져 있으면 다시 조회합니다.
- 초기 대화 조회와 SSE 연결의 순서가 맞지 않아 지난 이벤트를 다시 받던 문제를 고쳤습니다. 첫 조회가 끝난 뒤 마지막 순번부터 이어 받고, 이 순서를 회귀 테스트로 확인합니다.
- 화면에 보인 메시지의 마지막 순번을 500ms 동안 모아 읽음 처리하고 탭이 가려져 있으면 보내지 않습니다. 대화 목록에는 `column-reverse`를 적용하고, 새 메시지를 받거나 이전 내역을 불러올 때 스크롤 위치를 조정했습니다.
- 병원 관리자가 이미 다른 방에 있어 초대할 수 없으면 409 응답의 ID로 해당 관리자를 구분하고 참여 중인 방을 표시합니다. 나머지 대상은 다시 초대할 수 있게 했습니다.
- 한글 조합 중 Enter로 메시지가 중복 전송되는 문제는 `isComposing`과 전송 중 가드로 막았습니다. lint와 테스트에서 빠져 있던 채팅 영역도 다시 검사 대상으로 넣었습니다.

#### 쿠폰과 인증, 앱과 웹 연결 | 2025.06 – 현재

복지몰은 소셜 로그인 → 본인인증 → 소속인증 → 예약 순서로 이용합니다. 이 과정에서 로그인 수단 추가와 검색, 쿠폰, 예약 화면을 개발했습니다. 쿠폰함과 쿠폰팩을 만들고 예약 시 쿠폰을 적용할 수 있게 했습니다. 예약 화면에 들어오면 혜택이 가장 큰 쿠폰을 미리 선택합니다.

- 결제 예정 금액이 바뀌면 적용했던 쿠폰을 해제하도록 했습니다. 결제수단과 상태에 따라 입력, 완료, 취소할 수 있는 조건은 도메인 함수와 ts-pattern으로 모았습니다.
- 앱에서 `tel:` 상담 버튼을 눌러도 열리지 않아 기존 브릿지의 외부 링크 열기에 연결했습니다. 외부 예약 사이트 이동 기능을 만들 때는 뒤로 가기를 누르면 WebView가 통째로 닫히는 문제를 배포 전에 발견했습니다. 외부 사이트는 브릿지로 열고 웹 안의 이동은 웹 라우터로 처리하도록 고쳤습니다.
- 인증 후 이동 중 앱이 멈추는 오류를 Next.js 소스까지 추적했습니다. `redirect()` 처리 중 훅 호출 순서가 달라지는 경우를 찾아 해당 경로의 진입 조건 확인과 리다이렉트를 React 렌더 전의 proxy로 옮겼습니다.
- 잘못 안내된 쿠폰함 주소는 앱 핫픽스 대신 Load Balancer에서 리다이렉트하자고 제안해 합의했습니다.

#### 상태 관리와 공통 구조 | 2025.05 – 현재

기존 화면은 서버의 `ensureQuery` 결과를 render props로 받아 클라이언트에서 Query 캐시를 무효화해도 갱신되지 않았습니다. 2025년 5월부터 prefetch와 hydration으로 바꿔 서버가 준비한 데이터를 클라이언트도 같은 캐시에서 읽고 갱신하게 했습니다. 서버가 읽지 않는 URL 조건만 바꿀 때는 History API를 사용했습니다.

- 예약자의 가족과 날짜 값이 여러 상태에 흩어져 있었습니다. 서버에서 받은 목록은 Query에, 작성 중인 값은 RHF에 두고 제출 조건은 Zod로 검사하도록 정리했습니다.
- 화면마다 예외가 붙던 공통 검색 필터는 JSX 중복을 일부 감수하고 각 화면이 필요한 필터를 조합하도록 바꿨습니다. 27개 화면에 적용하고, 폼의 중첩 필드명과 값은 재귀 조건부 타입을 쓴 `createTypedForm<T>`로 검사합니다.
- 재사용할 것 같으면 entities에 두던 모호한 기준을 바꿔 서버 도메인은 features, 화면 조합은 pages, 공통 UI는 shared로 정했습니다. 화면 간 직접 참조를 정리하고 lint rule로 검사합니다. Bottom Sheet는 Compound Components와 overlay-kit으로 바꿔 본문과 하단 버튼이 같은 폼을 쓰게 했습니다.
- 글로벌 사용자 서비스와 CMS는 전달받은 프로토타입의 모든 화면을 구현해 3주 만에 PoC로 배포했습니다. shadcn/ui와 Base UI를 사용하고 다국어와 RTL을 지원했습니다. 파일 전송은 React 밖 스토어에서 관리하며 동시에 전송하는 용량을 제한했습니다.
