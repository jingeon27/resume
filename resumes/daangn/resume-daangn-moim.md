#### SSR·Streaming 및 시스템 이슈 해결 | 2026.04 – 현재

상담 화면의 서버 조회를 TanStack Query `prefetch`·hydration 구조로 전환해 서버 초기 데이터와 클라이언트 조회·무효화가 하나의 Query 캐시를 사용하도록 만들었습니다. 이후 Next.js `cacheComponents`를 적용하고 동적 렌더링과 캐시 범위를 다시 정리했습니다.

- 인증이 끝난 회원을 되돌려 보내는 서버 컴포넌트의 `redirect()`가 클라이언트 이동 중 하드 내비게이션으로 처리되면서 훅 개수가 어긋나 앱 전체가 멈추는 문제를 추적했습니다. 당시 프로덕션 unhandled 오류 중 영향 사용자 1위(68건·53명)였으며, Next.js 라우터 코드를 확인해 진입 게이트를 프록시로 이동했습니다.
- 검색 페이지의 서버 prefetch와 화면 훅이 서로 다른 `queryKey`를 만들어, 화면이 서버에서 채운 Query 캐시를 읽지 못했습니다. 사이트맵의 검색 URL 678개도 JS를 실행하지 않는 환경에서는 목록이 나오지 않는 구조였습니다. 키를 맞추고 첫 렌더부터 서버 데이터를 읽는지 네 가지 조합으로 테스트했습니다.
- `generateMetadata`의 스트리밍 때문에 기본 봇 목록에 없는 AI 인용·카카오톡·Daum 미리보기 봇이 canonical을 `<body>`에서 받고 있었습니다. 해당 봇을 기존 목록에 추가해 메타데이터가 `<head>`에 포함되도록 했습니다.
- Next.js 16 전환 뒤 개발 서버와 jsdom에서는 나타나지 않던 관리자 검색 회귀를 프로덕션 빌드에서 재현했습니다. 목록 7개 중 6개를 확인하고 업스트림 라우터 캐시 이슈까지 추적했습니다. 서버가 검색 조건을 읽지 않는 화면의 같은 경로 쿼리 변경은 History API로 처리했습니다.

#### Sentry 도입과 운영 오류 추적 | 2026.08 – 09

복지몰의 브라우저·서버·Edge 환경에 Sentry를 도입하고 운영 오류를 분류·추적하는 체계를 만들었습니다.

- 화면이 뜨지 않는 오류, 작업을 막는 오류, 재시도 가능한 실패를 구분하고 동일한 오류가 API 계층과 Error Boundary에서 중복 수집되지 않도록 했습니다.
- `sendDefaultPii: false`만으로 의료·인증 정보가 제거되지 않는 것을 확인해 SDK 소스를 추적했습니다. event·breadcrumb·transaction·span에 포함되는 데이터를 확인하고 민감한 값을 제거했으며, 누락을 막기 위해 타입과 단위 테스트를 추가했습니다.
- release와 브라우저 소스맵을 연결하고 Sentry API로 artifact bundle 생성을 확인했습니다. LCP·FCP·TTFB 전송 여부는 브라우저 E2E로 확인했으며, 사내 Sentry MCP를 연결해 에이전트도 운영 이슈를 조회할 수 있게 했습니다.
- Bottom Sheet 드래그 크래시를 라이브러리 내부의 null ref 접근까지 추적했습니다. 라이브러리를 업데이트하되 공통 Root에서 변경된 snap point 규칙을 변환해 기존 사용처를 유지했습니다. 수정 전 57명 이상에게 75건 발생한 오류 그룹은 배포 후 18일 동안 0건이었습니다.

- 새로운 테스트 패턴은 제품 코드를 의도적으로 깨뜨려 실제로 실패하는지 확인한 뒤 도입합니다.
- 새 기능의 기대 동작은 BDD 형식의 `*.spec`에 적고, 운영·QA에서 발견된 오류는 `*.test`에 재현합니다. 컴포넌트별로 빠진 조건이 없는지 읽고 확인합니다.

API 계약 테스트는 별도 단계로, E2E는 CI 밖에서 실행합니다.

#### AI 개발 workflow | 2026.04 – 현재

Claude Code와 Codex를 기능 개발과 리팩터링에 사용합니다. 에이전트가 제출한 코드와 테스트를 읽고, 부족한 부분을 짚어 수정본을 다시 확인합니다. 반복되는 지적은 skills와 lint 규칙에 남깁니다.

티켓·plan 검토 → 테스트 작성 → 에이전트 구현·에이전트 코드 리뷰 → 변경분 테스트·lint·typecheck → 제 diff 리뷰·로컬 화면 확인 → 전체 CI(테스트·knip·lint) → QA 더블 체크 요청

문제가 나오면 앞 단계로 돌아가 수정된 결과를 다시 확인합니다.

- 상태를 어디에 둘지, 어떤 경로로 import할지 같은 기준은 skills에 정리했습니다. 정적으로 검사할 수 있는 것은 자체 ESLint 규칙으로 옮겼습니다.
- 직접 import 경고 271건을 정리한 뒤 오류로 승격했습니다.
- 동적 import와 `as const` 쿼리 키를 놓치던 자체 규칙을 보완하도록 지시하고 결과를 확인했습니다. 새 테스트를 수정 전 규칙에 실행했을 때 8건이 실패했습니다.
- 여러 worktree에서 전체 검사를 동시에 돌리면 CPU를 서로 차지했습니다. 로컬 lint와 테스트는 변경 파일·영향 범위를 중심으로 돌리고, 타입 검사는 패키지나 앱 단위로 유지했습니다. 전체 검사는 CI에서 확인합니다.
- 타입 인지 lint는 검사 시간이 3.3배 늘어 도입을 보류했습니다.

#### 건강검진 서비스 내재화 | 2026.09 – 현재

건강검진은 아임웹에서 정보를 보고 전화로 문의해야 했습니다. 제휴 병원이 세이프닥에서 검진 예약을 받기를 요청했지만, 기존 비급여 프로그램에는 검사 구성·기업지원 검진·예약금 결제가 없었습니다. 개발팀장·부팀장과 빠진 동작과 예외를 확인하며 세 제품의 프론트엔드를 개발했습니다. 9월 9일부터 두 주 동안 순차 개발해 23일 운영에 배포했고, 30일 정식 오픈했습니다.

- 백오피스에는 검사항목·필수 및 선택 검사 구성, 기업지원 코드·서류 확인, 결제내역과 결제취소·환불 승인을 추가했습니다.
- 병원 관리자는 검진 프로그램을 조회하고 예약을 관리하도록 했습니다. 병원이 직접 처리할 수 없는 예약금 결제취소는 요청 접수로 안내했습니다.
- 복지몰에는 검진 상세·검사 선택·기업 검진 코드 입력·예약금 결제·예약 상세를 만들었습니다.
