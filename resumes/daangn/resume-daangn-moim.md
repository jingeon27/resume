## 소개

React 19·Next.js 16과 TypeScript로 가입 회원 약 15만 명의 복지몰과 병원 관리자·백오피스를 만드는 프론트엔드 엔지니어입니다. 2026년 1월부터 사내 유일한 프론트엔드이고, 4월부터 세 제품을 혼자 맡고 있습니다.

기능을 만들 때 사용자가 실제로 어떻게 쓰는지부터 봅니다. 모바일 리뷰 화면을 직접 써 보다 찾은 불편을 PO에게 공유했고, 검진 항목을 다 고르면 다음 그룹으로 넘기자는 요청에서는 빈틈을 짚어 담당자와 동작을 다시 정했습니다.

출시 뒤에는 Sentry로 운영 오류를 수집·추적해 영향이 큰 것부터 고칩니다. 모바일 시트 크래시(수정 전까지 누적 57명 이상)는 수정 배포 뒤 18일 동안 0건이 됐습니다. 기대 동작은 테스트로 먼저 적고, 운영·QA에서 나온 오류는 테스트로 재현해 다시 막습니다.

개발할 때는 기준을 먼저 세웁니다. 프로덕션 오류는 브라우저·React·Next.js의 실행 흐름을 따라 원인을 찾고, 타입은 재귀 조건부 타입과 Zod 스키마로 잘못된 값이 들어오는 경로마다 막습니다. 구현은 AI에게 맡기지만, 작성된 코드는 전부 이해해야 한다고 생각해 코드와 테스트를 직접 읽고 화면을 띄워 동작을 확인합니다.

중학교 때 게임 커뮤니티에서 만난 사람들과 정모로 직접 만나기도 했고, 그중 몇몇과는 지금까지 관계를 이어오고 있습니다. 같은 관심사로 온라인에서 시작한 인연이 오래 이어진 것은 제 인생에서 특별한 경험이었습니다. 당근 모임을 개발하며 더 많은 사람에게 이런 만남과 관계의 가치를 전하고 싶어 지원했습니다.

#### SSR·Streaming과 라우팅 개선 | 2026.04 – 현재

**역할** 프론트엔드 단독. 원인 추적·수정·테스트를 맡았습니다.

상담 화면은 서버에서 TanStack Query로 `prefetch`한 데이터를 hydration으로 넘기고, 클라이언트의 조회·무효화도 같은 캐시를 쓰게 했습니다. 6월에는 Next.js `cacheComponents`를 켜며 페이지의 `force-dynamic`을 걷어내고, 사이트맵은 `use cache`로 하루 단위로 캐시했습니다. 그 뒤 뒤로·앞으로 가기로 다시 들어온 폼에 이전 입력이 남아 있었는데, 떠난 화면이 언마운트되지 않고 `<Activity>`로 숨겨지기 때문이라 숨겨질 때도 실행되는 effect cleanup에서 공용 폼 훅이 폼을 초기화하게 했습니다.

- 이미 인증을 마친 회원이 본인인증·로그인 화면으로 갔다 되돌려질 때 앱 전체가 멈추는 오류를 추적했습니다(조사 당시 영향 사용자가 가장 많던 프로덕션 unhandled 오류, 68건·53명). Next.js 라우터 코드를 따라가 보니 클라이언트 이동 중 서버 컴포넌트가 던진 `redirect()`는 하드 내비게이션으로 처리되고, `AppRouter`가 훅 목록 중간에서 렌더를 멈춰 다음 렌더의 훅 개수가 어긋났습니다. 리다이렉트를 렌더 전 요청 단계인 Next.js proxy(구 middleware)로 옮겼습니다.
- 검색 페이지의 서버 prefetch와 화면 훅이 같은 URL을 서로 다른 Zod 스키마로 읽어 `queryKey`가 갈렸습니다. 화면이 서버가 받아 둔 목록을 찾지 못해 HTML이 로딩 상태로 나갔고, 사이트맵의 검색 URL 678개에서 JS를 실행하지 않는 봇은 목록을 받지 못했습니다. prefetch 조건을 화면 훅의 스키마로 만들게 하고, 시술·병원 탭과 필터·통합 검색의 네 조합에서 첫 렌더부터 서버 데이터를 읽는지 테스트했습니다.
- 스트리밍 응답은 `<head>`를 먼저 보내고 늦게 끝난 메타데이터를 `<body>`에 붙입니다. 기본 봇 목록에 없던 카카오톡·Daum 미리보기 봇과 AI 인용 봇이 canonical을 `<body>`에서 받고 있어, 목록에 더해 메타데이터를 기다린 뒤 `<head>`에서 받게 했습니다.
- Next.js 16 전환 뒤 관리자 검색이 동작하지 않는 오류는 개발 서버와 jsdom 테스트에서 나타나지 않아, 프로덕션 빌드로 재현해 목록 7개 중 6개에서 확인했습니다. 업스트림 라우터 캐시 이슈를 찾은 뒤, 클라이언트에서 목록을 조회하는 화면의 같은 경로 검색 조건 변경은 RSC 요청 없이 History API로 처리했습니다. 업스트림 버그는 16.3에서 고쳐졌지만, 이 화면들은 서버에 다시 물을 게 없어 버전을 올려도 History API를 유지하기로 했습니다. 8월 13일 핫픽스와 18일 전환 뒤 9월 28일까지 같은 증상의 재보고는 없었습니다.

#### 폼·검색 필터의 타입과 스키마 설계 | 2025.06 – 현재

**역할** 공용 폼·검색 필터와 검증 경계를 설계하고 운영 화면 전환까지 맡았습니다.

- Ant Design 폼은 필드 경로를 아무 문자열·배열로나 받아 중첩 필드명이 틀려도 컴파일됩니다. 폼 값 타입에서 유효한 경로와 그 값 타입을 재귀 조건부 타입으로 계산하는 `createTypedForm<T>`를 만들어, `name`·`getFieldValue`·`setFieldValue`·`useWatch`가 경로와 값을 함께 검사하게 했습니다. 서버 응답을 폼 값으로, 폼 값을 제출값으로 바꾸는 코드는 순수 함수로 분리했습니다.
- 공통 검색 필터 렌더러에 화면별 예외가 쌓여, JSX 일부 중복을 감수하고 각 화면이 필터를 직접 조합하도록 운영 화면 27개를 전환했습니다. 필드명은 조회 조건 스키마에서 `z.infer`로 파생해 서버 파라미터와 어긋나면 컴파일 오류가 나고, URL도 같은 스키마로 읽어 폼 타입과 검증 규칙이 갈라지지 않습니다.
- Zod의 실패 처리는 값의 출처에 따라 나눴습니다. 이미 돌아가는 화면에 뒤늦게 씌운 API 응답 스키마는 불일치를 기록하고 원본을 통과시키며, 로그로 찾은 두 형태의 검색 제안 응답은 dev 표본 2,292건과 대조해 `discriminatedUnion`으로 모델링했습니다. URL은 오래된 링크의 값 하나 때문에 검색 조건 전체가 사라지지 않도록 잘못된 필드만 스키마의 기본값으로 되돌립니다. 되돌린 값은 로그가 남지 않아, 반드시 추적할 파라미터에는 기본값을 두지 않습니다.
- 리뷰 정렬·사진 리뷰 필터가 URL 값을 `useState`로 복제하고 있어, 뒤로 가기나 다른 필터가 URL을 바꾸면 목록과 선택 표시가 어긋날 수 있었습니다. URL만 읽게 바꾸고, `router.replace`는 RSC 응답을 받아야 커밋되므로 그동안 보이는 값만 `useOptimistic`으로 앞당겼습니다.
- 예약 화면의 가족·날짜 선택 값이 Query 캐시·Zustand·로컬 상태에 나뉘어 있던 것을 React Hook Form과 Zod로 모아, 가족을 추가하면 날짜가 어긋나던 문제를 고치고 예약 대상 선택 컴포넌트를 519줄에서 55줄로 줄였습니다.

#### Sentry 도입 | 2026.08 – 09

**역할** 도입 설계부터 민감 정보 제거·운영 오류 대응까지 맡았습니다.

복지몰의 브라우저·서버·Edge 환경에 Sentry를 도입해 오류의 심각도를 나누고, 배포 버전과 원본 코드를 연결해 운영 중 생긴 문제를 추적합니다.

- 화면이 뜨지 않는 오류, 작업을 막는 오류, 재시도할 수 있는 실패를 구분하고, 같은 오류를 API 계층과 Error Boundary에서 두 번 보내지 않게 했습니다.
- SDK 소스를 읽고 event·breadcrumb·transaction·span에 담기는 데이터를 확인해 의료·인증 정보를 제거했습니다. 빠뜨리는 항목이 없도록 타입과 단위 테스트도 추가했습니다.
- release와 브라우저 소스맵을 연결해 artifact bundle 생성까지 확인했고, 사내 Sentry MCP로 에이전트가 운영 이슈를 조회할 수 있게 했습니다.
- Bottom Sheet를 드래그할 때 생긴 크래시를 라이브러리의 null ref 접근까지 추적했습니다. 라이브러리를 업데이트하며 바뀐 snap point 규칙은 공통 Root에서 변환해 기존 사용처를 유지했고, 수정 배포 전까지 누적 57명 이상에게 75건 발생한 오류 그룹은 배포 후 18일 동안 0건이었습니다.
- 회원 조회가 실패하면 바로 로그아웃되던 처리를 401 응답일 때만 로그아웃하도록 고쳤습니다. 9월 23일 운영 배포 뒤 9월 28일까지 관련 CS 문의와 운영 Sentry의 회원 조회 실패·401 로그아웃이 0건이었습니다.

#### 테스트 체계 재구축 | 2026.07 – 현재

**역할** 테스트 기준과 구조를 정하고 두 저장소에 적용했습니다.
