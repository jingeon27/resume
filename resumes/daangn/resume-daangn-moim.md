#### Sentry 도입 | 2026.08 – 09

복지몰의 브라우저·서버·Edge에 Sentry를 연결했습니다. 8월 19일부터 구현해 27일 운영에 배포했습니다. 화면이 뜨지 않는 오류, 작업을 막는 오류, 재시도할 수 있는 실패를 구분해 레벨을 정하고, 같은 오류가 API 처리와 Error Boundary를 거치며 여러 번 수집되지 않도록 했습니다.

`sendDefaultPii: false`를 설정해도 헤더·쿠키·본문·URL이 모든 전송 경로에서 빠지는 것은 아니었습니다. SDK 소스를 따라 이벤트·breadcrumb·transaction·span에 어떤 값이 실리는지 확인하고 의료·인증 정보가 담기는 값을 제거했습니다. 새 수집 항목을 추가할 때도 처리를 빠뜨리지 않도록 타입과 단위 테스트를 붙였습니다.

release와 브라우저 소스맵을 연결하고 Sentry API로 artifact bundle 생성을 확인했습니다. LCP·FCP·TTFB가 실제 브라우저에서 전송되는지는 E2E로 확인했고, 에이전트가 운영 이슈를 조회할 수 있도록 사내 Sentry MCP를 연결했습니다. 서버 소스맵은 업로드 중 502가 발생해 8월 31일부터 제외했습니다. 서버 스택은 압축된 코드로 남는 상태입니다.

도입 후에는 Bottom Sheet 드래그 크래시를 라이브러리의 null ref 접근까지 추적했습니다. 라이브러리를 올리고 바뀐 snap point 규칙은 공통 Root에서 변환해 기존 사용처를 유지했습니다. 수정 전 57명 이상에게 75건 발생한 오류 그룹은 9월 10일 배포 뒤 28일까지 0건이었습니다.

#### 테스트 체계 재구축 | 2026.07 – 현재

기존 테스트는 실제 폼에서 요청이 나가는지, 서버가 입력을 받아 주는지 확인하지 못했습니다. 이를 정리한 뒤 7월 20일부터 관리자 서비스 모노레포와 복지몰의 테스트를 다시 구성했습니다. 작성은 에이전트에 맡기고, 저는 확인할 동작과 빠진 조건을 짚고 테스트가 실제 오류를 잡는지 검토합니다.

- 순수 함수·스키마는 Vitest, 실제 UI와 폼은 React Testing Library·MSW, API 계약은 dev API 서버, 브라우저 흐름은 Playwright로 확인합니다.
- 테스트에서 제출 로직을 복제하던 Harness 대신 실제 등록 Drawer를 렌더하도록 바꿨습니다. 잘못된 입력에도 성공하던 Mock에는 확인한 서버 제약을 반영했습니다. 기대 payload는 제품의 변환 함수를 다시 호출해 만들지 않고 별도로 적었습니다.
- 등록·수정 Drawer를 나누면서 등록 후 창이 닫히지 않는 오류와 URL로 직접 진입하면 수정 payload 타입이 어긋나는 오류를 찾았습니다.
- 9월에는 병원 관리자에서 프로그램을 등록하고 Back-Office에서 검수중·반려·승인하는 E2E를 추가했습니다. 앱마다 로그인을 준비하고 테스트별 서버 상태를 맞춰 실행 순서가 달라도 동작하도록 했습니다.

새 기능의 기대 동작은 BDD 형식의 `*.spec`에 적고 컴포넌트별로 빠진 조건을 확인합니다. 운영·QA에서 발견한 오류는 `*.test`로 재현합니다. 새 패턴의 테스트는 제품 코드를 일부러 깨뜨려 실패하는지 확인한 뒤 넣습니다. dev API 계약 테스트는 PR을 막지 않는 별도 단계로 돌리고, E2E는 CI 밖에서 실행합니다.
