직접 써 보며 발견한 불편과 운영 제보를 기획·디자인·백엔드 담당자와 확인해 구현합니다. 여러 화면에서 반복되는 동작은 공통 컴포넌트로 정리하고, 코딩 에이전트가 만든 결과는 변경 코드와 테스트·실제 화면으로 검증합니다. 반복되는 리뷰 기준은 저장소별 스킬과 lint 규칙에 반영합니다.

#### 모바일 사용성 개선과 WebView 연동

- **리뷰 작성:** 직접 모바일에서 써 보며 시술 선택 목록이 키패드에 가려지고, 여러 개를 골라야 하는데 하나를 고를 때마다 닫히며, 선택한 항목도 잘 보이지 않는 문제를 발견했습니다. Jira에 정리해 PO에게 공유하고, 기획·디자인이 정한 드롭다운 안 복수 선택·체크·칩을 구현했습니다. 이후 디자인 시스템에서 선택 UI가 Bottom Sheet로 바뀌었을 때도 리뷰 화면에 적용하고, 시트 안 임시 선택을 ‘확인’할 때 폼에 반영하도록 구성했습니다.
- **검진 항목 선택:** 정해진 수만큼 고르면 다음 그룹으로 자동 이동하자는 요청에서, 기존 선택을 수정할 때도 강제 이동하는 문제를 짚었습니다. 담당자와 논의해 선택 수를 채운 그룹의 미선택 chip만 비활성화하도록 바꾸고, 빠져 있던 비활성 상태 디자인을 요청해 반영했습니다.
- **인앱 WebView:** 앱에서 동작하지 않던 `tel:` 전화상담 버튼을 기존 브릿지의 외부 링크 열기로 연결해 웹 배포로 해결했습니다. 외부 예약 사이트 이동 기능에서는 첫 구현의 네이티브 뒤로 가기가 WebView째 닫히는 것을 배포 전에 확인하고, 외부 사이트는 브릿지로 열되 이전 화면 복귀는 웹 라우터로 처리하도록 수정했습니다.

**티켓·plan 검토 → 테스트 작성 → 에이전트 구현·에이전트 코드 리뷰 → 변경분 테스트·lint·typecheck → 제 diff 리뷰·로컬 화면 확인 → 전체 CI(테스트·knip·lint) → QA 더블 체크 요청** 순서로 일하며, 문제가 나오면 앞 단계로 돌아갑니다.

- 새 기능의 기대 동작은 BDD 형식의 `*.spec`에 적어 컴포넌트별 누락 조건을 확인하고, 운영·QA에서 발견한 오류는 `*.test`로 재현합니다. 새 패턴의 테스트는 제품 코드를 일부러 깨뜨려 실제로 실패하는지 확인한 뒤 넣습니다.
- 9월에는 복지몰 lint가 레이어 루트·동적 import 위반을 놓치는 것을 확인해 규칙과 테스트를 보완했습니다. 추가한 테스트를 수정 전 규칙에 돌려 **8건이 실패**하는 것을 확인했습니다. 글로벌 서비스는 테스트에서 응답 스키마 위반이 경고로만 끝나던 것을 실패로 바꾸고, 목 데이터를 일부러 틀리게 해 검증했습니다.

React·TypeScript 기반 ATS ‘RoundHR’의 채용 관리 웹·채용 담당자용 웹·랜딩과 후보자 수집 Electron 앱을 팀원으로 개발했습니다. 프론트엔드·백엔드 개발자, 디자이너와 협업했습니다.

- 채용 공고 순서, 후보자 필터의 중첩 트리, 설정 테이블의 행 정렬에 DnD를 적용했습니다. 화면마다 따로 다루던 컨텍스트·핸들·정렬 대상을 dnd-kit 기반 공통 컴포넌트로 정리하고, 폴더 클릭과 정렬이 맞물릴 때 선택이 풀리는 동작도 수정했습니다. React Query key는 `query-key-factory`로 정리했습니다.
- 후보자 수집 앱의 로그인→수집→중복 확인→업로드를 공통 순서와 사이트별 adapter로 나누는 초기 구조를 설계하고, 잡플래닛·게임잡을 연결했습니다. 지원자 한 명의 실패가 전체 수집을 멈추지 않도록 격리했습니다. 현재 코드는 이후 동료가 다시 작성한 부분이 많습니다.
