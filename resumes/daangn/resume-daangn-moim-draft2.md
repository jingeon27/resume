## 소개

사용자 경험과 제품의 맥락을 살피며 기능을 개발하고, 기존 코드의 기술부채를 줄여 온 프론트엔드 엔지니어입니다. React·TypeScript·Next.js로 채용 SaaS와 의료복지 서비스를 개발·운영했습니다.

요구사항에서 빠진 동작은 담당자와 논의하고, 기술을 선택할 때는 이점과 전환·유지 비용을 함께 살핍니다. AI 개발 workflow로 빠르게 작업하면서 코드와 테스트를 먼저 읽고, 화면을 띄워 동작을 확인합니다. 반복되는 판단은 skills와 lint rule에 남깁니다.

중학교 때 게임 커뮤니티에서 가까운 지역에 살던 사람들을 알게 돼 정모로 만났고, 몇몇과는 지금도 연락하며 지냅니다. 같은 관심사를 가진 이웃과 오래 관계를 이어 온 경험이 특별해, 당근모임에서 더 많은 사람이 이런 만남을 시작하도록 돕고 싶습니다. 직접 모임에 참여하고 사용자 의견을 반영하는 팀에서, 제가 만든 변화가 모임 참여와 이후 활동에 미치는 영향을 동료들과 확인하고 싶습니다. 제품을 개선하면서 AI 개발 workflow와 SSR 서버 운영 경험도 넓히고 싶습니다.

#### CSR·SSR 범위와 데이터 조회 설계 | 2025.05 – 현재

입사 당시에는 서버 컴포넌트의 `ensureQuery` 결과를 render props로 전달했습니다. 화면이 Query 캐시를 구독하지 않아 무효화해도 갱신되지 않았고, 조회 조건만 바꿀 때도 서버의 렌더링 결과를 다시 받아야 했습니다.

2025년 5월 예약 화면부터 prefetch·hydration으로 바꾸고 다른 화면으로 확대했습니다. 초기 HTML에 필요한 데이터는 서버가 준비하고, 화면은 `useQuery`·`useSuspenseQuery`로 같은 캐시를 구독해 이후 조회·갱신·무효화를 처리하도록 나눴습니다.

- 관리자 검색 오류는 localhost의 `dev`에서 나타나지 않아 `build` 후 `start`로 재현했습니다. 목록 7개 중 6개에서 확인하고 라우터 캐시 이슈까지 추적했습니다. 서버가 검색 조건을 읽지 않는 화면의 같은 경로 조건 변경은 History API로 처리해 검색을 복구하고 불필요한 RSC 재요청을 줄였습니다. 수정 뒤 9월 28일까지 같은 증상의 재보고는 없었습니다.
- 인증 후 리다이렉트에서 앱이 멈추는 오류는 조사 당시 68건·53명에게 발생했습니다. Next.js 소스에서 `AppRouter`가 훅 호출 도중 렌더를 끝내는 경로를 확인하고, 인증 확인·리다이렉트를 React 렌더링 전 proxy로 옮겼습니다.
- 다른 서비스와 비교해 메타데이터·JSON-LD를 설계하고 병원·시술·인근 지하철역 정보를 반영했습니다. 정해진 값이 없을 때 직접 채워도 되는지 확인한 뒤 적용했습니다. Streaming 도입에 맞춰 일부 미리보기 봇에는 메타데이터를 `<head>`로 보내도록 설정했습니다.

#### 코드 구조와 기술부채 개선 | 2025.06 – 현재

- **예약 상태 관리:** 날짜를 고른 뒤 가족을 추가하면 선택 일시가 어긋났습니다. Query 캐시·Zustand·로컬 상태에 나뉜 값의 역할을 정리해 서버 목록은 Query, 작성 중인 값은 RHF, 제출 검증은 Zod로 관리했습니다. 동기화 로직을 훅·하위 컴포넌트로 나눠 519줄이던 예약 대상 선택 컴포넌트를 55줄로 줄였습니다(2025.06).
- **공통 UI 리팩터링:** `header`·`content`·`button`을 함수 인자로 받던 Bottom Sheet를 Compound Components와 overlay-kit으로 바꿨습니다. 본문과 하단 버튼이 같은 RHF 폼을 사용하고, 시트 안에서 고른 값은 ‘확인’을 눌러야 바깥 폼에 반영되도록 했습니다(2026.04).
- **검색·폼 표준화:** 검색 화면 27개를 `createSearchFilter(schema)`로 전환해 URL·폼·조회 조건을 같은 스키마로 다뤘습니다. 화면별 JSX 반복은 감수하고 공통 렌더러에 예외 분기가 쌓이지 않도록 했습니다. Ant Design Form에는 재귀 조건부 타입과 `infer`를 쓰는 `createTypedForm<T>`를 만들어 중첩 필드명·값을 컴파일 단계에서 검사합니다.
- **FSD 기준 정리:** 재사용할 것 같다는 이유로 `entities`에 두던 코드를 다시 구분했습니다. 서버 모델·API는 `features`, 화면별 조합은 `pages`, 도메인과 무관한 공용 UI는 `shared`로 정했습니다. 화면끼리 직접 참조하던 62건을 정리하고 새 위반은 lint error로 막았습니다(2026.09).
- **정산 리팩터링:** 엑셀 정산을 내부 예약 DB와 연결하는 기능의 초기 구현을 인수했습니다. 배포 전 요구사항을 반영하며 1,000줄이 넘는 파일의 조회·표·선택·편집·정산 처리를 나누고 타입·의존성을 정리했습니다. ref·`useImperativeHandle`로 열던 모달은 대상 데이터와 `open`·`onCancel`을 props로 받게 바꿨습니다. 낙관적 갱신의 조회 취소·rollback을 보완하고 필터 유실·다중 선택 오류를 회귀 테스트로 확인했습니다(2026.04 – 현재).
- **검증·오류 처리:** 기존 API 응답의 Zod 불일치는 트래킹하며 스키마를 맞추고, 잘못된 URL 필드는 기본값으로 되돌리며 결제 복원값은 버립니다. 독립적으로 복구할 기능마다 Error Boundary를 적용하고 백오피스 라우트 30개의 조회·화면 구성을 통일했습니다. API·렌더링 오류와 스키마 불일치는 AWS CloudWatch 로그로 추적합니다.

4월부터 Compound Engineering 방식으로 skills를 보완하고 FSD·lint rule을 저장소에 맞게 바꿨습니다. 반복해서 어긋나는 구현과 검토 기준을 남기며 에이전트에 맡기는 범위를 넓혔습니다.

티켓·plan 검토 → 테스트 작성 → 에이전트 구현·에이전트 코드 리뷰 → 변경분 테스트·lint·typecheck → 직접 diff 리뷰·화면을 띄워 동작 확인 → 전체 CI(테스트·knip·lint) → QA 더블 체크 요청

- Jira·Figma에서 빠진 동작과 사용성 의견을 담당자와 맞추고, 작업별로 PR까지 한 번에 맡길지 plan·완료 결과를 확인할지 정합니다. 에이전트가 제출한 완성본의 코드·테스트를 읽고 부족하면 반려합니다. critical 자동 수정 결과도 검토하며, 문제가 나오면 앞 단계로 돌아갑니다.
- 반복되는 판단은 skills·lint rule에 남기고 미사용 코드는 Knip으로 확인합니다. 슬라이스 내부 파일을 직접 참조하던 위반 271건을 정리했습니다. lint rule은 RuleTester·`__fixture__`·mock으로 검증합니다.
- 병렬 worktree의 CPU 부하를 줄이려고 작업 중에는 변경·영향 범위의 lint·테스트와 앱·패키지 단위 typecheck를 실행합니다. 전체 검사는 CI에서 확인합니다.

#### 기술 선택과 전환 | 2025.10 – 현재

- **UI 조합:** Headless UI에서 Radix UI로 옮겨 공통 UI의 조합 유연성과 접근성 primitive를 활용했습니다. 기존 props·이벤트·열림 상태를 바꾸는 비용을 감수하고 ref 전달·포커스 동작을 확인했습니다. Bottom Sheet의 기반 라이브러리는 유지했습니다.
- **개발 속도:** Turbopack과 Next.js 16의 로컬 개발 속도 개선을 위해 Next.js 14→16·React 18→19로 전환했습니다. 비동기 API·캐시 변경에 대응하고 직접 진입·뒤로가기·새로고침을 확인했습니다. 별도로 TypeScript 7 네이티브 체커를 병행해 타입 검사 시간을 12.5초에서 1.9초로 줄였습니다. 타입 인지 lint는 검사 시간이 3.3배 늘어 도입을 보류했습니다.
- **브라우저 호환성:** Tailwind v4 전환 전 2026년 8월 27일~10월 1일 Amplitude로 지원 여부를 확인했습니다. 하루 평균 약 1,000명 중 `color-mix()` 미지원은 하루 1명꼴(평균 0.94명), `@property` 미지원은 없었습니다. 전환을 보류하는 것도 검토했지만 [v4.1의 색상 fallback](https://tailwindcss.com/blog/tailwindcss-v4-1#improved-compatibility-with-older-browsers)을 확인해 진행했습니다.
