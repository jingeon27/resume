# 당근 모임팀 커버레터

김진건 · Frontend Engineer · jingeon27@gmail.com

중학교 때 게임 커뮤니티에서 만난 사람들과 정모로 직접 만나기도 했고, 그중 몇몇과는 지금까지 관계를 이어오고 있습니다. 같은 관심사로 온라인에서 시작한 인연이 오래 이어진 것은 제 인생에서 특별한 경험이었습니다. 동네에서 관심사가 통하는 이웃을 잇는 모임팀에서, 더 많은 사람이 이런 만남을 경험하고 관계를 이어갈 수 있는 서비스를 만들고 싶습니다.

세이프닥에서는 병원 비급여 프로그램과 건강검진을 예약하는 복지몰과 병원 관리자·백오피스를 개발하고 있습니다. 만든 화면은 실제 사용 환경에서 직접 써 봅니다. 외부 예약 사이트로 나가는 기능을 만들 때는 앱에서 네이티브 뒤로 가기를 쓰면 WebView 전체가 닫히는 것을 배포 전에 확인해, 외부 사이트는 브릿지로 열고 이전 화면으로 돌아가는 동작은 웹 라우터로 바꿨습니다.

출시한 뒤에는 Sentry로 사용자가 겪는 오류를 모으고, 영향을 받은 사용자가 많은 것부터 고칩니다. 화면이 뜨지 않는 오류와 작업을 막는 오류를 나눠 추적했고, Amplitude 이벤트도 140개 이상 새로 붙이거나 고쳤습니다. 이용자가 많은 당근 모임에서는 이런 오류 지표와 사용자 행동 데이터로 개선의 결과를 더 빨리 확인하며 기여할 수 있을 것이라 생각합니다.

개발할 때는 기준을 먼저 정합니다. Tailwind CSS v4로 올리기 전에는 5주 동안 사용자 브라우저의 color-mix()·@property 지원 여부를 기록했고, 미지원 사용자가 하루 1명꼴로 나와 철회도 검토한 뒤 v4.1의 색상 fallback을 확인하고 올렸습니다. 타입 인지 lint는 검사 시간이 3.3배 늘어 도입을 보류했습니다.

AI에게 구현을 맡긴 뒤에는 코드와 테스트를 직접 읽고 로컬에서 화면을 띄워 동작을 확인합니다. 반복해서 고친 내용은 skills와 lint rule에 남겨 다음 구현에 반영합니다. 폼·검색·공통 UI도 상태와 책임을 나눠 정리하며, AI가 만든 코드가 쌓여도 사람이 흐름을 파악하고 검증하기 쉬운 구조를 유지하고 있습니다.

세이프닥에서는 PM님이 주도한 실험에 화면 구현과 사용자 행동 측정으로 참여했습니다. 모임팀에서는 사용자분들의 이야기를 듣고 직접 제품을 써 보며, 처음 참여할 때의 망설임과 모임을 운영하는 부담을 이해하고 싶습니다. 동료분들과 필요한 개선을 정해 구현하고, 실제 참여와 꾸준한 만남으로 이어지는지까지 확인하며 일하겠습니다.

## 프로덕트(서비스)에 대한 의견을 내고 개선한 경험

공백 포함 500자 이내

모바일로 리뷰를 직접 써 보니, 시술을 하나 고를 때마다 목록이 닫혀 여러 개를 선택하기 번거롭고 고른 항목도 잘 보이지 않았습니다. 이 불편을 PO님께 공유했고, 기획·디자인 담당자분들이 정한 복수 선택과 칩 UI를 구현했습니다.

최근 검진 예약에서는 검사 항목을 정해진 개수만큼 고르면 다음 그룹으로 자동 이동하자는 요청이 있었습니다. 기존 선택을 바꿀 때도 화면이 넘어가면 오히려 불편하겠다는 의견을 냈습니다. 담당자분과 논의해 정해진 수를 채우면 고르지 않은 항목만 비활성화하도록 바꿨고, 빠져 있던 비활성 상태 디자인도 요청해 반영했습니다. 선택 개수를 넘기지 않으면서 이미 고른 항목은 같은 화면에서 수정할 수 있게 했습니다.
