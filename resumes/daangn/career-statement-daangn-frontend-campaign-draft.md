### 건강검진 서비스 내재화 | 2026.09 – 현재

**담당:** 복지몰, 병원 관리자, 백오피스의 프론트엔드 개발과 연동 검증 전담. 제휴 병원의 요구사항을 개발팀장, 부팀장과 확인하고 백엔드와 API 및 예외 처리 조율.

아임웹에서 정보를 보고 전화로 문의하던 건강검진을 기존 서비스에 내재화했습니다. 검사 구성과 기업지원 코드, 예약금 처리 방식이 기존 비급여 예약과 달라 제품별 업무를 나눴습니다.

- 백오피스의 검사항목과 검진 구성, 기업지원 서류 확인, 결제취소와 환불 승인을 개발했습니다. 병원 관리자에는 검진 예약 관리와 결제취소 요청 접수를, 복지몰에는 검사 선택과 기업 검진 코드, 토스페이먼츠 예약금 결제를 구현했습니다.
- 모바일 결제창을 다녀오면 입력이 사라져, 입력과 `orderId`를 sessionStorage에 저장했습니다. 해당 탭의 같은 주문이며 현재 Zod 스키마를 통과한 값만 한 번 복원하도록 했습니다.
- 정해진 수를 고르면 다음 검사 그룹을 자동으로 열자는 요청에, 기존 선택을 고칠 때도 화면이 넘어가는 문제를 짚었습니다. 담당자와 논의해 미선택 chip만 비활성화하고 빠진 디자인도 요청해 반영했습니다.
- 일괄 저장이 일부만 성공하면 서버 목록을 다시 받아 발급된 ID를 폼에 반영해 재시도 때 중복 등록을 막았습니다. 삭제된 검사항목이 조회 응답에 남아 수정 요청이 거절되는 조건은 백엔드에 전달했습니다.

**결과와 검증:** 2026년 9월 9일 개발을 시작해 23일 운영 배포, 30일 정식 오픈했습니다. 결제 실패 후 입력 복원과 승인 요청 실패 뒤 예약 목록 이동을 dev API 서버 E2E로 확인했습니다.

**기술:** Next.js, React Hook Form, Zod, TanStack Query, sessionStorage, Playwright.

### 모바일 리뷰와 WebView 개선 | 2025.06 – 2026.09

**담당:** 직접 발견한 모바일 불편을 PO에게 공유하고 담당자가 정한 개선안 구현. 후속 디자인 시스템 적용과 WebView 이동 검증.

모바일에서 리뷰를 쓰며 키패드가 시술 목록을 가리고, 하나를 고를 때마다 닫혀 여러 개를 고르기 어렵고, 선택한 항목도 잘 보이지 않는 문제를 찾았습니다. 2025년 6월 Jira로 공유한 뒤 기획과 디자인 담당자의 복수 선택, 체크, chip UI를 구현해 7월 10일 배포했습니다.

8월 7일에는 디자인 시스템의 Bottom Sheet를 적용했습니다. 시트 안의 임시 선택과 폼의 값을 나누고 ‘확인’을 눌렀을 때만 반영하도록 했습니다. `tel:` 상담은 네이티브 브릿지에 연결하고, 외부 예약 이동에서는 뒤로 가기가 WebView 전체를 닫는 조건을 배포 전에 발견해 외부 링크와 웹 내부의 이동을 나눴습니다.

### 웹 플랫폼과 Next.js 오류 대응 | 2025.05 – 현재

- 인증 화면에서 돌아올 때 멈추는 오류를 Next.js 소스까지 추적했습니다. 서버 컴포넌트의 `redirect()`가 AppRouter 렌더를 중단해 훅 개수가 달라지는 경로를 찾아 진입 판정을 proxy로 옮겼습니다.
- 관리자 검색 오류는 개발 서버에서 재현되지 않아 build 후 start로 목록 7개 중 6개에서 확인했습니다. 업스트림 수정 PR로 라우터 캐시 원인을 확인하고 서버가 읽지 않는 조회 조건은 History API로 처리했습니다. 수정 뒤 2026년 9월 28일까지 같은 증상은 다시 보고되지 않았습니다.
- 병원과 시술 상세의 메타데이터와 JSON-LD를 구성했습니다. 스트리밍 메타데이터를 읽지 못하는 봇은 `htmlLimitedBots`로 처리하고 공개 조회와 인증 쿠키를 분리해 동적 sitemap을 하루 단위로 재검증합니다.

### 프론트엔드 전반의 아키텍처 개선과 리팩터링 | 2025.05 – 현재

**담당:** 복지몰과 관리자 서비스의 코드 레이어, 도메인 의존성, 조회와 상태 관리, 공통 UI와 폼, 정산 화면 개선 및 적용.

- FSD에서 재사용 여부로 코드 위치를 정하던 기준을 서버 도메인, 화면 조합, 공통 UI의 책임에 따라 정리했습니다. 복지몰의 화면 간 직접 참조 62건을 정리하고 lint error로 검사하며 관리자 서비스의 프로그램과 시술 도메인 사이 순환 의존성을 끊었습니다.
- 서버 조회 결과를 render props로 읽던 화면은 Query 캐시를 무효화해도 갱신되지 않았습니다. 2025년 5월 예약 화면부터 prefetch와 hydration으로 전환해 서버는 초기 데이터를 준비하고 클라이언트는 같은 캐시를 구독하도록 했습니다.
- 예약 화면의 서버 목록은 Query, 작성 중인 입력은 React Hook Form, 제출 조건은 Zod로 나눴습니다. 가족을 추가할 때 선택한 일시가 어긋나는 조건을 고치고 예약 대상 선택 컴포넌트를 519줄에서 55줄로 줄였습니다.
- 공통 필터의 화면별 예외가 늘어 각 화면이 필터를 조합하게 했습니다. `createSearchFilter(schema)`로 URL과 폼, API가 같은 Zod 스키마를 따르도록 해 27개 화면에 적용했습니다. 화면별 JSX 중복은 일부 감수했습니다.
- Ant Design Form의 중첩 필드명과 값을 검사하는 `createTypedForm<T>`를 만들었습니다. 재귀 조건부 타입과 `infer`로 필드 경로와 값의 타입을 계산해 공통 필드 31개와 앱별 확장에 적용했습니다.
- 인수한 정산 화면은 조회와 표, 선택, 편집, 정산 처리를 나눴습니다. ref로 열던 모달은 대상 데이터와 열림 상태를 props로 받도록 바꿨고 배포 전 운영 요구사항과 이후 오류도 반영했습니다.

**결과와 검증:** 화면별 조합과 공통 계약을 분리하고, 반복되는 설계 기준을 skills와 lint rule에 반영했습니다. 의존 방향과 공개 API, queryKey 등 정적으로 검사할 수 있는 규칙은 RuleTester와 fixture, mock으로 검증합니다.

**기술:** TypeScript, TanStack Query, React Hook Form, Zod, Ant Design, ESLint.

**담당:** Amplitude 기반 A/B 테스트 환경 구축, PO와 마케터, 개발팀장과 측정 데이터 협의, 실험 및 캠페인의 화면 구현과 이벤트 추가 및 수정.

### Sentry 도입과 운영 오류 추적 | 2026.08 – 현재

**담당:** 복지몰 Sentry 도입과 수집 정책, 오류 원인 추적과 수정. 관리자 서비스의 오류 경계와 API 및 Zod 실패 트래킹.

브라우저, 서버, Edge에 Sentry를 연결해 8월 27일 운영 배포했습니다. 의료 서비스의 민감정보가 실리지 않도록 SDK 소스에서 URL과 쿠키, 인증 헤더의 수집 경로를 확인해 제거하고 release와 브라우저 소스맵을 연결했습니다.

- Bottom Sheet 드래그 크래시를 라이브러리 내부의 null ref 접근까지 추적해 버전업으로 고쳤습니다. 달라진 snap point는 공통 Root에서 변환했습니다.
- 일부 조회 실패가 정상 화면까지 지우지 않도록 기능별 오류 경계를 나눠 백오피스 라우트 30개에 적용했습니다. 동의서 문서 조회가 실패해도 고객명과 동의 내역이 남는지 테스트했습니다.
- 관리자 서비스의 API 오류와 응답 스키마 불일치는 CloudWatch로 트래킹합니다.

**결과:** 배포 전 누적 75건, 57명 이상에게 발생한 Bottom Sheet 오류 그룹은 9월 10일 배포 뒤 28일까지 18일간 추가 발생 0건이었습니다.

### 테스트 도입과 검증 기준 | 2026.07 – 현재

**담당:** 테스트 도입과 기능별 검증 범위, 제출된 테스트의 전제와 assertion 검토, 회귀 재현.

- 새 기능의 기대 동작은 BDD 형식의 `*.spec`에 적고 운영이나 QA 오류는 `*.test`에 재현합니다. 새 패턴의 테스트는 제품 코드를 일부러 깨뜨려 실제로 실패하는지 확인합니다.
- 테스트용 QueryClient가 앱과 다른 오류 조건에서 화면을 보여 주는 것을 확인해 설정을 맞추고 첫 조회 실패와 기존 데이터의 재조회 실패를 나눴습니다.
- diff에서 놓친 Bottom Sheet 헤더 스크롤은 수정 뒤 브라우저 레이아웃 회귀 테스트로 남겼습니다.
- API 연동은 dev API 서버를 우선하고 어려운 조건은 MSW로 재현합니다. 글로벌 사용자 서비스와 CMS의 E2E는 로컬에서 빌드한 백엔드를 연결했습니다.

### Game Mate
