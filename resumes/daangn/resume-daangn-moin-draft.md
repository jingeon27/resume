## 소개

사용자 경험과 제품의 맥락을 살피며, 기능이 늘어나도 읽고 검증하기 쉬운 코드를 만드는 프론트엔드 엔지니어입니다. React·TypeScript·Next.js로 ATS 기반 채용솔루션과 의료복지 플랫폼을 개발했습니다.

개발할 때는 기준을 먼저 세웁니다. 요구사항에서 빠진 동작은 담당자와 논의하고, 새로운 기술은 이점과 전환·유지 비용을 살펴 선택합니다. 코드를 읽으며 상태·데이터 흐름과 변경 영향을 확인하는 것도 검증의 일부로 봅니다.

AI 개발 workflow를 개선하며 반복되는 검토 기준은 skills와 lint rule에 남깁니다. 에이전트가 제출한 코드와 테스트에서 요구사항 누락과 잠재적인 오류를 검토한 뒤, 화면을 띄워 동작을 확인합니다. 출시 뒤에는 Sentry로 수집된 오류와 VOC로 접수된 오류를 추적하고 대응합니다.

## 지원동기

중학교 때 게임 커뮤니티에서 가까운 지역에 살던 사람들을 알게 됐고, 정모에서 직접 만났습니다. 그중 몇몇과는 지금도 연락하며 지냅니다. 같은 관심사를 가진 이웃과 만나 오래 관계를 이어 온 경험은 제게 특별했습니다. 당근모임에서 더 많은 이웃이 이런 만남을 시작하고 관계를 이어 갈 수 있도록 제품을 발전시키고 싶습니다.

직접 모임에 참여하고 사용자 의견을 반영하는 팀의 방식에 끌렸습니다. 리뷰·예약 흐름의 불편을 개선한 경험으로 기여하고, 많은 사용자가 이용하는 환경에서 제가 만든 변화가 모임 참여와 이후 활동에 미치는 영향을 지표로 확인하고 싶습니다.

동료들과 AI 개발 workflow를 발전시키고, SSR 서버의 성능과 안정성까지 다루며 사용자 경험을 개선하고 싶습니다. 제품을 성장시키는 과정에서 엔지니어로서도 경험을 넓힐 수 있는 팀이라 생각해 지원했습니다.

#### 복지몰·관리자 서비스의 CSR·SSR 범위와 데이터 조회 설계 | 2025.05 – 현재

입사 당시에는 서버 컴포넌트의 `ensureQuery` 결과를 render props로 전달했습니다. 화면이 Query 캐시를 구독하지 않아 무효화해도 갱신되지 않았고, 조회 조건을 바꿀 때도 `router.push`·`router.replace`로 서버의 렌더링 결과를 다시 받아야 했습니다.

2025년 5월 예약 화면부터 prefetch·hydration으로 바꾸고 다른 화면으로 확대했습니다. 초기 HTML에 필요한 데이터는 서버에서 준비하고, 화면은 `useQuery`·`useSuspenseQuery`로 같은 캐시를 구독합니다. 이후 조회·갱신·무효화는 클라이언트에서 처리하도록 역할을 나눴습니다.

SEO는 다른 서비스와 비교해 메타데이터와 JSON-LD를 설계했습니다. 정해진 값이 없을 때 직접 채워도 되는지 확인한 뒤, 병원·시술 정보와 인근 지하철역 등 검색에 필요한 정보를 넣었습니다. Streaming 도입에 맞춰 `htmlLimitedBots`도 설정해 일부 미리보기 봇에는 메타데이터를 `<head>`로 보내고 일반 사용자의 화면은 스트리밍을 유지했습니다.

- 로컬 개발 속도를 높이기 위해 Next.js 14→16·React 18→19로 전환했습니다. Turbopack 도입과 Next.js 16 자체의 개발 속도 개선을 함께 고려했습니다. 전환 과정에서는 비동기 API와 달라진 캐시 동작에 맞춰 기존 코드를 수정하고, 링크 직접 진입·뒤로가기·새로고침을 확인했습니다.

기존 Sentry 수집 흐름에는 서버 오류·인증 실패·기타 API 오류의 레벨을 나눴습니다.
