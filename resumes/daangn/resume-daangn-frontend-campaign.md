#### React 상태와 Next.js 오류 대응 | 2025.05 – 현재

서버에서 조회한 결과를 render props로 받던 화면은 Query 캐시를 구독하지 않아 무효화해도 내용이 바뀌지 않았습니다. 2025년 5월 예약 화면부터 prefetch와 hydration으로 바꿔, 서버가 초기 데이터를 준비하고 클라이언트는 같은 캐시를 구독하도록 전환했습니다.

- 인증 화면에서 돌아갈 때 앱이 멈춰 조사 당시 53명에게 68건의 오류가 발생했습니다. Next.js 소스를 확인해 서버 컴포넌트의 `redirect()`가 AppRouter 렌더를 중단하면서 훅 개수가 달라지는 경로를 찾았습니다. 진입 판정과 리다이렉트를 React 렌더 전의 proxy로 옮겼습니다.
- 관리자 검색 오류는 개발 서버에서 재현되지 않아 build 후 start로 목록 7개 중 6개에서 확인했습니다. 업스트림 이슈와 수정 PR로 라우터 캐시 원인을 확인하고, 서버가 읽지 않는 조회 조건은 History API로 처리했습니다. 수정 뒤 9월 28일까지 같은 증상은 다시 보고되지 않았습니다.
- 예약 화면의 가족과 날짜 값이 Query 캐시, Zustand, 로컬 상태에 흩어져 선택한 일시가 어긋났습니다. 서버 목록은 Query, 입력값은 React Hook Form, 제출 조건은 Zod로 나눴고 예약 대상 선택 컴포넌트는 519줄에서 55줄로 줄었습니다.
- Cache Components 적용 뒤에는 뒤로 가기로 돌아온 폼에 이전 입력이 남았습니다. `<Activity>`가 화면을 제거하지 않고 숨기는 동작을 확인하고, 공용 폼 훅의 layout effect cleanup에서 마운트 시점의 기본값으로 되돌리게 했습니다.
