## 지원동기

많은 사용자가 쓰는 제품을 여러 팀이 함께 만드는 환경에서 일하고 싶습니다. 지금은 프론트엔드 설계와 코드 검토를 주로 혼자 하고 있습니다. 당근에서는 같은 직군의 동료들과 설계를 검토하고, PM과 디자이너, 데이터 분석가와 각자의 전문성을 더해 제품을 만들고 싶습니다.

사용자 웹과 관리자 서비스를 함께 개발하고 운영한 경험을 살리겠습니다. 요구사항에서 빠진 동작을 찾고, 출시 후 오류를 추적하며, 반복 작업은 테스트와 AI 개발 workflow로 줄여 왔습니다. 당근에서는 사용자 지표로 가설을 확인하는 경험도 쌓고, 동료들과 제품을 키우며 저도 엔지니어로서 성장하고 싶습니다.

티켓과 plan 검토 → 테스트 작성 → 에이전트 구현과 에이전트 코드 리뷰 → 변경분 테스트, lint, typecheck → 직접 diff 리뷰와 화면 동작 확인 → 전체 CI(테스트, knip, lint) → QA 더블 체크 요청

- 테스트와 앱의 오류 처리 설정이 달라 실제로 보이지 않는 오류 화면을 검증하고 있었습니다. 테스트용 QueryClient를 앱과 맞추고, 데이터가 없는 조회 실패와 재조회 실패를 나눠 확인했습니다.

입사 당시에는 서버 컴포넌트에서 `ensureQuery`로 받은 결과를 render props로 넘겨, 화면이 Query 캐시를 구독하지 않아 무효화해도 갱신되지 않았습니다. 2025년 5월 예약 화면부터 화면별로 prefetch와 hydration으로 옮겨, 서버는 초기 HTML에 필요한 데이터를 준비하고 화면은 같은 캐시로 이후 조회와 갱신을 처리하게 했습니다.

- 인증을 마친 사용자가 로그인이나 본인인증 화면에서 돌아갈 때 앱이 멈추는 오류가 조사 당시 53명에게 68건 발생했습니다. Next.js 소스를 따라가 보니 서버 컴포넌트가 던진 `redirect()`가 하드 내비게이션으로 처리되며 AppRouter가 렌더를 중간에 끊어 렌더마다 훅 개수가 달라졌습니다. 진입 판정과 리다이렉트는 React 렌더 전에 도는 proxy로 옮겼습니다.
- 관리자 목록의 검색 오류는 개발 서버에서 재현되지 않아 build 후 start로 띄워 목록 7개 중 6개에서 확인했습니다. 업스트림 이슈와 수정 PR로 라우터 캐시 문제임을 확인하고, 서버가 읽지 않는 조건은 History API로 처리했습니다. 수정 뒤 9월 28일까지 같은 증상은 다시 보고되지 않았습니다.
- 예약 화면은 가족과 날짜 값이 Query 캐시, Zustand, 로컬 상태에 흩어져 가족을 추가하면 선택한 일시가 어긋났습니다. 서버 목록은 Query, 작성 중인 값은 React Hook Form, 제출 조건은 Zod가 맡도록 나눠 고쳤고, 519줄이던 예약 대상 선택 컴포넌트는 55줄이 됐습니다.

- 사용자 경험, 공개 범위와 권한, 업로드 제한, 검증할 가설을 제품 문서에 먼저 정했습니다. 10월 13일 사진 대회 MVP로 시작했지만, 직접 써 보니 대회가 열릴 때만 들어오는 서비스보다 평소에도 사진을 모으는 편이 낫다고 판단해 19일 상시 그룹 커뮤니티로 방향을 바꿨습니다. 기존 대회와 사진 데이터, 이전 링크는 보존했습니다.
- 가입 → 첫 게시물 → 좋아요 → 재방문 흐름을 보려고 Amplitude를 붙였습니다. 실제 수집 결과를 다시 조회해, 개발 모드에서 페이지뷰가 두 번 집계되고 URL에 검색어가 남는 문제를 찾아 고쳤습니다.
- 별사대는 schema-first GraphQL과 Apollo Client로 만들었습니다. NestJS와 Prisma, PostgreSQL 위에 도메인별 스키마와 resolver를 두고, 웹은 도메인별 문서에서 GraphQL Code Generator로 타입이 붙은 Document를 생성합니다. 서버 스키마로 앱의 모든 문서를 검증하는 계약 테스트를 둬 스키마와 맞지 않는 문서는 웹 테스트에서 실패합니다. API는 쿼리 깊이와 필드, alias 수를 검증 규칙으로 제한합니다.
- 모든 객체에 id를 받아 Apollo 정규화 캐시로 갱신합니다. 자식 컴포넌트에는 id만 넘겨 useFragment로 읽고, 사진 목록은 offsetLimitPagination으로 이어 받으며, 좋아요와 투표는 optimisticResponse로 먼저 반영합니다. 도메인별 캐시 정책은 두 도메인이 같은 필드를 정의하면 바로 실패하도록 합치고 실제 InMemoryCache로 테스트합니다.
- Next.js App Router에서는 RSC가 PreloadQuery로 미리 받은 결과를 브라우저 캐시로 넘기고, 화면은 useBackgroundQuery와 useReadQuery로 같은 조회를 구독합니다. 개인화된 조회는 캐시하지 않고 익명으로 볼 수 있는 공개 콘텐츠와 사이트맵만 서버 캐시에 둡니다. mutation은 Next 프록시를 거치게 해, 앞선 필드가 커밋된 뒤 다음 필드가 실패해 data가 null로 오는 부분 성공까지 판단해 공개 캐시를 만료합니다.
- Game Mate는 REST와 TanStack Query로 만들었고, 댓글 알림을 누르면 해당 글이나 댓글로 이동하며 읽음 뒤 알림 개수를 함께 갱신합니다. 두 서비스와 PostgreSQL은 EC2 한 대에서 Caddy 뒤에 실행하도록 구성하고, CI에서 검증한 이미지를 digest로 고정해 배포하며 readiness 확인에 실패하면 이전 이미지로 되돌립니다. AWS 리소스는 Terraform으로 구성하고 mock provider로 테스트합니다.
