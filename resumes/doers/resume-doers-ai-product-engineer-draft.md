### AI 개발 workflow와 검증 기준

2026년 4월부터 코딩 에이전트를 활용하고 7월부터 테스트를 도입했습니다. 현재 실무에서는 아래 순서로 작업하며, 에이전트가 완성본을 제출하면 제품 코드와 테스트를 읽고 부족한 부분을 반려해 다시 확인합니다.

티켓과 plan 검토 → 테스트 작성 → 에이전트 구현과 에이전트 코드 리뷰 → 변경분 테스트, lint, typecheck → 직접 diff 리뷰와 화면 동작 확인 → 전체 CI(테스트, knip, lint) → QA 더블 체크 요청

- 새 기능의 기대 동작은 BDD 형식의 `*.spec`에 적고, 운영이나 QA에서 발견한 오류는 `*.test`에 재현합니다. 새 패턴의 테스트는 제품 코드를 일부러 깨뜨려 실제로 실패하는지 확인합니다.
- 테스트용 QueryClient가 앱과 다른 오류 조건에서 화면을 보여 주는 것을 확인해 설정을 맞췄습니다. 첫 조회 실패와 기존 데이터의 재조회 실패를 나눠 검증했습니다. diff에서 놓친 Bottom Sheet의 헤더 스크롤은 고친 뒤 브라우저 레이아웃 회귀 테스트로 남겼습니다.
- 반복해서 의도와 어긋난 구현의 기준은 skills에 남기고, 정적으로 검사할 수 있는 import 방향과 공개 API, queryKey는 lint rule로 검사합니다. 규칙 자체는 RuleTester와 fixture, mock으로 검증합니다.
- 개발 중 검증을 빨리 돌리려고 TypeScript 7 네이티브 체커를 함께 사용해 **복지몰 타입 검사 시간을 12.5초 → 1.9초**로 줄였습니다.

### 사용자 흐름과 인터랙션 개선

- **결제 후 입력 복원:** 모바일 결제창을 다녀오면 입력이 사라져, 한 번의 결제 왕복에 필요한 값을 `orderId`와 함께 sessionStorage에 저장했습니다. 같은 주문이며 현재 Zod 스키마를 통과한 값만 한 번 복원합니다. 결제 실패 후 입력 복원과 승인 요청 실패 뒤 예약 목록 이동은 dev API 서버 E2E로 확인했습니다.
- **모바일 리뷰 작성:** 직접 사용하며 키패드가 목록을 가리고 여러 시술을 고르기 어려운 문제를 찾아 PO에게 공유했습니다. 기획과 디자인 담당자가 정한 복수 선택, 체크, chip UI를 구현하고 후속 디자인 시스템의 Bottom Sheet도 적용했습니다. 시트 안의 임시 선택은 ‘확인’을 누를 때 폼에 반영하도록 나눴습니다.
- **WebView 이동:** 전화상담의 `tel:` 링크는 네이티브 브릿지에 연결했습니다. 외부 예약 사이트 이동을 구현하며 뒤로 가기가 WebView 전체를 닫는 동작을 배포 전에 발견해, 외부 링크와 웹 내부의 이동 처리를 나눴습니다.
- **요구된 동작의 재검토:** 검사를 정해진 수만큼 고르면 다음 그룹을 자동으로 열자는 요청에, 기존 선택을 고칠 때도 화면이 넘어가는 점을 짚었습니다. 담당자와 논의해 선택 수를 채운 그룹의 미선택 chip만 비활성화하고 빠진 디자인도 요청해 반영했습니다.
- **일괄 저장의 부분 실패:** 검사항목이 일부만 저장되면 서버 목록을 다시 받아 발급된 ID를 폼에 반영했습니다. 재시도할 때 이미 만든 항목을 중복 등록하지 않도록 했습니다.

### 프론트엔드 아키텍처와 리팩터링

- **FSD와 도메인 의존성:** 재사용 여부로 코드 위치를 정하던 기준을 서버 도메인, 화면 조합, 공통 UI의 책임에 따라 정리했습니다. 복지몰의 화면 간 직접 참조 62건을 정리하고 lint error로 검사하며, 관리자 서비스에서는 프로그램과 시술 도메인의 순환 의존성을 끊었습니다.
- **서버와 클라이언트의 조회 경계:** 서버 조회 결과를 render props로만 읽는 화면은 Query 캐시를 무효화해도 바뀌지 않았습니다. 2025년 5월 예약 화면부터 prefetch와 hydration으로 전환해, 서버는 초기 데이터를 준비하고 클라이언트는 같은 캐시를 구독하도록 했습니다.
- **폼 상태의 책임 분리:** 예약 화면의 값이 Query, Zustand, 로컬 상태에 흩어져 선택한 일시가 어긋났습니다. 서버 목록은 Query, 입력은 React Hook Form, 제출 조건은 Zod로 나눠 예약 대상 선택 컴포넌트를 **519줄 → 55줄**로 줄였습니다.
- **화면별 조합과 공통 계약:** 공통 필터에 화면별 예외가 늘어, 각 화면이 필요한 필터를 조합하고 URL과 폼, API 요청은 같은 Zod 스키마를 따르도록 설계해 27개 화면에 적용했습니다. 화면별 JSX 중복은 일부 감수했습니다.
- **TypeScript로 필드 계약 검사:** Ant Design Form의 중첩 필드명과 값을 확인하는 `createTypedForm<T>`를 만들었습니다. 재귀 조건부 타입과 `infer`로 경로와 값의 타입을 계산해 공통 필드 31개와 앱별 확장에 적용했습니다.
- **정산 화면 리팩터링:** 인수한 정산 화면의 조회와 표, 선택, 편집, 정산 처리를 나눴습니다. ref로 열던 모달은 대상 데이터와 열림 상태를 props로 받도록 바꿨습니다.

### 원인 추적과 운영 오류 대응

- **Sentry 도입과 수집 정책:** 복지몰의 브라우저, 서버, Edge에 Sentry를 연결했습니다. 의료 서비스의 민감정보가 실리지 않도록 SDK 소스에서 URL과 쿠키, 인증 헤더의 수집 경로를 확인해 제거하고 release와 브라우저 소스맵을 연결했습니다.
- **라이브러리 내부 크래시:** Bottom Sheet의 null ref 접근을 라이브러리 소스까지 추적해 버전업으로 고쳤습니다. 달라진 snap point는 공통 Root에서 변환했습니다. 배포 전 누적 75건, 57명 이상에게 발생한 오류 그룹은 2026년 9월 10일 배포 뒤 28일까지 18일간 추가 발생 0건이었습니다.
- **배포 빌드에서만 나타난 오류:** 관리자 검색 오류를 build 후 start로 목록 7개 중 6개에서 재현하고, 업스트림 수정 PR로 라우터 캐시 원인을 확인했습니다. 서버가 읽지 않는 조회 조건은 History API로 처리했습니다.
- **실패 구획 분리:** 일부 조회 실패가 정상 화면까지 지우지 않도록 오류 경계를 나눠 백오피스 라우트 30개에 적용했습니다. 동의서 문서 조회가 실패해도 고객명과 동의 내역이 남는지 테스트했습니다.
