## AI로 만든 개인 프로젝트 | 2026.10 – 현재

사진 커뮤니티 별사대와 글로벌 게임 커뮤니티 Game Mate를 Yarn workspace 모노레포에서 개발합니다. Game Mate는 친추 판매와 게임 코칭을 원하는 사람을 연결하려고 시작했습니다. 가격과 조건을 표시한 모집 글에서 1:1 채팅으로 문의하도록 만들었습니다. 두 서비스 모두 공개 전이며 초기 사용자 검증을 준비하고 있습니다.

### 제품 방향과 구현 범위

별사대는 친구끼리 사진을 올리고 투표하는 대회로 시작했습니다. 직접 써 보니 대회가 없을 때도 사진을 모을 공간이 필요하다고 판단해 상시 그룹으로 바꿨습니다. 홈에는 가입한 그룹의 새 게시물을 모으고 공개 탐색을 추가했습니다. 기존 사진과 이전 링크는 보존했습니다.

Game Mate는 친추 판매와 코칭 모집 글에서 가격과 조건을 확인한 뒤 채팅으로 문의하는 흐름을 만들었습니다. 코치와 수강생 모두 모집할 수 있게 하고 수강료 단위를 나눴습니다. 결제와 정산은 구현하지 않았습니다. 화면을 직접 쓰며 가입 정보 입력은 별도 페이지로 나누고, 프로필 수정은 Bottom Sheet로 모았습니다.

### 저장과 전송의 실패 동작

- Game Mate의 글 저장 뒤 캐시 만료 호출만 실패해도 사용자에게 저장 실패로 응답하면 같은 글을 다시 쓸 수 있습니다. 변경 내용과 만료 태그를 DB에 함께 저장하고 캐시 만료만 재시도합니다. 늦게 끝난 호출이 새 기록을 지우지 않도록 revision을 확인하며 롤백과 재시작, 경합을 통합 테스트로 검증합니다.
- 파일 전체를 API가 받던 방식은 서버 메모리와 전송 부담이 있어 S3 직접 업로드로 바꿨습니다. Game Mate는 HEAD와 앞 4KB를 검사하고 ETag가 같을 때만 최종 객체로 복사합니다. 별사대는 원본을 보관하고 HEAD로 크기와 형식만 확인합니다.
- 별사대는 GraphQL과 Apollo Client, Game Mate는 REST와 TanStack Query를 사용합니다. 공개 데이터만 서버 캐시에 두고 사용자별 조회를 분리합니다. GraphQL 문서는 서버 스키마와 대조하고 API 통합 테스트는 격리된 PostgreSQL에서 실행합니다.

### 초기 비용과 검증 범위

두 서비스와 PostgreSQL을 EC2 한 대에서 실행하도록 구성했습니다. 초기 비용을 줄이는 대신 서버와 DB가 함께 중단될 수 있고 백업과 복구를 직접 관리해야 합니다. DB 데이터는 별도 EBS에 두고 일일 스냅샷과 배포 전 S3 덤프를 준비했습니다. Terraform은 mock provider로 테스트하며 실제 AWS 적용과 운영 부하 검증은 별도입니다.

Sentry와 Amplitude에는 확인용 이벤트를 보낸 뒤 MCP로 다시 조회했습니다. 이 과정에서 개발 모드의 중복 페이지뷰와 URL에 남는 검색어를 찾아 고쳤습니다. Web Vitals는 브라우저 전송과 실제 수신을 구분해 확인했습니다.
