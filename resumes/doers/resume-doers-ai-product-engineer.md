## AI로 만든 개인 프로젝트 | 2026.10 – 현재

사진 커뮤니티 별사대와 글로벌 게임 커뮤니티 Game Mate를 Yarn workspace 모노레포에서 개발합니다. 두 서비스 모두 공개 전이며 초기 사용자 검증을 준비하고 있습니다.

### 제품과 화면 결정

- 사진 대회가 열릴 때만 쓰던 서비스를 상시 그룹 커뮤니티로 바꿨습니다. 홈에는 가입한 그룹의 새 게시물을 보여 주고, 공개 그룹 탐색과 그룹 안의 대회를 추가했습니다. 기존 사진과 이전 링크는 보존했습니다.
- 화면을 직접 쓰며 사진을 가리던 순위와 실제 기능이 없는 스토리 테두리를 뺐습니다. Game Mate의 프로필 수정은 Bottom Sheet로 모으고, 닉네임과 자기소개를 바꾸는 DB 필드와 API 계약도 함께 수정했습니다.

### 대표 구현과 검증

- 사진 서비스는 GraphQL과 Apollo Client, Game Mate는 REST와 TanStack Query를 사용합니다. 각 서비스에서 공개 데이터만 서버 캐시에 저장하고 사용자별 데이터는 별도로 조회합니다.
- Game Mate는 게시글 변경과 캐시 만료 태그를 DB에 함께 저장합니다. Next.js의 캐시 만료 호출이 실패하면 재시도하고, 이전 호출이 늦게 끝나 새 기록을 지우지 않도록 revision을 확인합니다.
- 파일은 브라우저에서 S3로 직접 올립니다. Game Mate는 HEAD와 파일 앞 4KB를 검사하고 ETag가 같은 경우에만 최종 객체로 복사합니다. 사진 서비스는 원본을 보관하고 HEAD로 크기와 형식만 확인합니다.
- API는 Supertest와 격리된 PostgreSQL, 브라우저 흐름은 Playwright로 검증합니다. Sentry와 Amplitude는 확인용 이벤트를 보낸 뒤 MCP로 다시 조회했고, Web Vitals 전송도 브라우저 테스트로 확인했습니다.
- 초기 비용을 줄이려고 두 서비스와 PostgreSQL을 EC2 한 대에서 실행하도록 구성했습니다. DB 데이터는 별도 EBS에 두고 일일 스냅샷과 배포 전 S3 덤프를 준비했습니다. Terraform은 mock provider로 테스트하며 실제 AWS 적용과 운영 부하 검증은 별도입니다.

- 요구사항과 Figma를 먼저 보고 빠진 동작은 담당자와 논의합니다. 에이전트 리뷰의 critical 항목은 자동으로 고치게 하되 수정 결과를 확인합니다. 완성된 코드와 테스트를 읽으며 요구사항이 빠지거나 컨벤션이 어긋난 부분을 찾고, 화면도 직접 사용해 봅니다.

- 테스트용 QueryClient가 앱과 다르게 오류를 처리하던 문제를 고쳤습니다. 설정을 앱과 맞추고, 처음 데이터를 받지 못한 경우와 기존 데이터를 재조회하다 실패한 경우를 나눠 확인했습니다.

#### 구조 개선과 운영 대응 | 2025.05 – 현재

- 서버 조회 결과를 props로 받던 화면은 Query 캐시를 무효화해도 갱신되지 않았습니다. prefetch와 hydration으로 바꿔 서버가 준비한 데이터를 클라이언트도 같은 캐시에서 읽고 갱신하게 했습니다.
- 화면마다 다른 요구사항이 공통 검색 필터의 예외 분기로 쌓여, JSX 중복을 일부 감수하고 각 화면이 필요한 필터를 조합하도록 바꿨습니다. 27개 화면에 적용했습니다. 중첩 필드명과 값은 재귀 조건부 타입을 쓴 `createTypedForm<T>`로 검사합니다.
- 브라우저, 서버, Edge에 Sentry를 도입했습니다. Bottom Sheet 크래시는 라이브러리 소스까지 추적해 고쳤습니다. 누적 75건, 57명 이상에게 발생한 오류 그룹은 9월 10일 배포 뒤 28일까지 18일간 0건이었습니다.
- 동의서의 외부 문서 조회 실패가 화면 전체로 번지지 않도록 오류 경계를 나눴습니다. 문서를 받지 못해도 고객명과 동의 내역이 남는지 테스트했습니다.
- Amplitude 기반 A/B 테스트 환경을 구축하고 담당자 주도 실험의 화면과 사용자 행동 측정을 맡았습니다. UTM 누락은 Amplitude 설정으로 해결해 추가한 코드를 배포 전에 되돌렸습니다.
