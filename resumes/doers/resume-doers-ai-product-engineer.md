#### AI 개발 workflow | 2026.04 – 현재

에이전트 구현에서 파일 배치와 공통 코드 사용법이 반복해서 어긋나 FSD 기준과 skills를 정리했습니다. import 방향과 공개 API는 lint rule로 검사하고, 7월부터 테스트를 도입했습니다. 에이전트가 완성본을 제출하면 검토하고 부족한 부분은 수정을 요청해 다시 확인합니다.

티켓과 plan 검토 → 테스트 작성 → 에이전트 구현과 에이전트 코드 리뷰 → 변경분 테스트, lint, typecheck → 직접 diff 리뷰와 화면 동작 확인 → 전체 CI(테스트, knip, lint) → QA 더블 체크 요청

- 테스트용 QueryClient가 실제 앱과 다르게 오류를 처리해, 실제로는 오류 경계에 가려질 UI를 검증하고 있었습니다. 설정을 맞추고 첫 조회 실패와 기존 데이터의 재조회 실패를 나눠 확인했습니다.
- Bottom Sheet 변경에서 헤더까지 스크롤되는 것을 diff에서 놓쳤습니다. 본문만 스크롤되게 고치고 브라우저 레이아웃 회귀 테스트와 화면 확인을 보완했습니다.
- 새 기능은 BDD 형식의 `*.spec`에 컴포넌트별 기대 동작을 적고 누락을 검토합니다. 운영이나 QA 오류는 `*.test`에 재현하며, 새 테스트 패턴은 제품 코드를 일부러 깨뜨려 실패하는지 확인합니다. 에이전트 리뷰의 critical 항목은 자동 수정하게 하되 결과를 다시 확인합니다.

기능 개발과 리팩터링에서는 변경된 제품 코드와 테스트를 읽습니다. 맥락이 필요한 기준은 skills에, 자동 검사할 수 있는 기준은 lint rule에 남깁니다. 자체 규칙은 RuleTester와 fixture로 검증하고 미사용 코드는 Knip으로 찾습니다.
