## AI로 만든 개인 프로젝트 | 2026.10 – 현재

Yarn workspace 모노레포에서 사진 커뮤니티와 게임 커뮤니티를 개발합니다. 제가 제품 방향과 기술을 정하고 에이전트가 코드와 테스트를 작성합니다. 완성된 코드는 직접 읽고 화면도 확인합니다. 두 제품 모두 초기 사용자 검증을 준비하고 있습니다.

### 기능과 디자인 결정

- 사진 대회가 열릴 때만 쓰는 서비스에서 평소에도 사진을 모으는 그룹 커뮤니티로 바꿨습니다. 홈에는 가입한 그룹들의 새 게시물을 보여 주고 그룹 목록은 MY로 옮겼습니다. 공개 그룹 탐색을 추가하고 대회는 그룹 안에서 필요할 때 열 수 있게 했습니다.
- 참고 서비스의 디자인을 따라 만든 화면에 실제로 없는 스토리 기능의 테두리가 붙고, 순위가 사진을 가렸습니다. 테두리는 빼고 순위는 사진 밖으로 옮기도록 요청했습니다. 수정과 삭제 같은 게시물 작업은 메뉴로 모았습니다.
- 게임 커뮤니티의 설정 메뉴는 프로필로 합치고 실제 동작과 무관한 LIVE 표시는 뺐습니다. 모바일 로그인과 가입 정보 입력은 별도 페이지로 바꿨습니다. 신고와 사용자 차단, 관리자 문의도 추가했습니다.

### 캐시와 파일 업로드

- 사진 서비스는 GraphQL과 Apollo, 게임 서비스는 REST와 TanStack Query를 사용합니다. API와 브라우저 캐시는 서비스별로 유지합니다. 공개 데이터는 SSR 캐시를 공유하고 사용자별 데이터는 따로 조회합니다.
- 게임 게시글을 수정하면 NestJS에서 Next.js Route Handler를 호출해 공개 캐시를 만료하도록 했습니다. DB에 변경 내용과 만료할 태그를 함께 저장해 호출 실패 시 재시도합니다. 이전 요청이 늦게 끝나 새 기록을 지우지 않도록 revision이 일치할 때만 대기 기록을 삭제합니다.
- 파일은 브라우저에서 S3로 바로 올리도록 바꿨습니다. 게임 서비스는 업로드 후 HEAD와 파일 앞 4KB를 검사하고 ETag가 일치할 때 최종 객체로 복사합니다. 전체 파일을 API 서버 메모리에 올리지 않는 방식입니다. 서버에 남은 multipart 처리와 프로필 변환은 프로세스당 동시 3개, 대기 12개로 제한했습니다.

### 테스트와 배포 구성

- Vitest로 도메인 규칙을, Supertest와 격리된 PostgreSQL로 API 응답과 DB 결과를 테스트합니다. 브라우저 흐름은 Playwright로 확인합니다. 테스트 설정은 각 앱에서 관리하고 루트에서는 실행만 위임합니다.
- 공용 ESLint 패키지에서 FSD 경계와 공개 API, 컴포넌트의 직접 fetch, 중복된 오버레이 상태를 검사합니다. 규칙은 TypeScript로 작성하고 RuleTester와 fixture로 테스트합니다. DOM 관련 규칙은 Next.js와 Vite에만 적용하고 Expo에서는 제외했습니다.
- 배포 비용을 줄일 방법과 CD 설정 순서를 AI에게 물어보고 EC2 한 대에 두 서비스를 올리기로 했습니다. DB와 파일은 외부 RDS와 서비스별 S3에 둡니다. Terraform으로 네트워크와 리소스, 권한을 구성하고 mock provider 테스트를 붙였습니다. 실제 AWS 계정에 적용하거나 운영 부하를 검증한 단계는 아닙니다.
