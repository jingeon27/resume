## 소개

사용자가 쿠폰을 골라 예약하고 결제하기까지의 흐름과, 그 흐름을 처리하는 병원 관리자와 백오피스를 함께 만들어 온 프론트엔드 엔지니어입니다. 가입 회원 약 15만 명, 주간 활성 사용자 약 1만 명의 복지몰과 관리자 서비스를 개발합니다. 2026년 1월부터 사내 유일한 프론트엔드 개발자로, 4월부터는 전사 프론트엔드를 단독으로 담당하고 있습니다.

직접 써 보며 찾은 불편과 요구사항에서 빠진 동작을 담당자에게 제안하고 구현합니다. 반복되는 판단은 skills와 자체 lint rule로 옮겨 개발 속도를 유지하고, Claude Code, Codex가 제출한 코드와 테스트는 직접 읽은 뒤 화면을 띄워 동작을 확인합니다.

## 주요 경험

- **문제 발견과 제안:** 모바일로 리뷰를 써 보며 찾은 선택 불편을 PO에게 공유하고, 담당자가 정한 복수 선택 UI를 구현했습니다. 잘못 안내된 쿠폰함 URL은 Load Balancer 리다이렉트로 풀자고 제안해 합의했습니다.
- **쿠폰과 결제:** 쿠폰함과 쿠폰팩을 만들고, 예약 화면에서는 혜택이 가장 큰 쿠폰을 미리 골라 두게 했습니다. 병원 관리자 결제내역에 쿠폰 결제를 더하면서 흩어진 판단은 도메인 함수와 ts-pattern 분기로 모았습니다.
- **결제 복원:** 토스페이먼츠 결제창이 모바일에서 리다이렉트로만 돌아와 입력이 사라지는 문제는, 결제 시도의 `orderId`와 Zod 검증으로 복원 범위를 좁혀 풀고 중복 신청도 막았습니다.
- **운영 오류:** Sentry를 도입하고, 57명 이상에게 75건 발생한 Bottom Sheet 크래시를 라이브러리 소스까지 추적해 고쳤습니다. 배포 뒤 18일간 0건이었습니다.
- **React, Next.js:** 인증 뒤 리다이렉트에서 앱이 멈추는 오류는 라우터 소스를 따라가 훅 개수가 어긋나는 경로를 찾았고, 판정을 렌더 전 proxy로 옮겼습니다.
- **팀 생산성:** 문서에만 있던 타입 접두사 규칙과 어긋난 선언 400건을 한 번에 정리하고 lint rule로 막았습니다. 테스트를 도입했고, 타입 검사 시간을 12.5초에서 1.9초로 줄였습니다.

#### 쿠폰과 결제, 운영 기능 | 2025.06 – 현재

복지몰의 쿠폰함과 쿠폰팩, 예약 화면의 쿠폰 적용을 개발했습니다. 예약 신청 화면에 들어오면 혜택이 가장 큰 쿠폰을 미리 골라 둡니다.

#### React, Next.js 데이터 조회와 오류 대응 | 2025.05 – 현재

입사 당시에는 서버 컴포넌트의 `ensureQuery` 결과를 render props로 넘겨, 화면이 Query 캐시를 구독하지 않으니 무효화해도 갱신되지 않았습니다. 2025년 5월 예약 화면부터 prefetch와 hydration으로 옮겨, 서버가 준비한 데이터를 클라이언트가 같은 캐시로 이어서 조회하고 갱신하게 했습니다.

인증 뒤 리다이렉트에서 앱이 멈추는 오류는 조사 당시 53명에게 68건 발생했습니다. 클라이언트 이동 중 서버 컴포넌트가 던진 `redirect()`가 하드 내비게이션으로 처리되면서, Next.js의 AppRouter가 훅 호출 도중 렌더를 끊어 렌더마다 훅 개수가 달라졌습니다. 이 경로를 소스에서 확인한 뒤 판정을 React 렌더 전 proxy로 옮겼습니다. 프로덕션에서만 멈추던 관리자 검색은 build 후 start로 재현해 라우터 캐시 키 문제로 좁혔고, 같은 경로에서 클라이언트만 읽는 조건은 History API로 처리했습니다.

화면마다 예외가 쌓이던 검색 필터는 각 화면이 조합하도록 바꿔 27개 화면을 옮겼고, Ant Design Form에는 중첩 필드명과 값을 재귀 조건부 타입으로 검사하는 `createTypedForm<T>`를 만들었습니다. 예약 화면의 가족과 날짜는 서버 목록을 Query, 작성 중인 값을 React Hook Form, 제출 조건을 Zod로 나눠 다뤘습니다.

- 채용 사이트 로그인 → 수집 → 중복 확인 → 업로드를 공통 단계와 사이트별 adapter로 나누는 Electron 초기 구조를 설계하고, 잡플래닛과 게임잡을 연동했습니다. NestJS 도입은 무겁다는 CTO 피드백으로 닷새 만에 걷어냈습니다.
