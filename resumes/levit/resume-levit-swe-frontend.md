## 소개

사용자가 쿠폰을 골라 예약하고 결제하기까지의 흐름과, 그 흐름을 처리하는 병원 관리자와 백오피스를 함께 만들어 온 프론트엔드 엔지니어입니다. 가입 회원 약 15만 명, 주간 활성 사용자 약 1만 명의 복지몰과 관리자 서비스를 개발하며, 2026년 1월부터 사내 유일한 프론트엔드 개발자로, 4월부터는 전사 프론트엔드를 단독으로 담당합니다.

직접 써 보며 찾은 불편과 요구사항에서 빠진 동작을 담당자에게 제안하고 구현합니다. 반복되는 판단은 skills와 자체 lint rule로 옮겨 개발 속도를 유지하고, Claude Code, Codex가 제출한 코드와 테스트를 읽은 뒤 화면을 띄워 동작을 확인합니다.

- **문제 발견과 제안:** 모바일로 리뷰를 써 보며 찾은 선택 불편을 PO에게 공유해 복수 선택 UI로 바꿨습니다. 잘못 안내된 쿠폰함 URL은 앱 핫픽스 대신 Load Balancer 리다이렉트로 풀자고 제안해 합의했습니다.
- **쿠폰과 결제:** 쿠폰함, 쿠폰팩과 예약의 최대 혜택 쿠폰 선택을 개발하고, 병원 관리자 결제내역에 쿠폰 결제를 더하며 흩어진 판단을 도메인 함수와 `ts-pattern` 분기로 모았습니다.

- **팀 생산성:** 문서에만 있던 타입 접두사 규칙이 선언 400건에서 어긋난 것을 확인해 한 번에 정리하고 lint rule로 막았습니다. 테스트를 도입하고 타입 검사를 12.5초에서 1.9초로 줄였습니다.

#### React, Next.js 데이터 조회와 오류 대응 | 2025.05 – 현재

입사 당시에는 서버 컴포넌트의 `ensureQuery` 결과를 render props로 전달해, 화면이 Query 캐시를 구독하지 않아 무효화해도 갱신되지 않았습니다. 2025년 5월 예약 화면부터 prefetch와 hydration으로 옮겨 서버가 준비한 데이터를 클라이언트가 같은 캐시로 이어서 조회하고 갱신하게 했습니다.

인증 후 리다이렉트에서 앱이 멈추는 오류는 조사 당시 68건, 53명에게 발생했습니다. 클라이언트 이동 중 서버 컴포넌트가 던진 `redirect()`가 하드 내비게이션으로 처리되면서, Next.js의 `AppRouter`가 훅 호출 도중 렌더를 끊어 렌더마다 훅 개수가 달라지는 경로를 소스에서 확인하고, 판정을 React 렌더 전 proxy로 옮겼습니다. 프로덕션에서만 멈추던 관리자 검색은 `build` 후 `start`로 재현해 라우터 캐시 키 문제로 특정했고, 같은 경로에서 클라이언트만 읽는 조건은 History API로 처리했습니다.

- **폼 구조:** 화면별 예외가 쌓이던 검색 필터를 각 화면이 조합하도록 바꿔 27개 화면을 전환하고, Ant Design Form에는 재귀 조건부 타입으로 중첩 필드명과 값을 검사하는 `createTypedForm<T>`를 만들었습니다. 예약 화면의 가족과 날짜 값은 서버 목록은 Query, 작성 중인 값은 React Hook Form, 제출 조건은 Zod로 나눴습니다.
