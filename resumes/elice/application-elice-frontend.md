## 지원동기

엘리스에서는 학습과 클라우드 실습, AI 기능을 여러 팀과 함께 개발한다는 점에 관심이 갔습니다. 저는 채용 SaaS와 의료복지 서비스의 기능을 개발하며 폼과 데이터 조회, 공통 UI를 정리했습니다. 테스트와 Sentry, AI 개발 workflow도 도입했습니다. 이 경험을 살리면서 상태와 권한이 복잡한 교육 플랫폼을 개발해 보고 싶습니다.

[프론트엔드팀 소개](https://elice.io/ko/resources/blog/ai-a-z-part2)에서 기획 단계부터 의견을 나누고 코드 리뷰와 기술 논의를 제품에 반영한다는 내용을 읽었습니다. 현재는 전사 프론트엔드를 단독으로 맡고 있습니다. 엘리스에서는 동료들과 설계와 코드를 검토하며 여러 사람이 함께 개발할 때 필요한 기준을 배우고 싶습니다.

## 강점

코드에서 오류를 빠르게 찾을 수 있도록 읽기 쉬운 구조를 유지하려고 합니다. 공통 검색 필터에 화면별 예외가 계속 붙어 각 화면에서 필요한 필터를 조합하도록 바꿨습니다. 27개 화면에 적용했고, JSX가 일부 반복되더라도 한 화면의 요구사항 때문에 공통 코드에 분기를 넣지 않아도 됩니다.

Ant Design Form에는 `createTypedForm<T>`를 만들었습니다. 재귀 조건부 타입과 infer로 중첩 필드 경로에 맞는 값을 추론해 잘못된 필드명과 값을 타입 검사에서 잡습니다. 서버 응답과 폼, 제출값 사이의 변환은 순수 함수로 빼고 앱마다 다른 제출 흐름은 각 앱에 뒀습니다. FSD도 저장소에 맞게 기준을 정하고 화면 간 직접 참조와 슬라이스 내부 직접 import는 lint error가 나도록 했습니다.

AI가 작성한 코드도 같은 방식으로 봅니다. 에이전트가 제출한 코드와 테스트를 읽고, 요구사항이나 컨벤션과 다른 부분은 수정을 요청합니다. 같은 지적이 반복되면 skills와 lint rule을 고쳐 다음 작업에 반영합니다.

## 경력

### 세이프닥 | 2025.05 – 현재

가입 회원 약 15만 명, 주간 활성 사용자 약 1만 명의 복지몰과 병원 관리자, 백오피스를 개발하고 운영합니다. 글로벌 사용자 서비스와 CMS도 맡고 있습니다. 2026년 1월부터 사내 유일한 프론트엔드 개발자이며, 4월부터 전사 프론트엔드를 단독으로 담당합니다. 요구사항에서 빠진 동작과 예외는 기획, 운영 담당자와 논의하고 API 요청과 응답은 백엔드 개발자와 맞춥니다.

#### 건강검진 기능 개발 | 2026.09 – 현재

제휴 병원이 세이프닥에서 건강검진 예약을 받고 싶다고 요청했습니다. 이전에는 아임웹에서 정보를 보고 전화로 문의하던 흐름이었습니다. 검사 구성과 기업지원 코드, 예약금이 일반 비급여 프로그램과 달라 기존 서비스에 기능을 추가해야 했습니다. 복지몰, 병원 관리자, 백오피스의 프론트엔드를 맡아 9월 9일 개발을 시작했고 30일 정식 오픈했습니다.

- 백오피스에는 검사항목과 검사 구성, 기업지원 코드와 서류 확인, 결제내역, 결제취소와 환불 승인을 개발했습니다. 병원 관리자에는 프로그램 조회와 예약 관리를 만들었습니다.
- 복지몰의 프로그램 상세와 예약 신청, 예약 상세에 검사 선택과 기업 검진 코드 입력, 토스페이먼츠 예약금 결제를 연결했습니다.
- 일괄 저장 중 일부 요청만 성공하면 서버가 발급한 ID를 폼에 반영합니다. 재시도할 때 이미 저장된 항목이 중복 등록되지 않게 했습니다.
- 모바일에서 결제창을 다녀와도 신청 내용이 남도록 입력값과 `orderId`를 sessionStorage에 저장했습니다. 주문 ID가 일치하고 Zod 검증을 통과한 값만 한 번 복원합니다. 결제 실패 후 입력이 복원되는지, 승인 요청에 실패하면 예약 목록으로 이동하는지는 dev API 서버에 연결한 E2E로 확인했습니다.

#### Sentry 도입과 오류 대응 | 2026.08 – 현재

복지몰의 브라우저, 서버, Edge에 Sentry를 도입해 8월 27일 배포했습니다. 오류별 level을 정하고 중복 전송과 불필요한 수집을 줄였습니다. SDK 코드와 payload를 확인해 의료 정보와 인증 정보가 담긴 값은 제거했습니다. release와 브라우저 소스맵, MCP를 연결했고, Web Vitals(LCP, CLS 등)가 pageload 트랜잭션에 담기도록 수집 시간을 조정했습니다.

Bottom Sheet 드래그 크래시는 라이브러리의 null ref 접근까지 추적해 버전업으로 해결했습니다. 수정 전 누적 75건, 57명 이상에게 발생한 오류 그룹은 9월 10일 배포 뒤 28일까지 18일 동안 0건이었습니다. 관리자 서비스에는 목록과 상세, 오버레이에 Error Boundary를 두어 오류가 난 영역만 다시 시도할 수 있게 했습니다.

#### 테스트 도입 | 2026.07 – 현재

함수와 스키마는 Vitest로, UI와 폼은 React Testing Library로, 브라우저 흐름은 Playwright로 확인합니다. API 연동은 dev API 서버를 먼저 쓰고 재현하기 어려운 조건에 MSW를 씁니다. 실제 Drawer를 열어 폼을 제출하며, 기대 payload는 제품의 변환 함수를 재사용하지 않고 따로 작성합니다.

새 기능의 기대 동작은 BDD 형식의 `*.spec`에 적습니다. 운영이나 QA에서 발견한 오류, console warning은 `*.test`에 재현합니다. 컴포넌트마다 빠진 조건이 없는지 검토하고, 새 테스트 패턴은 제품 코드를 일부러 깨뜨려 실패하는지도 확인합니다. 9월에는 병원 관리자에서 등록한 프로그램이 백오피스의 검수중, 반려, 승인 상태로 바뀌는 과정도 두 앱을 연결한 E2E로 확인했습니다.

#### AI 개발 workflow | 2026.04 – 현재

에이전트가 의도와 다르게 구현하면 skills를 고쳐 다음 작업에 반영합니다. compound engineering 방식으로 계속 보강해 왔고 FSD, lint rule, 테스트 방식도 저장소에 맞게 다듬었습니다. 지금은 아래 순서로 작업하고 문제가 나오면 앞 단계로 돌아갑니다.

티켓과 plan 검토 → 테스트 작성 → 에이전트 구현과 에이전트 코드 리뷰 → 변경분 테스트, lint, typecheck → 직접 diff 리뷰와 화면 동작 확인 → 전체 CI(테스트, knip, lint) → QA 더블 체크 요청

에이전트 리뷰의 critical 항목은 자동 수정하게 하고 결과를 확인합니다. lint rule은 RuleTester와 `__fixture__`, mock으로 테스트하고 미사용 코드는 Knip으로 찾습니다. 여러 worktree에서 동시에 검사할 때 CPU 부하가 커 작업 중에는 변경분과 영향 범위를 먼저 검사합니다. typecheck는 앱과 패키지 단위로, 전체 검사는 CI에서 돌립니다.

### 왓타임 | 2024.01 – 2024.11

개발자, 디자이너와 채용 SaaS RoundHR의 채용 설정, 자동화, 평가, 온보딩, 랜딩과 라운지를 개발했습니다. 앱마다 있던 Query key를 공용 패키지로 모으고 드래그 공통 컴포넌트를 만들었습니다. 외부 채용 사이트의 지원자 데이터를 가져오는 Electron 앱은 초기 구조를 설계하고 채용 사이트 두 곳을 연동했습니다.

여러 개발자가 함께 읽고 수정하기 쉬운 코드를 만들고 싶습니다. 입사 후에는 담당 제품의 상태와 권한, 오류 처리, 배포 방식을 먼저 익히겠습니다. 동료들과 기능을 개발하면서 반복되는 오류와 개발 과정의 불편을 찾아 개선하고, 성능과 오류 지표로 변경 효과도 확인하고 싶습니다.
