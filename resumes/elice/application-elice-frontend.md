## 지원동기

엘리스의 공고에서 제품 개발과 공통 컴포넌트 및 개발 환경 개선을 함께 맡는다는 점에 관심이 갔습니다. 저는 채용 SaaS와 의료복지 서비스의 기능을 늘리면서 폼, 데이터 조회, 오류 처리 기준을 맞추고, 테스트와 AI 개발 workflow를 도입해 왔습니다. 이 경험을 교육, 실습, 클라우드가 연결된 제품에 활용하고 싶습니다.

[프론트엔드팀 소개](https://elice.io/ko/resources/blog/ai-a-z-part2)에서 기획 단계부터 의견을 나누고 코드 리뷰와 기술 논의를 제품에 반영하는 방식을 읽었습니다. 동료들과 설계와 코드를 검토하며, 여러 개발자가 함께 변경할 수 있는 구조를 만들고 복잡한 상태와 권한을 다루는 경험을 넓히고 싶습니다.

## 고유의 강점

기능을 개발하면서 다음 변경을 어렵게 만드는 구조도 함께 살핍니다. 공통 검색 필터에 화면별 예외가 계속 쌓이자, 필터를 각 화면에서 조합하도록 바꾸고 운영 화면 27개를 전환했습니다. JSX 일부 반복을 감수하고 화면마다 다른 요구사항을 공용 렌더러의 분기로 처리하지 않도록 했습니다.

Ant Design Form에는 재귀 조건부 타입과 `infer`를 활용한 `createTypedForm<T>`를 만들어 중첩 필드명과 값 타입을 검사했습니다. 서버 응답↔폼↔제출값 변환은 순수 함수로 분리하고 앱별 제출 흐름은 각 앱에 남겼습니다. FSD도 저장소에 맞게 기준을 정하고 화면 간 직접 참조와 슬라이스 내부 직접 import를 lint error로 차단했습니다.

AI 개발 workflow에서도 이 기준을 사용합니다. 구현이 의도와 어긋나면 코드만 고치지 않고 skills와 lint rule에 남깁니다. 에이전트가 제출한 코드와 테스트를 읽고, 요구사항과 맞지 않는 부분을 짚어 반려한 뒤 수정본을 확인합니다.

## 역할과 기여

### 세이프닥 | 2025.05 – 현재

가입 회원 약 15만 명, 주간 활성 사용자 약 1만 명의 복지몰, 병원 관리자, 백오피스, 글로벌 사용자 서비스와 CMS를 개발하고 운영합니다. 2026년 1월부터 사내 유일한 프론트엔드 개발자이며, 4월부터 전사 프론트엔드를 단독으로 담당합니다. 기획, 운영 담당자와 빠진 동작과 예외를 논의하고, 백엔드 개발자와 API 요청과 응답을 맞추며 개발합니다.

#### 건강검진 기능 개발 | 2026.09 – 현재

제휴 병원이 세이프닥에서 건강검진 예약을 받기를 요청했습니다. 기존에는 아임웹에서 정보를 보고 전화로 문의했고, 검사 구성, 기업지원 코드, 예약금 흐름이 비급여 프로그램과 달라 기존 서비스로 처리하기 어려웠습니다. 세 제품의 프론트엔드를 맡아 9월 9일 개발을 시작하고 30일 정식 오픈했습니다.

- 백오피스에는 검사항목과 검사 구성, 기업지원 코드와 서류 확인, 결제내역, 결제취소, 환불 승인을, 병원 관리자에는 프로그램 조회와 예약 관리를 개발했습니다.
- 복지몰의 프로그램 상세, 예약 신청, 예약 상세에 검사 선택, 기업 검진 코드와 토스페이먼츠 예약금 결제를 연결했습니다.
- 일괄 저장 중 일부 요청만 성공하면 서버가 발급한 ID를 폼에 반영해 재시도 시 중복 등록을 막았습니다.
- 결제 실패 후 입력은 `orderId`와 함께 `sessionStorage`에 남기고, 같은 주문이며 현재 Zod 스키마를 통과한 값만 한 번 복원합니다. 입력 복원과 승인 요청 실패 시 예약 목록 이동은 dev API 서버 E2E로 확인했습니다.

#### Sentry 도입과 오류 대응 | 2026.08 – 현재

복지몰의 브라우저, 서버, Edge에 Sentry를 도입하고 8월 27일 운영에 배포했습니다. 오류 레벨, 중복 수집, 전송 차단 기준을 정하고 의료와 인증 정보가 담기는 값을 제거했습니다. release, 브라우저 소스맵, MCP를 연결하고, Web Vitals(LCP, CLS 등)가 pageload 트랜잭션에 실리도록 수집 시간을 조정했습니다.

Bottom Sheet 드래그 크래시는 라이브러리의 null ref 접근까지 추적해 버전업으로 해결했습니다. 누적 75건, 57명 이상에게 발생한 오류 그룹은 9월 10일 배포 뒤 28일까지 18일간 0건이었습니다. 관리자 서비스에는 목록, 상세, 오버레이별 Error Boundary를 적용해 정상 구획을 유지하고 실패한 부분만 재시도하도록 했습니다.

#### 테스트 도입 | 2026.07 – 현재

함수와 스키마는 Vitest, UI 및 폼은 React Testing Library, 브라우저 흐름은 Playwright로 확인합니다. API 연동은 dev API 서버를 우선하고, 만들기 어려운 조건에는 MSW 목을 사용합니다. 실제 Drawer를 조작해 제출하고 기대 payload는 제품의 변환 함수를 재사용하지 않고 작성합니다.

새 기능의 기대 동작은 BDD 형식의 `*.spec.{ts,tsx}`, 운영 및 QA 오류와 console warning의 회귀는 `*.test.{ts,tsx}`로 구분합니다. 컴포넌트별로 빠진 조건을 검토하고, 새 패턴은 제품 코드를 일부러 깨뜨려 테스트가 실패하는지 확인합니다. 9월에는 병원 관리자 등록 → 백오피스 검수중, 반려, 승인을 두 앱에 걸쳐 확인하는 E2E도 추가했습니다.

[테스트 코드를 도입하면서 세운 기준](https://jingeon27.tistory.com/25)

#### AI 개발 workflow | 2026.04 – 현재

compound engineering 방식으로 skills를 보강하고 FSD, lint rule, 테스트 기준을 저장소에 맞게 다듬었습니다. 현재 작업은 다음 순서로 진행하며 문제가 나오면 앞 단계로 돌아갑니다.

티켓, plan 검토 → 테스트 작성 → 에이전트 구현과 에이전트 코드 리뷰 → 변경분 테스트, lint, typecheck → 직접 diff 리뷰, 화면을 띄워 동작 확인 → 전체 CI(테스트, knip, lint) → QA 더블 체크 요청

critical 자동 수정 결과도 검토합니다. lint rule은 RuleTester, `__fixture__`, mock으로 검증하고, Knip으로 미사용 코드를 검사합니다. 병렬 worktree의 CPU 부하 때문에 작업 중에는 변경과 영향 범위를 우선 검사하고 typecheck는 앱과 패키지 단위로 유지합니다. 전체 검사는 CI에서 확인합니다.

### 왓타임 | 2024.01 – 2024.11

개발자, 디자이너와 채용 SaaS RoundHR의 채용 설정, 자동화, 평가, 온보딩, 랜딩과 라운지를 개발했습니다. 앱 간 Query key, 드래그 공통 코드와 Electron 지원자 데이터 수집 앱의 초기 구조, 두 채용 사이트 연동도 맡았습니다.

## 앞으로의 방향

사용자에게 필요한 기능을 개발하면서, 여러 개발자가 함께 변경하고 운영할 수 있는 구조를 만드는 엔지니어로 성장하고 싶습니다. 초기에는 제품의 상태, 권한, 오류 처리와 배포 방식을 이해하고 동료들의 판단 기준을 배우겠습니다. 이후 반복되는 오류와 개발 과정의 불편부터 개선하고, 변경 전후의 성능과 오류 지표를 확인하는 경험을 넓히고 싶습니다.
