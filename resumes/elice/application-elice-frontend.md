## 소개·지원동기

React와 TypeScript로 사용자 화면과 관리자 서비스를 개발하는 김진건입니다. 세이프닥에서 가입 회원 약 15만 명, 하루 활성 사용자 약 1,500명의 복지몰, 병원 관리자, 백오피스, 글로벌 사용자 서비스와 CMS를 맡고 있습니다. 2026년 1월부터 사내 유일한 프론트엔드로 일하고 있으며, 4월부터 개발과 운영을 단독으로 담당합니다.

이전 직장 왓타임에서는 ATS ‘RoundHR’의 채용 설정과 자동화, 서류·면접 평가, 면접 템플릿을 개발했습니다. 프론트엔드·백엔드 개발자분들, 디자이너분과 함께 공통 코드를 정리했고, Electron 후보자 수집 앱의 초기 구조와 잡플래닛·게임잡 연동도 맡았습니다.

[엘리스 프론트엔드팀 소개](https://elice.io/ko/resources/blog/ai-a-z-part2)에서 실시간 수업과 코드 에디터를 만들면서 내부 라이브러리와 개발 환경도 함께 다룬다는 내용을 읽었습니다. 저도 여러 제품을 맡으며 기능 개발과 함께 여러 화면이 쓰는 공용 코드를 만들어 왔습니다. 중첩 필드 경로를 타입으로 검사하는 폼 API와 스키마에서 필드명을 파생하는 검색 필터를 만들어 운영 화면 27개에 적용했고, 반복되는 실수는 테스트가 딸린 자체 ESLint 규칙으로 막았습니다. 엘리스에서도 여러 제품에 쓰이는 라이브러리와 개발 환경을 다루면서 실제 기능을 개발하고 싶습니다.

## 건강검진 기능 개발 | 2026.09 – 현재

건강검진은 아임웹에서 정보를 보고 전화로 문의해야 했습니다. 한 제휴 병원이 세이프닥에서 검진 예약을 받기를 요청했지만, 기존 비급여 프로그램에는 검사 구성과 기업지원 검진, 예약금 결제가 없었습니다. 개발팀장님·부팀장님과 빠진 동작과 예외를 확인하며 세 제품의 프론트엔드를 개발했습니다. 9월 9일부터 두 주 동안 순차 개발해 23일 운영에 배포했고, 30일 정식 오픈했습니다.

백오피스에는 검사항목과 필수·선택 검사 구성, 기업지원 코드·서류 확인, 결제내역과 결제취소·환불 승인을 추가했습니다. 병원 관리자는 검진 프로그램을 조회하고 예약을 관리하도록 했습니다. 검진만 운영하는 병원과 다른 진료과도 운영하는 병원의 메뉴를 나누고, 병원이 직접 처리할 수 없는 예약금 결제취소는 요청 접수로 안내했습니다. 복지몰에는 검진 상세부터 검사 선택, 공단 검진 여부·주소·기업 검진 코드 입력, 예약금 결제, 예약 상세까지 만들었습니다.

검사항목 일괄 저장은 일부만 성공할 수 있어, 재시도 전에 서버 목록을 다시 받아 발급된 id를 폼에 반영했습니다. 비급여와 검진은 같은 상세 경로를 쓰면서 상단바와 인증 후 이동은 공유하고, 상세 화면과 신청 폼은 따로 두었습니다. 결제 실패로 돌아오면 문서가 새로 로드되므로, 신청 내용을 결제 시도(`orderId`)와 함께 `sessionStorage`에 남기고 현재 폼 스키마로 `safeParse`한 값만 한 번 되살립니다. 결제창 실패 복귀의 입력 복원과 승인 요청 실패 시 예약 목록 이동은 dev API 서버 E2E로 확인했습니다.

## Sentry 도입과 운영 오류 추적 | 2026.08 – 09

운영 오류를 수집하고 원인을 추적할 수 있도록 복지몰의 브라우저·서버·Edge에 Sentry를 도입했습니다. 8월 19일부터 구현해 27일 운영에 배포했습니다. 작업을 얼마나 막는지에 따라 오류 레벨을 정하고, 같은 오류가 API 처리와 Error Boundary를 거치며 여러 번 수집되지 않도록 했습니다.

`sendDefaultPii: false`를 설정해도 모든 전송 경로에서 민감 정보가 빠지는 것은 아니었습니다. SDK 소스를 따라 이벤트·breadcrumb·transaction·span에 어떤 값이 실리는지 확인해 의료·인증 정보가 담기는 값을 제거하고 타입과 테스트를 붙였습니다. release와 브라우저 소스맵도 연결했습니다. 서버 소스맵은 업로드 502 때문에 제외해 서버 스택은 압축된 코드로 남아 있습니다.

수집한 Bottom Sheet 크래시는 라이브러리의 null ref 접근까지 추적해 버전을 올렸습니다. 수정 배포 전까지 누적 57명 이상에게 75건 발생한 오류 그룹은 9월 10일 배포 뒤 28일까지 0건이었습니다.

## 테스트 체계 재구축 | 2026.07 – 현재

기존 테스트는 실제 폼에서 요청이 나가는지, 서버가 입력을 받아 주는지 확인하지 못했습니다. 이를 정리한 뒤 7월 20일부터 관리자 서비스 모노레포와 복지몰의 테스트를 다시 구성했습니다. 순수 함수·스키마는 Vitest, UI와 폼은 React Testing Library, 브라우저 흐름은 Playwright로 확인합니다. 목은 마지막 수단으로 두고, 관리자 서비스의 화면 테스트는 dev API 서버에 붙이는 것을 기본으로 합니다. 작성은 에이전트에 맡기고, 저는 기대 동작과 빠진 조건, 실제 오류를 잡는지 검토합니다.

테스트 안에서 제출 로직을 복제하던 하네스를 없애고 실제 Drawer를 렌더하게 바꿨습니다. 잘못된 입력에도 성공하던 목에는 서버에서 확인한 제약을 반영했습니다. 기대 payload는 제품 변환 함수를 다시 호출해 만들지 않고 별도로 적었습니다. 등록·수정 Drawer를 나누면서 등록 후 창이 닫히지 않는 오류와 URL로 직접 진입하면 수정 payload 타입이 어긋나는 오류를 찾았습니다. 9월에는 병원 관리자에서 프로그램을 등록하고 백오피스에서 검수중·반려·승인하는 E2E를 추가했습니다.

새 기능은 BDD 형식의 `*.spec`에 컴포넌트별 기대 동작을 적고 빠진 조건을 확인합니다. 운영·QA 오류는 `*.test`로 재현합니다. 새 패턴의 테스트는 제품 코드를 일부러 깨뜨려 실패하는지 확인한 뒤 넣습니다. dev API 계약 테스트는 PR을 막지 않는 별도 단계로 돌리고, E2E는 CI 밖에서 실행합니다.

## 검색 필터와 SSE 상담 화면 | 2026.06 – 08

2026년 8월 검색 필터를 화면에서 직접 조합하도록 바꾸고 운영 화면 27개를 전환했습니다. 화면마다 JSX를 적어야 하지만, 새 조건 때문에 공용 렌더러에 분기를 추가하는 일은 줄었습니다. 처음에는 수동 페이지·요청 순서 관리도 그대로 옮겼습니다. 이후 이름은 같고 코드가 다른 기업이 중복 제거로 사라지는 것을 찾아 조회를 도메인 쪽으로 옮겼고, 공용 UI에는 입력과 스크롤 처리를 남겼습니다.

6월에 통합한 상담 화면은 두 서버를 수정할 수 없는 상황이었습니다. 상담 SSE에 AI 답변과 상담사 메시지가 모두 들어오는 것을 확인해 화면 표시를 하나로 합쳤습니다. AI 생성이 끝까지 진행되도록 AI 스트림 연결도 유지했고, 메시지를 보낼 서버는 상담 상태에 따라 구분했습니다. 이후 상담 SSE를 `@tanstack/ai`의 메시지 모델로 바꾸는 어댑터를 만들었습니다. AI 생성이 브라우저 연결과 요청 시간 제한에 영향을 받는 점은 남아 있습니다.

## 코딩 에이전트와 작업하는 방식 | 2026.04 – 현재

의도와 다르게 구현한 부분은 코드 수정으로 끝내지 않고 스킬에 기준을 적었습니다. 정적으로 검사할 수 있는 것은 lint 규칙으로 옮겼습니다. 현재 기능 개발과 리팩터링에서는 에이전트가 제출한 제품 코드와 테스트를 읽고, 부족한 부분을 짚어 수정본을 다시 확인합니다.

티켓·plan 검토 → 테스트 작성 → 에이전트 구현·에이전트 코드 리뷰 → 변경분 테스트·lint·typecheck → 제 diff 리뷰·로컬 화면 확인 → 전체 CI(테스트·knip·lint) → QA 더블 체크 요청

위 순서로 진행하며 문제가 나오면 앞 단계로 돌아갑니다. 테스트는 앞서 적은 `*.spec`·`*.test` 기준을 따릅니다. 검사 시간이 얼마나 드는지도 확인합니다. 타입 인지 lint는 시간이 3.3배 늘어 도입을 보류했습니다.
