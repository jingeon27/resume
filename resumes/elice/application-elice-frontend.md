## 지원동기

엘리스의 프론트엔드는 교육·실습·클라우드가 연결된 제품에서 복잡한 상태와 권한을 다루고, 공통 코드와 개발 환경도 함께 개선하는 역할이라고 이해했습니다. [프론트엔드팀 소개](https://elice.io/ko/resources/blog/ai-a-z-part2)에서도 기능 개발과 내부 라이브러리를 함께 다루는 방식을 읽었습니다.

저는 채용 SaaS RoundHR과 의료복지 서비스를 개발하며 여러 제품의 폼·조회·오류 처리 기준을 정하고 기존 코드를 리팩터링했습니다. 최근에는 AI 개발 workflow와 테스트·lint를 함께 개선해 왔습니다. 이 경험으로 제품 개발에 기여하고, 동료들과 설계와 코드를 검토하며 복잡한 상태·권한과 실시간 기능을 다루는 역량을 키우고 싶습니다.

## 맡아 온 역할

세이프닥에서 가입 회원 약 15만 명, 주간 활성 사용자 약 1만 명의 복지몰과 병원 관리자·백오피스, 글로벌 사용자 서비스·CMS를 개발·운영합니다. 2026년 1월부터 사내 유일한 프론트엔드 개발자이고, 4월부터 전사 프론트엔드를 단독으로 담당합니다. 예약·리뷰·쿠폰·결제·정산 등의 기능을 개발하면서 사용자와 병원·운영팀의 흐름을 함께 다뤘습니다.

왓타임에서는 프론트엔드·백엔드 개발자, 디자이너와 RoundHR의 채용 설정·자동화·평가·온보딩과 랜딩·라운지를 개발했습니다. 면접 템플릿의 단계별 입력과 앱 간 Query·드래그 공통 코드, Electron 지원자 데이터 수집 앱의 초기 구조와 두 채용 사이트 연동도 맡았습니다.

## 공통 구조와 타입 설계

화면마다 예외가 늘어나는 공통 검색 필터를 화면별 조합으로 바꾸고 운영 화면 27개를 전환했습니다. JSX 일부 반복을 감수하고 새 조건이 다른 화면의 필터에 영향을 주지 않도록 했습니다. Ant Design Form에는 재귀 조건부 타입과 `infer`로 중첩 필드 경로와 값 타입을 계산하는 `createTypedForm<T>`를 만들어 잘못된 필드명과 값을 타입 검사에서 찾도록 했습니다.

FSD의 배치 기준도 저장소에 맞게 정했습니다. 서버 모델·API 로직은 features, 화면 조합은 pages, 도메인에 의존하지 않는 공통 UI는 shared에 두었습니다. 화면 간 직접 참조 62건과 슬라이스 내부 직접 import 경고 271건을 정리하고 lint error로 차단했습니다. 데이터 조회는 2025년 5월부터 서버 결과를 props로 읽던 구조를 prefetch·hydration으로 옮겨, 클라이언트가 같은 Query 캐시로 갱신·무효화를 처리하도록 했습니다.

## 건강검진 기능 개발 | 2026.09 – 현재

제휴 병원이 세이프닥에서 건강검진 예약을 받기를 요청했습니다. 기존에는 아임웹에서 정보를 본 뒤 전화로 문의했고, 검사 구성·기업지원 코드·예약금 흐름이 비급여 프로그램과 달라 기존 서비스로 처리하기 어려웠습니다. 개발팀장·부팀장과 빠진 동작과 예외를 확인하며 세 제품의 프론트엔드를 개발했습니다. 9월 9일 개발을 시작해 23일 운영에 배포하고, 30일 정식 오픈했습니다.

백오피스에는 검사항목과 필수·선택 검사 구성, 기업지원 코드·서류 확인, 결제내역과 결제취소·환불 승인을 추가했습니다. 병원 관리자는 검진 프로그램을 조회하고 예약을 관리하도록 했습니다. 검진만 운영하는 병원과 다른 진료과도 운영하는 병원의 메뉴를 나누고, 병원이 직접 처리할 수 없는 예약금 결제취소는 요청 접수로 안내했습니다. 복지몰에는 검진 상세부터 검사 선택, 공단 검진 여부·주소·기업 검진 코드 입력, 예약금 결제, 예약 상세까지 만들었습니다.

검사항목 일괄 저장은 일부만 성공할 수 있어, 재시도 전에 서버 목록을 다시 받아 발급된 id를 폼에 반영했습니다. 모바일 토스페이먼츠 결제창에서 실패로 돌아오면 문서가 새로 로드되므로, `orderId`와 입력값을 `sessionStorage`에 남겼습니다. 같은 결제 시도이면서 현재 Zod 스키마를 통과한 값만 한 번 복원하고, 맞지 않는 값은 버립니다. 입력 복원과 승인 요청 실패 시 예약 목록 이동은 dev API 서버 E2E로 확인했습니다.

## Sentry 도입과 운영 오류 추적 | 2026.08 – 현재

운영 오류를 수집하고 원인을 추적할 수 있도록 복지몰의 브라우저·서버·Edge에 Sentry를 도입했습니다. 8월 19일부터 구현해 27일 운영에 배포했습니다. 작업을 얼마나 막는지에 따라 오류 레벨을 정하고, 같은 오류가 API 처리와 Error Boundary를 거치며 여러 번 수집되지 않도록 했습니다.

차단 게이트로 의미 없는 전송을 줄이고 SDK 소스를 확인해 의료·인증 정보가 담기는 값을 제거했습니다. release와 브라우저 소스맵, Web Vitals 수집, 에이전트가 이슈를 조회할 수 있는 Sentry MCP를 연결했습니다. 정보 제거 로직은 타입과 테스트로 검증하고 Web Vitals 전송은 브라우저 E2E로 확인했습니다.

수집한 Bottom Sheet 크래시는 라이브러리의 null ref 접근까지 추적해 버전을 올렸습니다. 누적 75건·57명 이상에게 발생한 오류 그룹은 9월 10일 배포 뒤 28일까지 18일간 0건이었습니다. 관리자 서비스는 Error Boundary를 목록·상세·오버레이로 나눠 정상 구획을 유지하고 실패한 부분만 재시도하도록 했습니다. API·렌더링 오류와 Zod 응답 스키마 불일치는 CloudWatch에서 추적합니다.

## 테스트 도입 | 2026.07 – 현재

7월부터 테스트 코드를 도입하고 기능 개발과 오류 대응을 거치며 기준을 보완했습니다. 순수 함수·스키마는 Vitest, UI와 폼은 React Testing Library, 브라우저 흐름은 Playwright로 확인합니다. API 연동은 dev API 서버에서 확인하는 것을 우선하고, 해당 환경으로 만들기 어려운 조건에 MSW 목을 사용합니다. 에이전트가 테스트를 작성하고, 저는 기대 동작과 빠진 조건, 실제 오류를 잡는지 검토합니다.

폼 테스트는 실제 등록·수정 Drawer를 조작해 제출 요청을 확인합니다. 기대 payload는 제품 변환 함수를 재사용하지 않고 별도로 작성합니다. 9월에는 병원 관리자에서 프로그램을 등록하고 백오피스에서 검수중·반려·승인하는 두 앱의 흐름을 E2E로 연결했습니다.

새 기능은 BDD 형식의 `*.spec.{ts,tsx}`에 컴포넌트별 기대 동작을 적고 빠진 조건을 확인합니다. 운영·QA 오류와 console warning의 회귀는 `*.test.{ts,tsx}`로 재현합니다. 새 패턴의 테스트는 제품 코드를 일부러 깨뜨려 실패하는지 확인합니다. dev API 계약 테스트는 PR을 막지 않는 별도 CI 단계로, 브라우저 E2E는 CI 밖에서 실행합니다.

## AI 개발 workflow | 2026.04 – 현재

4월부터 compound engineering 방식으로 skills를 보강했습니다. 의도와 다르게 구현한 부분은 코드 수정으로 끝내지 않고 skills에 기준을 남겼고, 정적으로 검사할 수 있는 것은 lint rule로 옮겼습니다. 현재 기능 개발과 리팩터링에서는 에이전트가 제출한 코드와 테스트를 읽고, 부족한 부분을 짚어 반려한 뒤 수정본을 확인합니다.

티켓·plan 검토 → 테스트 작성 → 에이전트 구현·에이전트 코드 리뷰 → 변경분 테스트·lint·typecheck → 직접 diff 리뷰·화면을 띄워 동작 확인 → 전체 CI(테스트·knip·lint) → QA 더블 체크 요청

단계 중 문제가 나오면 앞 단계로 돌아갑니다. 테스트는 앞서 적은 `*.spec`·`*.test` 기준을 따릅니다. 자체 lint rule은 RuleTester와 `__fixture__`·mock으로 검증하고 Knip으로 미사용 코드도 검사합니다. 병렬 worktree의 CPU 부하 때문에 변경분을 우선 검사하고 전체 검사는 CI에서 확인합니다. 타입 인지 lint는 검사 시간이 3.3배 늘어 도입을 보류했습니다.

## 앞으로의 방향

제품의 요구사항을 구현하면서 여러 개발자가 함께 변경할 수 있는 구조와 검증 기준을 만드는 엔지니어로 성장하고 싶습니다. 합류하면 현재 제품의 상태·권한·오류 처리와 배포 방식을 먼저 이해하겠습니다. 이후 반복되는 문제부터 동료들과 개선하고, 성능과 오류 지표를 기준으로 변경 효과를 확인하는 경험을 넓히고 싶습니다.
