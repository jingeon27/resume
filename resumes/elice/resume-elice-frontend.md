## 소개·지원동기

React·TypeScript로 사용자 화면과 관리자 서비스를 개발하고, 공통 컴포넌트·조회 구조·검증·운영 모니터링을 함께 개선해 온 프론트엔드 엔지니어입니다. 세이프닥에서 2026년 1월부터 사내 유일한 프론트엔드로 일하고, 4월부터 개발·운영을 단독으로 담당합니다. 가입 회원 약 15만 명의 복지몰, 병원 관리자, Back-Office와 글로벌 사용자 서비스·CMS까지 다섯 제품을 맡고 있습니다.

전달받은 요구사항에서 빠진 동작과 예외는 담당자와 확인하고, 기술 선택은 실제 사용 흐름과 유지할 범위에 맞춰 결정합니다. 에이전트 구현은 변경 코드·테스트·실제 화면으로 검토하며, 반복되는 판단은 스킬과 lint 규칙에 반영합니다.

### 엘리스에 지원하는 이유

교육·평가·클라우드 기능이 이어지는 엘리스에서 사용자 작업과 여러 제품의 공통 기반을 함께 다루는 프론트엔드 역할에 관심이 있습니다. [엘리스 프론트엔드팀 소개](https://elice.io/ko/resources/blog/ai-a-z-part2)에서 실시간 기능과 내부 라이브러리·개발 환경을 함께 만드는 업무가 인상적이었습니다.

저는 병원 설정부터 사용자 예약·결제까지 세 제품을 함께 개발하고, 서로 다른 SSE를 하나의 상담 화면에 연결했으며, 화면별 예외에 대응할 수 있도록 공통 필터와 폼을 바꿨습니다. 이 경험을 바탕으로 엘리스에서도 기능 구현과 운영 문제 해결에 기여하고 싶습니다. 동료들과 설계의 근거와 비용을 검토하며 공통 기반의 변경이 여러 제품에 미치는 영향을 함께 확인하고, 실시간 서비스의 연결·복구와 성능을 다루는 경험도 넓히고 싶습니다.

#### AI 워크플로와 검증·개발 비용 조정 | 2026.04 – 현재

에이전트 구현이 의도와 어긋나면 기준을 저장소별 스킬과 lint 규칙에 남겼습니다. 기능 개발·리팩터링에서는 변경된 제품 코드와 테스트를 읽고, 에이전트가 제출한 결과의 부족한 부분을 짚어 수정본을 다시 확인합니다.

**티켓·plan 검토 → 테스트 작성 → 에이전트 구현·에이전트 코드 리뷰 → 변경분 테스트·lint·typecheck → 제 diff 리뷰·로컬 화면 확인 → 전체 CI(테스트·knip·lint) → QA 더블 체크 요청** 순서로 일하고, 문제가 나오면 앞 단계로 돌아갑니다.

- 새 기능의 기대 동작은 BDD 형식의 `*.spec`에 적어 컴포넌트별 누락 조건을 보고, 운영·QA 오류는 `*.test`에 재현합니다. 새 패턴의 테스트는 제품 코드를 일부러 깨뜨려 실제로 실패하는지 확인한 뒤 넣습니다.
- **규칙 보강(2026.08 – 09):** 복지몰의 직접 import 경고 **271건**을 정리하고 9월 1일 error로 막았습니다. 9월 29일에는 동적 import 등을 놓치는 규칙을 수정하고, 추가한 테스트를 수정 전 규칙에 돌려 **8건이 실패**하는 것을 확인했습니다. 글로벌 서비스의 테스트에서는 응답 스키마 위반을 경고에서 실패로 바꾸고, 목 데이터를 틀리게 해 검증했습니다.
- 병렬 worktree의 전체 검사가 CPU 경합을 일으켜 로컬은 변경분·영향 범위를 확인하고 전체 검사는 CI에서도 수행하도록 조정했습니다. 전체 저장소의 문제 발견이 늦어질 수 있어 CI 결과까지 확인합니다. 별도로 타입 인지 lint 규칙은 검사 비용이 **3.3배** 늘어나는 것을 확인해 도입을 보류했습니다.
