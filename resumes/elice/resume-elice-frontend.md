## 소개

여러 제품의 기능을 만들면서 다음 변경이 쉬워지도록 공통 구조와 개발 환경도 함께 정리해 온 프론트엔드 엔지니어입니다. 가입 회원 약 15만 명, 주간 활성 사용자 약 1만 명의 복지몰, 병원 관리자, 백오피스, 글로벌 서비스와 CMS를 개발합니다. 2026년 1월부터 사내 유일한 프론트엔드 개발자이며, 4월부터는 전사 프론트엔드를 단독으로 담당합니다.

개발할 때는 기준을 먼저 세웁니다. 폼 필드 경로는 제네릭으로 검사하고, Zod 검증 실패는 값의 출처에 따라 다르게 처리합니다. 반복되는 판단은 skills와 자체 lint rule로 남깁니다. 에이전트가 제출한 코드와 테스트를 읽은 뒤 화면을 띄워 동작을 확인합니다.

## 주요 경험

- **공통 검색과 폼:** 화면별 예외가 쌓이던 공통 검색 필터를 화면마다 조합하는 구조로 바꿔 운영 화면 27개를 옮겼습니다. Ant Design Form의 중첩 필드는 `createTypedForm<T>`로 타입 검사를 받게 했습니다.
- **채팅:** 백오피스와 병원 관리자가 같은 대화 화면과 실시간 연결을 쓰도록 공유 패키지로 옮기고, 그 위에 병원 상담 채팅을 만들었습니다. lint와 테스트에서 빠져 있던 채팅 코드는 다시 검사 대상으로 넣었습니다.
- **데이터 조회:** 서버 조회 결과를 props로 받아 무효화해도 갱신되지 않던 화면을 prefetch와 hydration 구조로 옮겼습니다. 인증 후 리다이렉트에서 앱이 멈추던 오류는 Next.js 라우터 소스까지 따라가 고쳤습니다.
- **건강검진:** 기존 서비스로는 다루기 어려웠던 검진 예약을 세 제품에 걸쳐 3주 만에 열었습니다. 결제창을 다녀와도 입력이 남게 하되, `orderId`와 Zod 검증으로 복원할 값을 좁혔습니다.
- **운영 오류:** 복지몰에 Sentry를 도입했습니다. 57명 이상에게 75건 난 Bottom Sheet 크래시는 라이브러리 소스까지 따라가 고쳤고, 배포 뒤 18일 동안 0건이었습니다.
- **개발 환경:** 슬라이스 내부를 직접 import하던 271건을 정리해 lint error로 막고, 타입 검사를 12.5초에서 1.9초로 줄였습니다.
- **테스트:** 2026년 7월부터 테스트를 도입해 새 기능은 BDD 명세로, 운영 오류는 회귀 테스트로 남깁니다. 두 앱에 걸친 등록과 검수 흐름은 E2E로 확인합니다.

#### 공통 구조, 폼, 타입 설계 | 2025.06 – 현재

관리자 화면이 늘면서 공통 검색 필터에 화면별 예외 분기가 계속 쌓였습니다. 각 화면이 필요한 필터를 조합하도록 바꾸고 운영 화면 27개를 옮겼습니다. JSX가 조금 반복되는 건 감수했고, URL과 폼, API의 필드는 같은 Zod 스키마로 맞췄습니다.

Ant Design Form은 중첩 필드명을 배열로 받아서, 틀린 필드명이나 값이 실행해야 드러났습니다. 재귀 조건부 타입과 infer로 유효한 경로와 값을 계산하는 `createTypedForm<T>`를 만들어 name, getFieldValue, setFieldValue, useWatch에 적용했습니다. 타입 단언은 래퍼 안에만 두고, 서버 응답과 폼, 제출값 사이의 변환은 순수 함수로 뺐습니다.

예약 화면은 가족과 날짜 값이 Query 캐시와 Zustand, 로컬 상태에 나뉘어 있어서, 날짜를 고른 뒤 가족을 추가하면 선택한 일시가 어긋났습니다. 서버 목록은 Query, 작성 중인 값은 React Hook Form, 제출 조건은 Zod가 맡도록 나눠 고쳤고, 519줄이던 예약 대상 선택 컴포넌트는 55줄이 됐습니다.

- FSD에서 재사용할 것 같으면 entities에 두던 기준을 바꿔, 서버 모델과 API는 features, 화면 조합은 pages, 공통 UI는 shared에 두기로 했습니다. 화면 간 직접 참조 62건은 정리하고 lint error로 막았습니다.
- 인수한 1,170줄짜리 정산 페이지는 조회, 표, 선택, 편집, 정산 처리로 나누고, ref로 열던 모달은 대상 데이터와 열림 상태를 props로 받게 했습니다. 가격 이력을 추가하자는 요청에는 정산 기준이 프로그램 가격인지 견적 금액인지부터 확인했고, 견적 금액이 기준이라 이력 구조는 만들지 않았습니다.
- 공통 UI는 조합이 더 유연하고 접근성 primitive를 쓸 수 있어 Headless UI에서 Radix UI로 옮겼습니다. Bottom Sheet는 Compound Components와 overlay-kit으로 다시 짜서 본문과 하단 버튼이 같은 폼을 쓰게 했습니다.

#### 상담 채팅과 공유 패키지 | 2026.06 – 현재

백오피스의 유저 상담 채팅은 동료가 처음 만들었고, 저는 입력과 실시간 연결을 고치고 병원 상담 채팅을 새로 만들었습니다. 병원 상담은 최고 관리자가 채팅방을 열고 병원 관리자와 상담사를 초대하는 흐름입니다. 병원 관리자 화면도 같은 대화와 입력칸, 실시간 연결을 써야 해서 백오피스 안에 있던 채팅을 공유 패키지로 옮겼습니다. 상담사와 병원 관리자는 API 경로가 달라, API 함수만 앱마다 넣게 했습니다.

- 방 SSE 연결은 React 밖 스토어에 두고 useSyncExternalStore로 구독합니다. 토큰이 만료되면 갱신한 뒤 이어 받고, 끊기면 `last-event-id`로 마지막 순번부터 다시 받습니다. 새 메시지와 읽음은 다시 조회하지 않고 캐시에 바로 넣습니다.
- 유저 상담은 첫 페이지를 받기 전에 스트림을 열어, 방을 열 때마다 지난 이벤트를 모두 다시 받고 무효화가 3건씩 나갔습니다. 첫 페이지의 마지막 순번부터 열도록 고치고 회귀 테스트로 고정했습니다.
- 병원 관리자는 방 하나에만 들어갈 수 있어서, 초대가 막힌 사람만 골라 참여 중인 방을 표시하고 나머지는 바로 다시 보낼 수 있게 했습니다. 한글 조합 중 Enter로 메시지가 두 번 전송되던 문제도 막았습니다.
- 채팅 영역은 lint와 테스트, Knip 검사에서 빠져 있었습니다. 직접 관리하기로 하면서 제외 설정을 걷어내 채팅 테스트 21개가 다시 돌게 했고, 목으로 돌던 테스트는 목 레인으로 옮겼습니다.

#### 데이터 조회와 Next.js 오류 대응 | 2025.05 – 현재

입사 당시에는 서버 컴포넌트가 `ensureQuery`로 받은 결과를 render props로 넘겼습니다. 화면이 Query 캐시를 구독하지 않아 무효화해도 갱신되지 않았고, 조회 조건만 바꿔도 서버 렌더링 결과를 다시 받아야 했습니다. 2025년 5월 예약 화면부터 prefetch와 hydration 구조로 옮겼습니다. 서버는 초기 HTML에 필요한 데이터를 준비하고, 이후 조회와 갱신, 무효화는 클라이언트가 같은 캐시로 처리합니다.

인증을 마친 사용자가 로그인, 본인인증 화면에서 돌아갈 때 앱이 멈추는 오류는 조사 당시 53명에게 68건 났습니다. Next.js 소스에서 `redirect()` 처리 중 렌더마다 호출되는 훅 개수가 달라지는 경로를 찾았고, 인증 확인과 리다이렉트를 React 렌더링 전에 도는 proxy로 옮겼습니다.

관리자 검색 오류는 localhost에서 dev로 띄우면 나타나지 않아 build 후 start로 재현했습니다. 목록 7개 중 6개에서 확인하고 업스트림의 라우터 캐시 이슈까지 추적했습니다. 서버가 검색 조건을 읽지 않는 화면은 같은 경로의 쿼리 변경을 History API로 처리했고, 수정 뒤 9월 28일까지 같은 증상은 다시 보고되지 않았습니다.

Next.js 14→16, React 18→19 전환은 Turbopack과 Next.js 16의 로컬 개발 속도 개선을 보고 진행했습니다. 비동기 API와 캐시 변경에 맞춰 코드를 고친 뒤 직접 진입, 뒤로가기, 새로고침을 확인했습니다.

#### 테스트 도입과 AI 개발 workflow | 2026.04 – 현재

2026년 4월부터 에이전트로 구현하면서, 의도와 어긋난 구현은 코드만 고치지 않고 파일 배치나 상태 관리, 공통 코드 사용 기준을 skills와 lint rule에 남겼습니다. 7월부터는 테스트를 도입해 같은 흐름에 넣었습니다.

티켓, plan 검토 → 테스트 작성 → 에이전트 구현과 에이전트 코드 리뷰 → 변경분 테스트, lint, typecheck → 직접 diff 리뷰, 화면을 띄워 동작 확인 → 전체 CI(테스트, knip, lint) → QA 더블 체크 요청

- 새 기능의 기대 동작은 BDD 형식의 `*.spec`에, 운영과 QA 오류는 `*.test`에 나눠 씁니다. 새 패턴은 제품 코드를 일부러 깨뜨려 테스트가 실패하는지 확인하고, 기대 payload는 제품의 변환 함수 없이 따로 작성합니다. dev API 서버를 먼저 쓰고, 만들기 어려운 조건에만 MSW 목을 씁니다.
- 4월에 공통 Bottom Sheet를 바꿀 때 에이전트가 제목과 버튼까지 스크롤 영역에 넣었는데, diff를 읽고도 놓쳤습니다. 9월에 본문만 스크롤되게 고치고 브라우저 레이아웃 회귀 테스트를 추가했습니다.
- lint rule은 RuleTester에 `__fixture__`와 mock으로 테스트 환경을 만들어 검증하고, 미사용 코드는 Knip으로 찾습니다. 병렬 worktree의 CPU 부하를 줄이려고 작업 중에는 변경과 영향 범위만 검사하고, 전체 검사는 CI에 맡깁니다.
