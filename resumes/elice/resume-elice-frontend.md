## 소개

기능이 늘어도 읽고 바꾸기 쉬운 코드를 유지하려고 합니다. 여러 상태에 흩어진 예약 폼을 정리하고, 화면마다 예외가 붙던 공통 코드를 나눠 왔습니다. 요구사항에서 빠진 동작이나 직접 써 보며 발견한 불편은 담당자와 논의해 반영합니다.

AI로 구현하면서 같은 수정이 반복되면 skills와 lint rule을 고쳤습니다. 완성된 코드와 테스트는 직접 읽고 화면을 띄워 동작을 확인합니다. 출시 뒤에는 Sentry와 VOC로 들어온 오류를 추적합니다.

#### 공통 폼과 아키텍처 | 2025.06 – 현재

관리자 화면이 늘 때마다 공통 검색 필터에 예외 분기가 추가됐습니다. 필요한 필터를 각 화면에서 조합하도록 바꾸고 27개 화면에 적용했습니다. JSX는 일부 반복되지만 한 화면의 요구사항 때문에 공통 코드에 분기를 넣지 않아도 됩니다. URL과 폼, API 요청은 같은 Zod 스키마를 사용하도록 맞췄습니다.

- Ant Design Form에서 중첩 필드명과 값의 타입을 검사하도록 `createTypedForm<T>`를 만들었습니다. 재귀 조건부 타입과 infer로 필드 경로에 맞는 값을 추론하고 name, getFieldValue, setFieldValue, useWatch에 적용했습니다. 라이브러리 타입을 보완하는 단언은 래퍼 안에만 뒀습니다.
- 예약 폼의 가족과 날짜 값이 Query, Zustand, 로컬 상태에 흩어져 가족을 추가하면 선택한 일시가 어긋났습니다. 서버에서 받은 목록은 Query에, 작성 중인 값은 React Hook Form에 두고 제출 조건은 Zod로 검사하도록 정리했습니다.
- FSD의 entities와 features를 나누는 기준이 모호해 재사용할 것 같으면 entities에 두고 있었습니다. 저장소에 맞춰 서버 모델과 API는 features, 화면 조합은 pages, 도메인과 무관한 공통 UI는 shared에 두도록 정했습니다. 화면 간 직접 참조 62건도 정리하고 같은 참조가 생기면 lint error가 나도록 했습니다.
- 공통 UI는 접근성 primitive와 조합 유연성을 보고 Headless UI에서 Radix UI로 옮겼습니다. Bottom Sheet는 Compound Components와 overlay-kit으로 바꿔 본문과 하단 버튼이 같은 폼을 쓰게 했습니다.

#### 서버 렌더링과 데이터 조회 | 2025.05 – 현재

기존 화면은 서버의 `ensureQuery` 결과를 render props로 받아 클라이언트에서 Query 캐시를 무효화해도 갱신되지 않았습니다. 2025년 5월 예약 화면부터 prefetch와 hydration으로 바꿨습니다. 서버가 준비한 데이터를 클라이언트도 같은 Query 캐시에서 읽어 이후 조회와 갱신을 처리하도록 했습니다.

- 인증 후 이동 중 앱이 멈추는 오류가 조사 당시 68건, 53명에게 발생했습니다. Next.js 소스를 읽어 `redirect()` 처리 중 렌더마다 훅 개수가 달라지는 경우를 찾았습니다. 해당 경로의 진입 조건 확인과 리다이렉트를 React 렌더 전의 proxy로 옮겼습니다.
- 관리자 검색 오류는 개발 서버에서는 나타나지 않아 build 후 start로 목록 7개 중 6개에서 재현했습니다. 업스트림 이슈와 수정 PR로 라우터 캐시 문제를 확인하고, 서버가 읽지 않는 URL 조건 변경은 History API로 처리했습니다. 수정 뒤 9월 28일까지 같은 증상은 다시 보고되지 않았습니다.
- Turbopack과 Next.js 16의 로컬 개발 속도 개선을 보고 Next.js 14→16, React 18→19로 전환했습니다. 비동기 API와 캐시 동작 변경에 맞춰 코드를 수정하고 링크 직접 진입, 뒤로가기, 새로고침을 확인했습니다.
- TypeScript 7 네이티브 체커를 병행해 복지몰 타입 검사 시간을 12.5초에서 1.9초로 줄였습니다. 타입 정보를 사용하는 lint도 검토했지만 검사 시간이 3.3배 늘어 도입을 보류했습니다.

#### 상담 채팅과 공유 패키지 | 2026.06 – 현재

기존 유저 상담 채팅의 입력과 실시간 연결을 개선했습니다. 10월부터는 최고 관리자가 방을 열고 병원 관리자와 상담사를 초대하는 병원 상담 채팅을 개발했습니다. 백오피스와 병원 관리자가 대화 화면, 입력칸, SSE 연결 코드를 함께 쓰도록 공유 패키지로 옮겼습니다. 경로가 다른 API 함수는 각 앱에서 전달합니다.

- 방 SSE는 React 밖 스토어와 `useSyncExternalStore`로 연결합니다. 토큰 갱신과 `last-event-id` 재연결을 처리하고, 받은 메시지와 읽음은 Query 캐시에 바로 반영합니다.
- 첫 페이지 조회 전에 SSE를 연결해 지난 이벤트를 다시 받던 문제를 고쳤습니다. 초기 조회가 끝난 뒤 마지막 순번부터 이어 받도록 했습니다. 읽음 처리는 500ms 동안 모아 보냅니다.
- 한글 조합 중 Enter로 메시지가 두 번 전송되는 문제는 `isComposing`과 전송 중 가드로 막았습니다.
- lint와 테스트에서 빠져 있던 채팅 영역을 다시 검사 대상으로 넣고 회귀 테스트를 보완했습니다.

백오피스에는 검사 구성과 검진 프로그램 관리, 기업지원 코드와 서류 확인, 결제취소와 환불 승인을 개발했습니다. 병원 관리자에는 예약 관리와 결제취소 요청을, 복지몰에는 검사 선택과 기업 검진 코드 입력, 토스페이먼츠 결제를 만들었습니다.

#### Sentry 도입과 운영 오류 추적 | 2026.08 – 현재

복지몰의 브라우저, 서버, Edge에 Sentry를 도입해 8월 27일 배포했습니다. 오류별 level을 정하고 중복 전송을 줄였으며, release와 브라우저 소스맵을 연결했습니다. SDK 코드와 payload를 확인해 의료 정보와 인증 정보가 담긴 값은 제거했습니다.

- Web Vitals가 pageload 트랜잭션에 담기도록 tracing을 연결하고, 값이 도착하기 전에 종료되지 않게 idleTimeout을 조정했습니다.
- Bottom Sheet 크래시는 라이브러리의 null ref 접근까지 추적해 고쳤습니다. 누적 75건, 57명 이상이던 오류 그룹은 9월 10일 배포 뒤 28일까지 18일간 0건이었습니다.
- 조회 한 건이 실패해도 앱 전체가 오류 화면으로 바뀌지 않도록 Error Boundary를 기능별로 나눴습니다. 백오피스 라우트 30개에 적용해 오류가 난 영역만 다시 시도할 수 있게 했습니다.
- Zod 검증에 실패했을 때는 값의 출처에 따라 다르게 처리합니다. 기존 API 응답 불일치는 CloudWatch로 트래킹합니다. URL은 잘못된 필드만 기본값으로 바꾸고, 결제 후 복원할 입력값은 검증에 실패하면 버립니다.

#### AI 개발 workflow | 2026.04 – 현재

에이전트가 의도와 다르게 구현한 부분은 skills를 고쳐 다음 작업에 반영합니다. 의존 방향과 공개 API, queryKey처럼 자동으로 검사할 수 있는 내용은 lint rule로 만들었습니다. 상태 관리와 폴더 구조도 저장소에 맞게 정리했습니다.

티켓과 plan 검토 → 테스트 작성 → 에이전트 구현과 에이전트 코드 리뷰 → 변경분 테스트, lint, typecheck → 직접 diff 리뷰와 화면 동작 확인 → 전체 CI(테스트, knip, lint) → QA 더블 체크 요청

공통 Bottom Sheet를 바꿀 때 diff를 읽고도 본문과 헤더가 함께 스크롤되는 문제를 놓쳤습니다. 본문만 스크롤되도록 고치고 브라우저 레이아웃 테스트를 추가했습니다. 코드 리뷰와 테스트가 끝나도 화면을 띄워 동작을 확인합니다.

여러 worktree에서 동시에 검사하니 CPU 부하가 커졌습니다. 작업 중에는 변경분과 영향 범위의 lint와 테스트를 돌리고, 타입 검사는 앱과 패키지 단위로 진행합니다. 전체 검사는 CI에서 돌립니다.

- 면접 템플릿은 네 단계로 입력하고 단계별로 검증하도록 만들었습니다. 작성 중인 값은 sessionStorage로 복원합니다. 앱마다 있던 Query key와 조회 함수는 공용 패키지로 모았습니다. 공고 순서와 중첩 필터, 테이블에 쓰는 드래그 공통 컴포넌트도 개발했습니다.
- Electron 앱은 공통 수집 단계와 사이트별 adapter로 나누는 초기 구조를 설계하고 잡플래닛, 게임잡을 연동했습니다. NestJS도 도입하려 했지만 Electron main 프로세스에는 무겁다는 CTO 피드백을 받아 제거했습니다. 모듈 구분과 생성자 주입은 참고해 남겼습니다.
