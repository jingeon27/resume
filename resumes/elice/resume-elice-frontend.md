#### AI 개발 workflow와 개발 환경 개선 | 2026.04 – 현재

4월부터 compound engineering 방식으로 skills를 보강해 왔습니다. 구현이 의도와 다르면 해당 코드만 고치지 않고 파일 배치·상태 관리·공통 코드 사용 기준을 skills에 남겼습니다. 에이전트가 저장소의 맥락을 찾고 일관되게 구현하도록 FSD 구조와 lint rule, 테스트 기준도 함께 다듬었습니다.

티켓·plan 검토 → 테스트 작성 → 에이전트 구현·에이전트 코드 리뷰 → 변경분 테스트·lint·typecheck → 직접 diff 리뷰·화면을 띄워 동작 확인 → 전체 CI(테스트·knip·lint) → QA 더블 체크 요청

에이전트가 완성본을 제출하면 변경된 코드와 테스트를 읽고, 부족한 부분을 짚어 반려한 뒤 수정본을 확인합니다. 에이전트 리뷰의 critical 항목은 자동 수정하고 그 결과도 검토합니다. 새 기능은 `*.spec`의 기대 동작과 빠진 조건을 보고, 운영·QA 오류는 `*.test`로 재현합니다. 단계 중 문제가 나오면 앞 단계로 돌아갑니다.

- 자체 lint rule은 RuleTester와 `__fixture__`·mock으로 테스트 환경을 만들어 검증합니다. Knip으로 미사용 파일·export도 검사합니다.
- 병렬 worktree의 CPU 부하를 줄이려고 lint·테스트는 변경 파일과 영향 범위로 좁히고 타입 검사는 패키지·앱 단위로 유지했습니다. 전체 테스트·knip·lint는 CI에서 확인합니다. 타입 인지 lint는 검사 시간이 3.3배 늘어 도입을 보류했습니다.
- TypeScript 7 네이티브 체커를 병행해 복지몰의 타입 검사 시간을 실측 **12.5초에서 1.9초**로 줄였습니다.

#### 폼·검색 필터와 공통 구조 개선 | 2025.06 – 현재

검색 필터의 공통 렌더러에 화면별 예외가 계속 늘었습니다. 필터를 화면에서 직접 조합하도록 바꾸고 2026년 8월 운영 화면 27개를 전환했습니다. 화면마다 JSX를 적어야 하지만, 새 조건 때문에 공용 렌더러에 분기를 추가하는 일은 줄었습니다. URL·폼·API 필드는 Zod 스키마로 맞췄습니다.

선택지의 수동 페이지·요청 순서 관리도 TanStack Query로 옮겼습니다. 이름이 같고 코드가 다른 기업이 중복 제거로 사라지는 오류를 확인해 식별 기준을 고치고, 공용 UI에는 입력과 스크롤 처리만 남겼습니다. 목록과 선택지의 key도 나눠 목록 갱신 때문에 선택지 페이지까지 다시 요청하지 않도록 했습니다.

Ant Design Form의 필드 경로를 문자열로만 다루면 중첩 필드명과 값이 틀려도 타입 검사에서 놓칠 수 있었습니다. 재귀 조건부 타입과 `infer`로 유효한 경로와 값 타입을 계산하는 `createTypedForm<T>`를 만들어 필드명과 값을 함께 검사하도록 했습니다. 응답 → 폼 → 제출값 변환은 순수 함수로 분리하고, 병원 관리자와 백오피스의 제출 처리는 각 앱에 남겼습니다.

2025년 6월에는 Query 캐시·Zustand·로컬 상태에 흩어진 가족·날짜 선택값을 React Hook Form·Zod로 정리했습니다. 서버 목록과 작성 중인 값을 나누고, 가족 추가 시 날짜가 어긋나는 동작을 고쳤습니다. 예약 대상 선택 컴포넌트는 선택 UI만 남겨 519줄에서 55줄로 줄였습니다.

FSD는 재사용할 것 같다는 이유로 entities에 두던 기준을 저장소에 맞게 다시 정했습니다. 서버 모델·API 로직은 features, 화면 조합은 pages, 도메인에 의존하지 않는 UI는 shared에 두고 공통 UI는 compound 방식으로 조합하도록 했습니다. 화면 간 직접 참조 62건과 슬라이스 내부 직접 import 경고 271건을 정리하고 lint error로 차단했습니다.

공통 UI는 조합 유연성과 접근성 primitive를 활용하려고 Headless UI에서 Radix UI로 전환했습니다. 기존 props·ref·이벤트를 새 API에 맞추고 포커스 동작을 확인했습니다. Bottom Sheet는 기반 라이브러리를 유지하면서 Compound Components와 overlay-kit으로 바꿔 본문과 하단 버튼이 같은 폼 상태를 쓰도록 했습니다.

정산 기능에서는 1,170줄의 페이지에 섞인 조회·표·선택·편집·정산 처리를 나누고 관련 파일과 타입도 정리했습니다. 다른 기능이 라우트 안의 모달을 직접 참조하는 의존을 끊고, `useImperativeHandle`과 ref로 열던 모달은 대상 데이터와 열림 상태를 props로 받도록 바꿨습니다.

- 선택 개수를 채우면 다음 검사 그룹을 자동으로 열자는 요청에는 기존 선택을 수정할 때도 강제 이동하는 문제를 제기했습니다. 담당자와 논의해 미선택 chip만 비활성화하고 기존 선택은 같은 화면에서 수정하도록 했습니다.

#### Sentry 도입과 운영 오류 추적 | 2026.08 – 현재

운영 오류를 수집하고 원인을 추적할 수 있도록 복지몰의 브라우저·서버·Edge에 Sentry를 도입했습니다. 8월 19일부터 구현해 27일 운영에 배포했습니다. 화면이 뜨지 않는 오류, 작업을 막는 오류, 재시도할 수 있는 실패를 구분해 레벨을 정하고, 같은 오류가 API 처리와 Error Boundary를 거치며 여러 번 수집되지 않도록 했습니다.

- 차단 게이트로 의미 없는 전송을 줄이고, SDK 소스를 확인해 의료·인증 정보가 담기는 값을 제거했습니다. 오류 레벨과 중복 수집 처리, 정보 제거 로직에 타입과 테스트를 붙였습니다.
- release와 브라우저 소스맵을 배포에 연결했습니다. Web Vitals를 breadcrumb으로 수집하고 실제 전송은 브라우저 E2E로 확인했습니다. 운영 이슈를 에이전트도 조회할 수 있도록 Sentry MCP를 연결했습니다.
- Bottom Sheet 드래그 크래시는 라이브러리의 null ref 접근까지 추적해 버전업으로 해결했습니다. 바뀐 snap point 규칙은 공통 Root에서 변환해 기존 사용처를 유지했습니다. 누적 **75건·57명 이상**에게 발생한 오류 그룹은 9월 10일 배포 뒤 28일까지 **18일간 0건**이었습니다.
- 인증 후 화면 이동 중 멈추는 오류는 Next.js 라우터 소스를 읽어 `redirect()` 처리 중 훅 호출 순서가 어긋나는 경로를 확인했습니다. 진입 판정을 React 렌더 전 proxy로 옮겼습니다.

#### 테스트 도입 | 2026.07 – 현재
