## 소개·지원동기

React와 TypeScript로 모바일 웹과 관리자 서비스를 개발합니다. 세이프닥에서 가입 회원 약 15만 명의 복지몰, 병원 관리자, 백오피스, 글로벌 사용자 서비스와 CMS를 맡고 있습니다. 2026년 1월부터 사내 유일한 프론트엔드로 일하고 있으며, 4월부터 개발과 운영을 단독으로 담당합니다.

개발할 때는 기준을 먼저 세웁니다. 프로덕션 오류는 브라우저·React·Next.js의 실행 흐름을 따라 원인을 찾고, 타입은 재귀 조건부 타입과 Zod 스키마로 잘못된 값이 들어오는 경로마다 막습니다. AI에게 구현을 맡긴 뒤에는 코드와 테스트를 직접 읽고 dev 화면에서 동작을 확인하며, 반복해서 고친 내용은 skills와 lint rule에 남깁니다.

[엘리스 프론트엔드팀 소개](https://elice.io/ko/resources/blog/ai-a-z-part2)에서 실시간 수업과 코드 에디터를 만들면서 내부 라이브러리와 개발 환경도 함께 다룬다는 내용을 읽었습니다. 저도 여러 제품을 맡으며 기능 개발과 함께 여러 화면이 쓰는 공용 코드를 만들어 왔습니다. 중첩 필드 경로를 타입으로 검사하는 폼 API와 스키마에서 필드명을 파생하는 검색 필터를 만들어 운영 화면 27개에 적용했고, 반복되는 실수는 테스트가 딸린 자체 ESLint 규칙으로 막았습니다. 엘리스에서도 여러 제품에 쓰이는 라이브러리와 개발 환경을 다루면서 실제 기능을 개발하고 싶습니다.

지금은 혼자 프론트엔드를 맡고 있어, 설계와 코드를 함께 검토하며 배울 동료가 없다는 점이 아쉬웠습니다. 같은 직군의 훌륭한 엔지니어분들과 교류하며 엔지니어로서도 성장하고 싶어 지원했습니다.

#### 건강검진 도메인 내재화 | 2026.09 – 현재

건강검진은 아임웹에서 정보를 보고 전화로 문의해야 했습니다. 한 제휴 병원이 세이프닥에서 검진 예약을 받기를 요청했지만, 기존 비급여 프로그램에는 검사 구성, 기업지원 검진, 예약금 결제가 없었습니다. 개발팀장님·부팀장님과 빠진 동작과 예외를 확인하며 세 제품의 프론트엔드를 개발했습니다. 9월 9일부터 두 주 동안 순차 개발해 23일 운영에 배포했고, 30일 정식 오픈했습니다.

- **백오피스:** 검사항목과 필수·선택 검사 그룹, 프로그램별 검진 구성을 관리하는 화면을 만들었습니다. 기업지원 코드·서류 확인, 결제내역 조회, 예약금 결제취소·환불 승인도 추가했습니다.
- **병원 관리자:** 검진 프로그램은 조회하고 예약을 관리하도록 했습니다. 검진만 운영하는 병원에서는 등록·검수 메뉴를 숨기고, 다른 진료과도 운영하는 병원에는 기존 기능을 유지했습니다. 예약 취소와 예약금 결제취소는 구분해, 병원이 직접 처리할 수 없는 결제취소는 요청 접수로 안내했습니다.
- **복지몰:** 검진 상세부터 검사 선택, 공단 검진 여부·주소·기업 검진 코드 입력, 예약금 결제, 예약 상세까지 만들었습니다. 사용자 부담금과 기업지원 내용도 나눠 표시했습니다. 비급여와 같은 상세 경로를 쓰면서 상단바와 인증 후 이동은 공유하고, 상세 화면과 신청 폼은 따로 두었습니다.

검사항목 일괄 저장은 일부만 성공할 수 있었습니다. 그대로 재시도하면 이미 만들어진 항목을 중복 등록하므로, 성공 여부와 관계없이 서버 목록을 다시 받아 발급된 id를 폼에 반영했습니다. 검진 구성을 비우는 요청이 실패한 뒤에도 남은 항목을 다시 삭제할 수 있게 했습니다.

결제 실패 후 입력 복원도 바꿨습니다. 토스페이먼츠 결제창은 모바일에서 결과를 리다이렉트로만 돌려줘, 실패로 돌아오면 문서가 새로 로드되며 입력이 사라집니다. 처음에는 Zustand persist 스토어에 프로그램 ID 기준으로 맡겼는데, 복원 값을 검증할 자리가 없어 옛 폼 값이 그대로 덮일 수 있었습니다. 스토어를 걷어내고 결제 시도(`orderId`)와 함께 `sessionStorage`에 남긴 뒤, 돌아오면 한 번만 꺼내 현재 폼 스키마로 `safeParse`한 값만 되살립니다. 어긋난 값은 버립니다. 다시 입력하는 수고가 한 번 생기지만, 배포로 바뀐 폼에 옛 값이 덮이면 화면이 깨지기 때문입니다. 주문 생성부터 토스페이먼츠 결제창이 열릴 때까지 버튼을 잠그고, 결제창 실패 복귀의 입력 복원과 승인 요청 실패 시 예약 목록 이동은 dev API 서버 E2E로 확인했습니다.

#### Sentry 도입과 운영 오류 추적 | 2026.08 – 09

운영 오류를 수집하고 원인을 추적할 수 있도록 복지몰의 브라우저·서버·Edge에 Sentry를 도입했습니다. 8월 19일부터 구현해 27일 운영에 배포했습니다. 화면이 뜨지 않는 오류, 작업을 막는 오류, 재시도할 수 있는 실패를 구분해 레벨을 정하고, 같은 오류가 API 처리와 Error Boundary를 거치며 여러 번 수집되지 않도록 했습니다.

`sendDefaultPii: false`를 설정해도 헤더·쿠키·본문·URL이 모든 전송 경로에서 빠지는 것은 아니었습니다. SDK 소스를 따라 이벤트·breadcrumb·transaction·span에 어떤 값이 실리는지 확인하고 의료·인증 정보가 담기는 값을 제거했습니다. 새 수집 항목을 추가할 때도 처리를 빠뜨리지 않도록 타입과 단위 테스트를 붙였습니다.

release와 브라우저 소스맵을 연결하고 Sentry API로 artifact bundle 생성을 확인했습니다. LCP·FCP·TTFB가 실제 브라우저에서 전송되는지는 E2E로 확인했고, 에이전트가 운영 이슈를 조회할 수 있도록 사내 Sentry MCP를 연결했습니다. 서버 소스맵은 업로드 중 502가 발생해 8월 31일부터 제외했습니다. 서버 스택은 압축된 코드로 남습니다.

도입 후에는 Bottom Sheet 드래그 크래시를 라이브러리의 null ref 접근까지 추적했습니다. 라이브러리를 올리고 바뀐 snap point 규칙은 공통 Root에서 변환해 기존 사용처를 유지했습니다. 수정 배포 전까지 누적 57명 이상에게 75건 발생한 오류 그룹은 9월 10일 배포 뒤 28일까지 0건이었습니다.

#### 테스트 체계 재구축 | 2026.07 – 현재

기존 테스트는 실제 폼에서 요청이 나가는지, 서버가 입력을 받아 주는지 확인하지 못했습니다. 이를 정리한 뒤 7월 20일부터 관리자 서비스 모노레포와 복지몰의 테스트를 다시 구성했습니다. 작성은 에이전트에 맡기고, 저는 확인할 동작과 빠진 조건을 짚고 테스트가 실제 오류를 잡는지 검토합니다.

- 순수 함수·스키마는 Vitest, UI와 폼은 React Testing Library, 브라우저 흐름은 Playwright로 확인합니다. 목은 마지막 수단으로 두고, 관리자 서비스의 화면 테스트는 dev API 서버에 붙이는 것을 기본으로 합니다.
- 테스트 안에서 제출 로직을 복제하던 하네스를 없애고 실제 등록 Drawer를 렌더하게 바꿨습니다. 잘못된 입력에도 성공하던 목에는 서버에서 확인한 제약을 반영했습니다. 기대 payload는 제품의 변환 함수를 다시 호출해 만들지 않고 별도로 적었습니다.
- 등록·수정 Drawer를 나누면서 등록 후 창이 닫히지 않는 오류와 URL로 직접 진입하면 수정 payload 타입이 어긋나는 오류를 찾았습니다.
- 9월에는 병원 관리자에서 프로그램을 등록하고 백오피스에서 검수중·반려·승인하는 E2E를 추가했습니다. 앱마다 로그인을 준비하고 테스트별 서버 상태를 맞춰 실행 순서가 달라도 동작하도록 했습니다.

새 기능의 기대 동작은 BDD 형식의 `*.spec`에 적고 컴포넌트별로 빠진 조건을 확인합니다. 운영·QA에서 발견한 오류는 `*.test`로 재현합니다. 새 패턴의 테스트는 제품 코드를 일부러 깨뜨려 실패하는지 확인한 뒤 넣습니다. dev API 계약 테스트는 PR을 막지 않는 별도 단계로 돌리고, E2E는 CI 밖에서 실행합니다.

#### 검색 필터와 프로그램·예약 폼 | 2025.06 – 2026.08

검색 필터의 공통 렌더러에 화면별 예외가 계속 늘었습니다. 필터를 화면에서 직접 조합하도록 바꾸고 2026년 8월 운영 화면 27개를 전환했습니다. 화면마다 JSX를 적어야 하지만, 새 조건 때문에 공용 렌더러에 분기를 추가하는 일은 줄었습니다. URL·폼·API 필드는 Zod 스키마로 맞췄습니다.

처음에는 선택지 조회의 수동 페이지·요청 순서 관리도 그대로 옮겼습니다. 이후 이름은 같고 코드가 다른 기업이 중복 제거로 사라지는 것을 찾았습니다. 조회를 도메인의 `infiniteQueryOptions`와 화면의 `useInfiniteQuery`로 옮겨 공용 UI에는 입력과 스크롤 처리를 남겼습니다. 목록과 선택지의 key도 나눠 목록 갱신 때문에 선택지 페이지까지 다시 요청하지 않도록 했습니다.

Ant Design 폼은 필드 경로를 아무 문자열·배열로나 받아 중첩 필드명이 틀려도 컴파일됩니다. 폼 값 타입에서 유효한 경로와 그 값 타입을 재귀 조건부 타입으로 계산하는 `createTypedForm<T>`를 만들어, `name`·`getFieldValue`·`setFieldValue`·`useWatch`가 경로와 값을 함께 검사하게 했습니다. 응답 → 폼 → 제출값 변환은 순수 함수로 분리했습니다. 병원 관리자와 백오피스가 같은 필드를 쓰더라도 제출 처리는 각 앱에 남겼습니다.

2025년 6월에는 Query 캐시·Zustand·로컬 상태에 흩어진 가족·날짜 선택값을 나흘 동안 React Hook Form·Zod로 모았습니다. 가족을 추가하면 날짜가 어긋나는 동작을 고쳤고, 예약 대상 선택 컴포넌트는 519줄에서 55줄로 줄었습니다.
