- **테스트:** 2026년 7월부터 테스트를 도입해 새 기능은 BDD 명세, 운영 오류는 회귀 테스트로 나누고, 두 앱을 잇는 E2E로 등록·검수 흐름을 확인합니다.

#### 공통 구조·폼·타입 설계 | 2025.06 – 현재

관리자 화면이 늘면서 공통 검색 필터에 화면별 예외 분기가 계속 쌓였습니다. 각 화면이 필요한 필터를 조합하도록 바꾸고 운영 화면 27개를 전환했습니다. JSX가 일부 반복되는 것은 감수했고, URL·폼·API의 필드 계약은 같은 Zod 스키마로 맞췄습니다.

Ant Design Form은 중첩 필드명을 배열로 받아 잘못된 필드명이나 값이 실행해야 드러났습니다. 재귀 조건부 타입과 `infer`로 유효한 경로와 값을 계산하는 `createTypedForm<T>`를 만들어 `name`·`getFieldValue`·`setFieldValue`·`useWatch`에 적용했습니다. 단언은 래퍼 내부에만 두고, 서버 응답↔폼↔제출값 변환은 순수 함수로 분리했습니다.

예약 화면은 가족·날짜 값이 Query 캐시·Zustand·로컬 상태에 나뉘어, 날짜를 고른 뒤 가족을 추가하면 선택한 일시가 어긋났습니다. 서버 목록은 Query, 작성 중인 값은 React Hook Form, 제출 조건은 Zod로 역할을 나눠 고쳤고, 519줄이던 예약 대상 선택 컴포넌트는 55줄이 됐습니다.

- **FSD:** 재사용할 것 같다는 이유로 entities에 두던 기준을 서버 모델·API는 features, 화면 조합은 pages, 공통 UI는 shared로 다시 정했습니다. 화면 간 직접 참조 62건을 정리해 lint error로 막았습니다.
- **정산:** 인수한 1,170줄의 정산 페이지에서 조회·표·선택·편집·정산 처리를 나누고, ref로 열던 모달은 대상 데이터와 열림 상태를 props로 받게 바꿨습니다. 가격 이력을 추가하자는 요청에는 정산 기준이 프로그램 가격인지 견적 금액인지 먼저 확인했고, 견적 금액이 기준이라 이력 구조는 만들지 않았습니다.

#### 데이터 조회와 Next.js 오류 대응 | 2025.05 – 현재

입사 당시에는 서버 컴포넌트의 `ensureQuery` 결과를 render props로 전달했습니다. 화면이 Query 캐시를 구독하지 않아 무효화해도 갱신되지 않았고, 조회 조건만 바꿀 때도 서버 렌더링 결과를 다시 받아야 했습니다. 2025년 5월 예약 화면부터 prefetch·hydration·`useQuery` 구조로 옮겨, 서버는 초기 HTML에 필요한 데이터를 준비하고 클라이언트는 같은 캐시로 이후 조회·갱신·무효화를 처리하게 했습니다.

인증한 사용자가 로그인·본인인증 화면에서 돌아갈 때 앱이 멈추는 오류는 조사 당시 68건·53명에게 발생했습니다. Next.js 소스에서 `redirect()` 처리 중 렌더마다 호출되는 훅 개수가 달라지는 경로를 확인하고, 인증 확인과 리다이렉트를 React 렌더링 전 proxy로 옮겼습니다.

관리자 검색 오류는 localhost의 `dev`에서는 나타나지 않아 `build` 후 `start`로 재현했습니다. 목록 7개 중 6개에서 확인하고 업스트림 라우터 캐시 이슈까지 추적했습니다. 서버가 검색 조건을 읽지 않는 화면의 같은 경로 쿼리 변경은 History API로 처리했고, 수정 뒤 9월 28일까지 같은 증상의 재보고는 없었습니다. Next.js 14→16·React 18→19 전환은 Turbopack과 Next.js 16의 로컬 개발 속도 개선을 보고 진행했고, 비동기 API·캐시 변경에 맞춰 코드를 고친 뒤 직접 진입·뒤로가기·새로고침을 확인했습니다.

#### 테스트 도입과 AI 개발 workflow | 2026.04 – 현재

2026년 4월부터 에이전트로 구현하며, 의도와 어긋난 구현은 코드만 고치지 않고 파일 배치·상태 관리·공통 코드 사용 기준을 skills나 lint rule에 남겼습니다. 7월부터는 테스트를 도입해 같은 흐름에 넣었습니다.

티켓·plan 검토 → 테스트 작성 → 에이전트 구현·에이전트 코드 리뷰 → 변경분 테스트·lint·typecheck → 직접 diff 리뷰·화면을 띄워 동작 확인 → 전체 CI(테스트·knip·lint) → QA 더블 체크 요청

- 새 기능의 기대 동작은 BDD 형식의 `*.spec.{ts,tsx}`, 운영·QA 오류는 `*.test.{ts,tsx}`로 나눕니다. 새 패턴은 제품 코드를 일부러 깨뜨려 테스트가 실패하는지 확인하고, 기대 payload는 제품의 변환 함수를 쓰지 않고 따로 작성합니다. dev API 서버를 우선하고 만들기 어려운 조건에만 MSW 목을 씁니다.
- 4월 공통 Bottom Sheet를 바꿀 때 에이전트가 제목·버튼까지 스크롤 영역에 넣은 것을 diff를 읽고도 놓쳤습니다. 9월에 본문만 스크롤되게 고치고 브라우저 레이아웃 회귀 테스트를 추가했습니다.
- lint rule은 RuleTester·`__fixture__`·mock으로 검증하고 Knip으로 미사용 코드를 검사합니다. 병렬 worktree의 CPU 부하를 줄이려고 작업 중에는 변경·영향 범위만 검사하고 전체 검사는 CI에서 확인합니다. 타입 인지 lint는 검사 시간이 3.3배 늘어 보류했고, TypeScript 7 네이티브 체커로 복지몰 타입 검사를 **12.5초에서 1.9초**로 줄였습니다.
