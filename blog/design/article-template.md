## 어떤 문제가 있었나

관찰한 증상과 발생 조건을 적는다. 개발 환경과 운영 환경이 달랐다면 구분한다.

```text
재현 환경:
사용자 행동:
기대한 결과:
실제 결과:
```

## 범위를 어떻게 확인했나

한 화면의 문제인지 공통 구조의 문제인지 확인한 과정을 적는다. 수동 점검 수치는 자동 검증처럼 표현하지 않는다.

## 원인은 무엇이었나

프레임워크·브라우저·서버의 책임을 구분해 설명한다. 내부 구현은 결정에 필요한 만큼만 보여준다.

## 어떻게 구현했나

핵심 코드만 싣는다. import와 주변 코드가 결론에 필요하지 않으면 생략한다.

```ts
// 핵심 결정이 드러나는 최소 코드
```

## 어떻게 검증했나

- 실제 개발 서버에서 확인한 것
- 프로덕션 빌드에서만 확인할 수 있었던 것
- 테스트로 고정한 것
- Sentry나 Web Vitals로 운영에서 확인한 것

## 결과

측정한 결과와 관찰한 결과를 분리한다. 전후 수치는 측정 조건을 함께 적는다.

<div class="note note-limit">
  <strong>아직 확인하지 못한 것</strong>
  <p>측정하지 않은 성능·매출·전환 효과를 인과로 주장하지 않습니다.</p>
</div>
