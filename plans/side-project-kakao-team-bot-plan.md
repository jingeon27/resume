# 사이드 프로젝트: 카톡 팀뽑기·사다리 봇 계획

> 레퍼런스: [youhogeon/kakao-bot](https://github.com/youhogeon/kakao-bot). 안드로이드 기기의 카카오톡 알림을 메신저봇R로 읽고 답장하는 구조를 그대로 가져온다.

## 한 줄 정의

단톡방에서 `참여`만 치면 명단이 모이고, `팀전`이면 n:n으로 팀을 나누고, `사다리전`이면 정한 인원만큼 걸릴 사람을 뽑아 주는 카톡 봇. 방 멤버 전체 호출도 한다.

## 구조

레퍼런스는 메신저봇R이 메시지를 PC의 Spring UDP 서버로 넘기고, 서버가 처리해 답을 돌려준다. 이 봇은 명령어 처리와 방별 상태만 있으면 되므로 처음에는 메신저봇R 스크립트 하나로 끝낸다.

- PC 서버를 띄워 둘 필요가 없어 휴대폰 한 대로 돈다.
- 로직은 `handle(방, 보낸 사람, 내용) → 답장 문자열 | null` 순수 함수로 두고, 메신저봇R 연결부는 파일 맨 아래에 따로 둔다. 같은 파일을 Node에서 불러와 테스트한다.
- 메신저봇R은 Rhino 엔진이라 ES5 문법(`var`, `function`, `indexOf`)으로 쓴다.
- 전적 저장이나 웹 대시보드가 필요해지면 그때 레퍼런스처럼 서버로 뺀다.

## 명령어

| 명령 | 동작 |
| --- | --- |
| `팀전 [팀 수]` | 팀전 열기. 기본 2팀(n:n), 2~10팀 |
| `사다리전 [걸릴 인원]` | 사다리전 열기. 기본 1명 |
| `참여` | 명단에 들어간다 |
| `탈퇴` · `참여취소` | 명단에서 빠진다 |
| `명단` · `참여자` | 현재 모드와 참여자 |
| `뽑기` | 지금 모드로 뽑는다. `팀뽑기` · `사다리타기`도 받는다 |
| `종료` | 게임을 닫고 명단을 비운다 |
| `전체멘션 [할 말]` | 방 멤버를 `@이름`으로 전부 부른다 |
| `도움말` · `명령어` | 명령어 목록 |

명령어는 메시지 전체가 정확히 일치할 때만 반응한다. `참여 하고 싶다` 같은 평범한 대화에는 답하지 않는다.

## 동작 규칙

### 참여와 탈퇴

- 게임이 열려 있지 않으면 `참여`를 받지 않고 `팀전`이나 `사다리전`으로 먼저 열라고 안내한다.
- 같은 사람이 `참여`를 다시 보내면 명단에 두 번 넣지 않고 "이미 참여했어요"로 답한다. 팀이 둘로 쪼개지거나 사다리에 두 번 걸리는 일을 막는다.
- 참여하지 않은 사람이 `탈퇴`하면 그렇다고 알려 준다.
- 참여·탈퇴 답장마다 현재 인원을 붙인다.

### 팀전

- 명단을 Fisher–Yates로 섞은 뒤 팀 수만큼 돌아가며 한 명씩 넣는다. 인원 차이는 최대 1명이다.
- 결과 첫 줄에 인원과 팀 구성(`6명 · 3:3`, `7명 · 3:2:2`)을 보여 준다. 나눠떨어지지 않으면 팀 인원이 다르다고 한 줄 덧붙인다.
- 참여자가 팀 수보다 적으면 뽑지 않는다.

### 사다리전

- `사다리전 2`처럼 걸릴 인원을 정해 연다. 참여자 중에서 그 인원만큼 무작위로 걸리고, 결과는 `걸림`과 `통과` 두 줄로 보여 준다.
- 참여자가 걸릴 인원보다 많아야 뽑는다.
- 사다리 그림은 그리지 않는다. 카톡 글꼴이 고정폭이 아니라 글자 사다리는 줄이 어긋난다. 결과는 무작위 순열과 같으므로 섞어서 앞에서 자르는 것으로 충분하다.

### 모드 전환과 다시 뽑기

- 게임이 열린 상태에서 다른 모드를 열면 명단은 그대로 두고 모드만 바꾼다. 같은 사람들이 팀전 뒤에 바로 사다리를 타는 경우가 많다.
- 뽑은 뒤에도 게임을 닫지 않는다. `뽑기`를 다시 보내면 새로 뽑는다. `종료`해야 명단이 비워진다.
- 사다리전에서 `팀뽑기`를 보내면 뽑지 않고 지금 모드를 알려 준다.

## 전체 멘션의 한계

알림 기반 봇이라 할 수 있는 범위가 좁다. 1주차에 실기기에서 먼저 확인한다.

- **진짜 멘션이 아니다.** 알림 답장은 글자만 보낼 수 있어 `@이름`이 파란 멘션으로 바뀌지 않고, 받는 사람에게 멘션 알림도 가지 않는다. 방 알림을 꺼 둔 사람은 못 볼 수 있다.
- **방 멤버 목록을 알 수 없다.** 봇이 아는 사람은 봇이 켜진 뒤 그 방에서 한 번이라도 말한 사람뿐이다. 말한 적 없는 사람은 호출 명단에 없다.
- 그래서 방마다 말한 사람을 기억해 두고 파일(`/sdcard/msgbot/teambot-members.json`)에 저장한다. 새 사람이거나 닉네임이 바뀌었을 때만 쓴다. 봇을 재시작해도 명단이 남는다.
- 진짜 멘션이 꼭 필요하면 비공식 클라이언트 프로토콜 같은 다른 방식이 필요한데, 계정 제재 위험이 커서 이 프로젝트에서는 하지 않는다.

## 사람 구분

- 메신저봇R API2의 `msg.author.hash`가 있으면 그것을 id로 쓰고, 없으면 닉네임으로 대신한다. hash가 지원되는 버전·환경 조건은 1주차에 확인한다.
- 닉네임으로 대신할 때는 같은 닉네임 두 사람을 구분하지 못한다. 단톡방 규모에서는 감수하고, 실제로 겹치면 그때 안내 문구를 넣는다.
- 참여한 사람이 닉네임을 바꾸면 다음 `참여` 때 명단의 이름을 새 이름으로 바꾼다.

## 상태

| 상태 | 위치 | 재시작 시 |
| --- | --- | --- |
| 방별 게임(모드, 팀 수 또는 걸릴 인원, 참여자) | 메모리 | 사라진다. 다시 열면 된다 |
| 방별 멤버(id → 닉네임) | 메모리 + 파일 | 파일에서 다시 읽는다 |

## 구현 순서

1. **실기기 확인 (반나절):** 서브 계정으로 공기계에 카카오톡과 메신저봇R을 깔고 `테스트` 답장이 오는지 본다. 레퍼런스 README대로 카카오톡은 9.6.7 버전을 먼저 쓴다. `author.hash`가 오는지, `@이름` 답장이 어떻게 보이는지 여기서 확인한다.
2. **로직 + 테스트:** `handle` 함수와 Node 테스트를 같이 쓴다. 테스트 목록은 아래와 같다.
3. **연결부:** `BotManager.getCurrentBot().addListener(Event.MESSAGE, …)`에서 카카오톡 패키지만 받고, `handle` 결과가 있으면 `msg.reply`로 답한다. 멤버 파일 읽기·쓰기는 `FileStream`으로 하고 실패해도 봇이 멈추지 않게 감싼다.
4. **실제 방에서 한 번 돌려 보기:** 지인 단톡방에서 팀전·사다리전을 한 번씩 돌리고 답장 문구와 줄바꿈을 다듬는다.

## 테스트

Node 기본 테스트 러너(`node --test`)로, 메신저봇R 없이 `handle`만 부른다.

- 게임이 없으면 참여를 막는다.
- 중복 참여를 막고, 탈퇴하면 명단에서 빠진다. 참여하지 않은 사람의 탈퇴를 안내한다.
- 팀전은 모든 참여자를 빠짐없이, 겹치지 않게 n:n으로 나눈다.
- 팀 수를 지정할 수 있고, 나눠떨어지지 않으면 안내한다(7명 3팀 → `3:2:2`).
- 사다리전은 지정한 인원만큼만 걸리고, 걸림과 통과를 합치면 참여자 전원이다.
- 사다리 인원이 부족하면 뽑지 않는다.
- 모드를 바꿔도 참여자가 남고, 다른 모드의 뽑기 명령은 안내만 한다. 종료하면 다시 참여할 수 없다.
- 잘못된 숫자(`팀전 1`, `사다리전 abc`)를 거른다.
- 명령어와 비슷한 평범한 대화에는 답하지 않는다.
- 전체멘션은 말한 적 있는 사람을 전원 부르고 파일 저장을 요청한다.

새 테스트는 로직을 일부러 깨뜨려 실제로 실패하는지 확인한 뒤 넣는다.

## 미리 알아 둘 리스크

- **계정 제재:** 카카오 운영정책은 자동화 프로그램 사용을 제한한다. 봇은 서브 계정으로 돌린다.
- **카카오톡 업데이트:** 알림 구조가 바뀌면 봇이 메시지를 못 읽는다. 레퍼런스도 9.7 이상에서 오작동 가능성을 적어 두었다. 봇 기기는 자동 업데이트를 끈다.
- **방 알림:** 봇 기기에서 방 알림을 끄면 메시지가 안 들어온다. 봇 계정은 모든 방 알림을 켜 둔다.
- **기기 상태:** 배터리 최적화가 메신저봇R을 죽일 수 있다. 최적화 예외로 두고 충전기에 꽂아 둔다.
- **영리 활동:** 무료로 지인 방에서만 쓴다. 산업기능요원 복무 중 겸직·영리 활동 제한이 있으므로 수익화는 하지 않는다.
